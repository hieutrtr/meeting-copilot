# T-2.9 — Settings Store: Sensitivity Slider + Haiku Toggle + Cost-Guard Limit (Persisted)

> Phase 2, task #9 of 10. Companion review = `T-2.9-review.md`. Spec source = `docs/tasks/phase-2/INDEX.md` line 55.

## Reference

- **Plan:** `docs/IMPLEMENTATION-PLAN.md` Phase 2 row T-2.9 — "Settings: detector sensitivity slider (precision-recall tradeoff) + enable/disable Haiku filter toggle. Persist via localStorage."
- **Architecture:**
  - `docs/ARCHITECTURE.md` §5.1 (Two-stage detector) — Stage 2 Haiku admits at confidence ≥ 0.7. The slider is the exposed knob over that cutoff (heuristic-only at one extreme = $0 filter cost, strict-Haiku at the other = lowest false-positive rate).
  - §5.2 (Sliding window) — silence threshold is 800 ms by default. Risk register R-2 (INDEX) calls this out as a tunable Settings value because synthetic vs. real meeting cadence differ.
  - §13 (Cost Model) — the cost-guard $/h threshold is exposed so a heavy user can raise it for a long-form meeting (or lower it for a budget-tight session).
- **PRD:** US-04 (auto-detect highlighted), US-09 (cost-aware) — Settings is the lever on both. US-12 (manual fallback) stays decoupled (settings here do not gate manual-mark).
- **Carry-forward (read-only):**
  - `src/llm/haikuFilter.ts` (T-2.3) — `HAIKU_ADMIT_THRESHOLD = 0.7` default. The slider raises/lowers the live cutoff (via `applySettingsToClassification` helper here) without re-prompting the model.
  - `src/cost/costGuard.ts` (T-2.7) — `DEFAULT_THRESHOLD_USD_PER_HOUR = 0.5`, `setPaused()`. T-2.9 binds the saved values to a fresh `createCostGuard(...)` on meeting-start.
  - `src/detector/sliding-window.ts` (T-2.2) — `DEFAULT_SILENCE_MS = 800`. Settings exposes this as the second tunable (Phase-2 default; raise for chatty cohorts, lower for fast-paced QA).
  - `src/detector/heuristic.ts` (T-2.1) — pure function; no settings knob in v0.2 (the Haiku stage is the precision-recall lever).

## Scope (in)

1. New module **`src/store/settingsStore.ts`** — factory `createSettingsStore({ storage?, storageKey?, now? })` + module-level default singleton `useSettingsStore` that:
   - Defines `SettingsState` shape (5 user-tunable values + actions + reset).
   - Loads from injected `Storage` (defaults to `globalThis.localStorage`) on construction. Bad/missing JSON → defaults silently.
   - Persists synchronously on every setter via the same `Storage`. Failures (quota exceeded, security error) are swallowed — settings reads never fail; writes are best-effort.
   - Versioned key (`meeting-copilot:settings:v1`) so future migrations have a hook.
   - Setters clamp out-of-range values to the documented bounds (no surprise NaN / negative thresholds in downstream pipeline).
2. New helper **`classifyWithSettingsGate(text, classify, settings, costGuard?, opts?)`** — composer that:
   - Returns `{ status: "skipped-disabled" }` when `settings.haikuEnabled === false` (heuristic-only mode → $0 filter cost; Stage 2 short-circuits).
   - Otherwise delegates to `guardedClassifyWithHaiku` (T-2.7) so the cost-guard pause flag still wins (guard takes precedence over settings — guard is a *runtime brake*, settings is a *user preference*).
   - When the classifier returns, applies the `haikuConfidenceCutoff` to the result: an admit decision (`isQuestion: true && confidence ≥ cutoff`) is exposed via the returned `admit: boolean` so callers do not have to recompute. The original `result` is preserved verbatim.
3. **Tests** — `src/store/settingsStore.test.ts` (Vitest, default `node` env — no DOM needed, mock storage is a `Map`-backed `Storage`-shape) covering defaults, clamping, persistence round-trip, corrupted-storage fallback, and the `classifyWithSettingsGate` composer.

## Scope (out / deferred)

- **Settings React component (sheet / drawer / form)** — deferred. The store is the contract; a slider component is a thin wrapper any future UI iteration can build (a single `<input type="range" min="0" max="1" step="0.05" value={cutoff} onChange={(e) => setHaikuConfidenceCutoff(+e.target.value)}>` plus its checkbox siblings). Phase 2.x can land this as a backlog item without touching the store.
- **API key UI** — Phase 1.x backlog (`ANTHROPIC_API_KEY` is read from env in T-2.3 / T-1.10; UI for entering it is out of Phase-2 scope per INDEX line 55 risk note).
- **Provider picker / model picker** — Phase 3 (multi-provider track).
- **Per-meeting overrides** — settings are global. A future "this meeting only" override would layer on top via a mergeable selector; we ship the global tier first.
- **Migration v1 → v2** — N/A. The versioned key gives us the hook; migration logic ships alongside the first breaking shape change.
- **SQLite-backed settings persistence** — out of scope. `localStorage` covers the v0.2 surface (settings are per-device user preferences; no need for SQLite cross-device sync).

## Acceptance Criteria

| # | Criterion | How measured |
|---:|---|---|
| AC-1 | **Defaults match the source-of-truth constants.** New store reads `haikuConfidenceCutoff = HAIKU_ADMIT_THRESHOLD (0.7)`, `haikuEnabled = true`, `silenceThresholdMs = DEFAULT_SILENCE_MS (800)`, `costGuardThresholdUsdPerHour = DEFAULT_THRESHOLD_USD_PER_HOUR (0.5)`, `costGuardPaused = false`. | Vitest unit: assert each field on a freshly-created store with empty storage. |
| AC-2 | **Slider change updates threshold.** `setHaikuConfidenceCutoff(0.85)` → `getState().haikuConfidenceCutoff === 0.85`. Same for `setSilenceThresholdMs` + `setCostGuardThresholdUsdPerHour`. | Vitest unit: 3 cases. |
| AC-3 | **Toggle disables Haiku.** `setHaikuEnabled(false)` → composer returns `{ status: "skipped-disabled" }` and inner `classify` is NOT called (spy callCount === 0). | Vitest unit: spy + composer call. |
| AC-4 | **Persistence across reload.** Mutate store A; construct store B with the SAME `Storage` instance; B reads back the mutated values. | Vitest unit: write 5 fields, recreate, assert each. |
| AC-5 | **Default-restore on empty / corrupted storage.** Storage with malformed JSON / wrong-shape JSON / missing keys → store falls back to defaults silently. No throw. | Vitest unit: 3 cases (empty, garbage-string, partial-shape JSON). |
| AC-6 | **Setter clamping.** Out-of-range inputs are clamped: `haikuConfidenceCutoff` ∈ [0, 1]; `silenceThresholdMs` ∈ [200, 10_000]; `costGuardThresholdUsdPerHour` ∈ [0, 100]. NaN inputs are rejected (state unchanged). | Vitest unit: 4 cases per field (below, above, NaN, mid-range). |
| AC-7 | **`reset()` restores defaults.** After mutating all fields + persisting, `reset()` → `getState()` matches defaults; storage now contains the defaults too (so a re-construct also gets defaults). | Vitest unit. |
| AC-8 | **`classifyWithSettingsGate` honors cost-guard pause.** With `haikuEnabled = true` and `costGuard.isPaused() === true`, composer returns `{ status: "skipped-paused" }` (cost-guard wins) and the inner `classify` is NOT called. | Vitest unit: spy + paused guard. |
| AC-9 | **`classifyWithSettingsGate` records usage when classified.** Inner classifier returns a fixed `HaikuClassification`; composer returns `{ status: "classified", result, admit }`; the cost guard's `recordHaikuUsage` is invoked exactly once with `result.usage`. | Vitest unit: spy on `recordHaikuUsage` via a composed test guard. |
| AC-10 | **`admit` flag respects the slider.** `result.confidence = 0.7` + `cutoff = 0.85` → `admit === false`. `result.confidence = 0.9` + `cutoff = 0.85` → `admit === true`. NO impact on `isQuestion` (preserved verbatim from upstream). | Vitest unit: 2 cases. |
| AC-11 | **Storage write failures swallowed.** A `setItem` that throws (quota exceeded, security policy) does NOT propagate out of the setter. State still mutates in-memory; only the persistence side is best-effort. | Vitest unit: throwing-`setItem` mock; setter call must not throw. |
| AC-12 | **No edits to T-1.x / T-2.1..T-2.8 source files.** Settings store is purely additive. | git diff inspection + whole-repo `bun test` green + `tsc --noEmit` clean. |
| AC-13 | **Phase-1 + earlier-Phase-2 regression-free.** | `bun run test` baseline 373 → 373 + N net new (all green). |
| AC-14 | **Versioned storage key.** Module exports `SETTINGS_STORAGE_KEY === "meeting-copilot:settings:v1"`. The next migration bumps `:v2` and adds a coercion helper here; v0.2 ships v1 only. | Vitest unit: `SETTINGS_STORAGE_KEY` constant assertion + key-write inspection on the mock storage. |
| AC-15 | **`haikuEnabled = false` short-circuits before the cost-guard check.** Even if the guard is paused, when Haiku is disabled the wrapper returns `{ status: "skipped-disabled" }` (settings is the more-restrictive gate; cost-guard doesn't even need to run). Documents the precedence: `settings.haikuEnabled === false` ⇒ skipped-disabled, else `guard.isPaused() === true` ⇒ skipped-paused, else classify. | Vitest unit: disabled + paused → `{ skipped-disabled }`, classifier NOT called. |

## Risk Register

| # | Risk | Probability | Impact | Mitigation |
|---|---|---|---|---|
| R-1 | **Slider mis-clamping causes detector pipeline to admit nothing.** A buggy clamp (e.g. > instead of ≥, or upper-bound 0 instead of 1) would silently kill detection. | Low | High | AC-6 covers above/below/NaN/mid-range for each field. AC-10 verifies the cutoff is applied as `≥` (admits at exact cutoff). |
| R-2 | **Persistence corruption locks user out of defaults.** A bad shape on disk could throw on load → store unusable. | Low | Medium | AC-5 fallback path: any JSON.parse error or shape-mismatch silently restores defaults. Test `SS-S2` (garbage string) + `SS-S3` (partial JSON) covers. |
| R-3 | **Settings change not propagated to live cost guard.** User flips `costGuardPaused = true` in Settings; the existing `costGuard` instance does not see it. | Medium | Medium | Scope is the **store**; the wiring layer (Phase-2.x React Settings sheet) is responsible for `useEffect(() => costGuard.setPaused(state.costGuardPaused), [...])`. The composer helper `classifyWithSettingsGate` makes the precedence explicit so a misconfigured wiring pre-Phase-2.x at least exhibits documented behavior. |
| R-4 | **Storage quota exceeded crashes UI on toggle.** Some browsers throw on `setItem` when storage is full. | Low | Low | AC-11 — write failures are caught + swallowed; in-memory state still mutates. The user loses persistence for that one tick; the UI does not crash. |
| R-5 | **`localStorage` undefined at construction time** (Tauri webview pre-init or test env without DOM). | Low | Low | Factory accepts injected `storage` arg; default singleton lazily reads `globalThis.localStorage` only at construction. Test env passes a `Map`-backed mock; production reads the real `localStorage`. AC-5 scope-guard test (`SS-S28`) covers `null` storage. |

## Hand-off

- **T-2.10 E2E** — uses `createSettingsStore` directly (no UI sheet) to dial the synthetic-fixture detector to a known-deterministic configuration: `haikuEnabled = true`, `haikuConfidenceCutoff = 0.7`, `silenceThresholdMs = 800` (verbatim defaults). Establishes the metric report's ground state.
- **Phase-2.x Settings sheet** — wraps the store in a `<SettingsPanel>` React component with sliders + checkboxes. The store is the only contract; the sheet edit lands without touching detector / queue / cost-guard code.
- **Phase 3 multi-provider** — extends `SettingsState` with `provider: "anthropic" | "openai" | ...` and `apiKey: { anthropic?: string; openai?: string; }`. Migration `v1 → v2` lands here.
