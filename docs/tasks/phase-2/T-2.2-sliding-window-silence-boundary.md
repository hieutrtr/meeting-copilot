## Scope

A pure stateful struct (closure-based; no React, no Tauri events directly):

```ts
interface Utterance {
  text: string;        // chunk texts joined + whitespace-collapsed
  startTs: number;     // earliest chunk.startTs
  endTs: number;       // latest chunk.endTs
  chunkIds: string[];  // in arrival order
}

interface SlidingWindow {
  push(chunk: TranscriptChunk): Utterance[]; // 0 or 1 emit per call (or 1 + 1 in the rare flush-then-push edge case)
  flush(): Utterance[];                      // drain pending buffer, e.g. on meeting end
  pending(): Utterance | null;               // observe in-flight aggregate (no mutation)
  reset(): void;                             // hard clear (e.g. between meetings)
}

function createSlidingWindow(opts?: SlidingWindowOptions): SlidingWindow;
```

`Utterance` lives in `shared/types.ts` next to `TranscriptChunk` so Rust ⇄ TS schema-parity assumptions stay simple if a future task moves the assembler into the Rust helper daemon.

### Boundary rules

An utterance is closed (and emitted) when **any** of the following triggers fire:

1. **Silence gap.** `nextChunk.startTs - bufferLastChunk.endTs ≥ silenceThresholdMs` (default **800 ms**). Mirrors ARCH §5.1 third-bullet rationale ("intonation rise" is the prosody analogue we cannot use; silence is the fallback we *can* observe). The current chunk that triggered the gap starts a *new* buffer — it is NOT discarded.
2. **Final-with-punctuation.** The current chunk has `isFinal === true` AND its trimmed text ends with sentence-terminating punctuation (`.`, `!`, `?`, `…`, plus CJK `。`, `！`, `？` for forward-compat). The chunk is appended to the buffer, the buffer is emitted, then cleared.
3. **`flush()` called.** Caller signals "no more chunks coming" (e.g. meeting ended). Whatever is in the buffer drains as a final utterance even without a punctuation closer.

Sub-threshold gaps and `isFinal:false` chunks **never** close the utterance — interim partials accumulate until either (1) or (2) fires. This matches the MLX whisper streaming model where interim partials are revised text from the same sentence.

### Defaults + tunables

- `silenceThresholdMs`: 800 (per INDEX.md). Exposed for T-2.9 settings (sensitivity slider's silence half).
- `endPunctuation`: `/[.!?…。！？]\s*["”'')\]]?\s*$/` — closing punctuation followed by optional trailing quote/bracket. Configurable for languages we have not pinned yet.

## Acceptance Criteria

Verbatim from plan (T-2.2):

> Synthetic chunked-transcript fixture verifies correct segment boundaries.

Translated (consistent with INDEX.md row): on a 1-minute synthetic chunk fixture with **10 ground-truth utterances**, the assembler's emitted utterances must match ≥ **80 %** of ground-truth boundaries (8 / 10 minimum). A "match" requires:

- `|emitted.startTs − groundTruth.startTs| ≤ 100 ms`
- `|emitted.endTs − groundTruth.endTs| ≤ 100 ms`
- `emitted.chunkIds` set-equal to `groundTruth.chunkIds` (order = arrival order)

Numeric metric (boundary correctness = matches / 10) recorded in `T-2.2-review.md`. The fixture is hand-authored to be solvable at 100 % so any drop signals a regression.

## TDD Plan

Test file: `src/detector/sliding-window.test.ts`. Fixture file: `shared/fixtures/sliding-window-1min.json`.

Test cases (Vitest):

1. **Fixture shape gate** — fixture has exactly 10 ground-truth utterances; ground-truth `chunkIds` partition the chunk stream (no chunk used twice, no chunk orphaned). Guards against accidental fixture edits.
2. **Silence boundary triggers an emit** — two-chunk feed where the gap is ≥ 800 ms emits exactly one utterance on the second push (the second chunk starts a fresh buffer).
3. **Sub-threshold gap does NOT split** — same shape but gap = 700 ms → 0 emits, `pending()` shows both chunks merged.
4. **Final-with-punctuation triggers an emit** — single `isFinal:true` chunk ending in `.` emits immediately.
5. **Final without punctuation does NOT split** — `isFinal:true` chunk without sentence-terminator (e.g. trailing `,`) does not emit; waits for silence or `flush()`.
6. **Interim partials accumulate** — three `isFinal:false` chunks back-to-back → 0 emits, `pending().text` is the joined+collapsed form.
7. **`flush()` drains pending** — after partial input, `flush()` returns one utterance and `pending()` returns null afterwards.
8. **`reset()` clears state** — `pending()` returns null after reset; subsequent push starts clean.
9. **CJK / VI punctuation** — `？` and `…` close. `。` closes. Spot-check.
10. **Aggregate boundary correctness gate** — feed all fixture chunks in order, collect emits + final `flush()`. Compare emitted utterances vs ground-truth, assert `correctness ≥ 0.8`. **This is the AC gate.**
11. **Determinism** — same fixture twice → identical emit sequence (no hidden state across fresh `createSlidingWindow()` instances).
12. **Empty stream** — no `push` calls + `flush()` → empty array. `pending()` is null.

## Risk + Mitigation

| Risk | Mitigation |
|---|---|
| **Synthetic fixture cadence diverges from real STT cadence** (e.g. real MLX whisper may emit chunks every 1–2 s of audio with overlapping interim revisions). | T-2.10 real-recording verify is the empirical gate; T-2.2 fixture is the unit-level guard. The 800 ms threshold is exposed via T-2.9 settings so users on slow speakers can tune. |
| **Punctuation-stripped STT output never closes** ("...the deadline is friday" with no period). | Silence-gap fallback (rule 1) always closes. Worst case: utterance ends ~800 ms late, still well within end-to-end < 3 s budget. |
| **`isFinal:true` revisions over the same time range overwrite earlier interim text incorrectly.** MLX whisper sometimes re-emits a chunk with corrected text. | Out-of-scope for T-2.2 v0.2 — current implementation appends every chunk verbatim. If revisions cause double-counting, T-2.10 catch-rate will surface it; mitigation is a Phase-2.x backlog item ("dedup `isFinal:true` revision over same `[startTs, endTs]` window"). |
| **Buffer leak on never-ending stream without silence or punctuation** (degenerate case: continuous filler "uhhh uhhh uhhh"). | `pending()` exposes the buffer for caller-side guards; T-2.5 queue worker will impose its own admission policy. T-2.2 itself does not need a max-buffer cap in v0.2. |
| **Trigger ordering when both rules fire on the same push** (e.g. silence gap closes the previous buffer AND the new chunk is a final-with-punctuation single-chunk utterance). | `push()` emit array can contain two utterances on the same call: first the silence-flushed previous buffer, then the punctuation-closed new chunk. Test case 4 + a combined scenario in test case 10 (fixture U2→U3 transition) covers this. |

## Out of Scope (explicitly deferred)

- Prosody / intonation rise signal (no MLX support — same deferral as T-2.1).
- Speaker-change boundary (`speaker` field flip closes utterance) — Phase 2 PRD does not require speaker-aware assembly; will revisit if T-2.10 metrics are weak on multi-speaker fixtures.
- Re-segmentation of `isFinal:true` revisions over the same time window.
- Max-buffer guard / hard timeout (deferred to T-2.5 queue admission policy).
