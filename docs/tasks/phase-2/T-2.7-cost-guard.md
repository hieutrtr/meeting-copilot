# T-2.7 — Cost Guard: Per-Meeting Token Counter + Threshold Alert

> Phase 2, task #7 of 10. Companion review = `T-2.7-review.md`. Spec source = `docs/tasks/phase-2/INDEX.md` line 53.
>
> Off-critical-path: depends only on T-2.3 (Haiku usage shape) and T-1.10 carry-forward (`pricing.ts`, `AnthropicUsage`). Lands the *state machine* + math + a thin Haiku wrapper helper. UI surface is deferred to T-2.8 (banner) / T-2.9 (settings toggle).

## Reference

- **Plan:** `docs/IMPLEMENTATION-PLAN.md` Phase 2 row T-2.7 — "Track Haiku token usage per meeting, warning UI nếu > $0.50/hour. AC: counter chạy realtime, alert hiện đúng threshold."
- **Architecture:**
  - `docs/ARCHITECTURE.md` §13 (Cost Model) — local-first $0.31/h, mixed $0.71/h, cloud $0.97/h. Haiku filter ≈ $0.005/h on a 30-candidate-per-hour cadence; Sonnet warm-cache ≈ $0.005/turn × 10 turns/h ≈ $0.05/h. Combined headroom is wide vs $0.50/h, but a talky meeting (3 candidates/min × 60 min = 180 candidates) drives Haiku to $0.04/h on its own — combined with frequent answers can approach the $0.50/h ceiling. ARCH §"Risk Register" #5 explicitly calls out "Cost overrun" as a top-5 risk; this task is the in-app counterpart of that mitigation.
  - §6.2 (Prompt Cache) — both Haiku (T-2.3) and Sonnet (T-1.10) use ephemeral cache. Cost guard reads `cache_read_input_tokens` / `cache_creation_input_tokens` / `input_tokens` / `output_tokens` from the `usage` shape `pricing.ts` already understands.
- **PRD:** US-09 ("Cost-aware") implicit in Phase-2 cost guard goal — surface cost, give user a brake. T-2.9 will wire the brake (pause toggle) into Settings.
- **Carry-forward (read-only):**
  - `src/llm/pricing.ts` (T-1.10 + T-2.3 extension) — `computeCostUsd(usage)` for Sonnet, `computeHaikuCostUsd(usage)` for Haiku, both taking the same `AnthropicUsage` shape.
  - `src/llm/haikuFilter.ts` (T-2.3) — `HaikuClassification.usage` is the input to the cost guard. The wrapper `guardedClassifyWithHaiku` in this task short-circuits the Haiku call when `paused`.
  - `src/queue/queueWorker.ts` (T-2.6) — `onItemDone(item, result)` exposes `result.usage` (Sonnet) which T-2.7 reads via `recordSonnetUsage`. No edit to T-2.6 required.

## Scope (in)

1. New module **`src/cost/costGuard.ts`** — pure factory `createCostGuard(opts)` returning a closure-scoped state machine with:
   - `recordHaikuUsage(usage)` — increments Haiku counter, recomputes cost via `computeHaikuCostUsd`, fires latched `onAlert` callback when projected cost-per-hour first crosses threshold.
   - `recordSonnetUsage(usage)` — same shape but uses `computeCostUsd` (Sonnet pricing).
   - `snapshot()` — read-only view of current state (haiku counter, sonnet counter, total, elapsed, projected, threshold, latched-flag, paused-flag). Defensive copies on read so React state can compare cheaply.
   - `setPaused(p)` / `isPaused()` — toggle that callers (T-2.3 wrapper, T-2.9 Settings) flip; cost guard does NOT enforce pause itself, only carries the flag.
   - `reset()` — zero the counters, un-latch the alert, advance `meetingStart` to `now()`. Called on `meetingStore.startNew()`.
2. New helper **`guardedClassifyWithHaiku(text, classify, guard, opts?)`** — composer that:
   - Returns `{ status: "skipped-paused" }` when `guard.isPaused()` is true (no SDK call made).
   - Otherwise awaits `classify(text, opts)`, calls `guard.recordHaikuUsage(result.usage)`, and returns `{ status: "classified", result }`.
   - This is the integration seam T-2.3's caller swaps in. Keeping it a function (not a closure) makes it trivial to compose into `useDetectorPipeline` (T-2.8) without leaking state.
3. **Tests** — `src/cost/costGuard.test.ts` (Vitest) covering counter math, threshold latch, pause flag, reset semantics, and the composer wrapper.

## Scope (out / deferred)

- **UI surface (banner / counter chip)** — deferred to **T-2.8** which wires the snapshot into the AnswerPanel header. T-2.7 ships only the state machine + tests; no React component lands.
- **Settings UI for the pause toggle / Haiku-disable** — deferred to **T-2.9** (Settings sheet). The cost guard exposes `setPaused`; T-2.9 binds it to a checkbox + `localStorage`.
- **Hard-stop / cost-cap enforcement** — Phase 2 ships *advisory* (alert + opt-in pause). A hard-stop that automatically pauses Haiku when the threshold crosses is a Phase-2.x decision; the latch we ship is the lower bound on that future behavior (the alert is fired exactly once, callers may flip `setPaused(true)` from inside `onAlert` if they want auto-pause).
- **Sonnet quota separately** — the AC speaks of Haiku usage, but the cost-guard math sums Haiku + Sonnet because the user-visible "$/hour" includes the answer cost too. The counter shape distinguishes them so T-2.8 can render a breakdown chart later, but for the alert we sum `haiku.costUsd + sonnet.costUsd`.
- **Persistence across reload** — counters reset every meeting. SQLite-backed historical-cost reporting is a Phase-3 concern (cost meter UI is Phase-3 T-3.5).

## Acceptance Criteria

| # | Criterion | How measured |
|---:|---|---|
| AC-1 | **Counter math is verbatim `computeHaikuCostUsd` / `computeCostUsd`.** Recording N usage events sums the cost as if the caller called the helper N times. | Vitest unit: feed 3 Haiku usages, assert `snapshot().haiku.costUsd === sum(computeHaikuCostUsd(...))`. |
| AC-2 | **Token counters add up correctly.** `inputTokens`, `cacheCreationTokens`, `cacheReadTokens`, `outputTokens` accumulate across calls; `calls` counter increments by 1 per `record*Usage`. | Vitest unit: feed 2 usages with known token counts, assert each counter field. |
| AC-3 | **`totalCostUsd === haiku.costUsd + sonnet.costUsd`** (no double counting, no other costs leaked in). | Vitest unit: mix Haiku + Sonnet usages, assert sum invariant. |
| AC-4 | **Threshold-crossing alert fires exactly once.** Project = total / elapsed × 3_600_000. When projection first exceeds `thresholdUsdPerHour`, `onAlert(snapshot)` fires; subsequent records past threshold do NOT re-fire. | Vitest unit: configure threshold $0.50/h + 1 h elapsed; feed cost = $0.51 → alert fires; feed another cost = $0.10 → alert does NOT fire again. |
| AC-5 | **Below-threshold record does NOT fire alert.** | Vitest unit: feed cost = $0.49 / 1 h elapsed → `alertSpy.callCount === 0`. |
| AC-6 | **Alert callback receives a snapshot with `thresholdCrossed: true`** so the UI can render the alert state from the same shape it uses for the live counter. | Vitest unit: capture `onAlert` arg, assert `snap.thresholdCrossed === true` and `snap.projectedCostPerHourUsd > snap.thresholdUsdPerHour`. |
| AC-7 | **Warm-up gate prevents false alarms when elapsed is small.** With the default `minElapsedMsForProjection = 60_000` (1 min), a $0.10 Haiku spike inside the first 30 s does NOT trigger the alert. The user-visible projection reads 0 (or the configured floor) until the warm-up window passes. | Vitest unit: with `now()` advancing only 30 000 ms, feed cost = $1.00 → `snapshot().projectedCostPerHourUsd === 0` and `alertSpy.callCount === 0`. After advancing past 60 000 ms, the projection becomes the real number; if still > threshold, alert fires. |
| AC-8 | **Pause flag round-trips.** `setPaused(true)` then `isPaused() === true`; `setPaused(false)` flips back. Default initial state is `false`; option `paused: true` overrides initial state. | Vitest unit: 3 cases. |
| AC-9 | **Paused state does NOT prevent recording usage** (callers may still record after a manual SDK call landed mid-pause). The flag is a *signal* not an *interlock* — callers (T-2.3 wrapper) honor it. | Vitest unit: pause + record → `haiku.calls === 1`. |
| AC-10 | **`reset()` zeroes counters + un-latches alert + advances `meetingStart` to current `now()`.** A second alert can fire after reset. | Vitest unit: trigger alert, reset, feed same cost again → alert fires a second time (post-reset). |
| AC-11 | **`guardedClassifyWithHaiku` short-circuits when paused** — inner classifier is NOT invoked, returns `{ status: "skipped-paused" }`, no usage recorded. | Vitest unit: spy on classifier, set paused, call wrapper, assert spy not called + return shape. |
| AC-12 | **`guardedClassifyWithHaiku` records usage when not paused** — inner classifier invoked once, `recordHaikuUsage` called once with the result's usage, returns `{ status: "classified", result }`. | Vitest unit: spy on classifier returning a fixed `HaikuClassification`, assert wrapper return + counter increment. |
| AC-13 | **Default threshold is $0.50/h** (per plan). | Vitest unit: `createCostGuard()` snapshot has `thresholdUsdPerHour === 0.5`. |
| AC-14 | **`onAlert` callback errors do not crash the guard.** A throwing callback is swallowed (telemetry-only). | Vitest unit: pass `onAlert` that throws; force crossing; assert no exception escapes `recordHaikuUsage`. |
| AC-15 | **No edits to T-1.x / T-2.1..T-2.6 source files.** Cost guard is purely additive. | git diff inspection + whole-repo `bun test` green + `tsc --noEmit` clean. |
| AC-16 | **Phase-1 regression-free.** | `bun test` 320 → 320 + N net new (all green). |

## Risk + Mitigation

| # | Risk | Mitigation |
|---:|---|---|
| 1 | **Pricing constants drift** — Anthropic changes per-MTok price → counter overstates / understates by 10-20% silently. | Constants are pinned in `src/llm/pricing.ts` with a comment dating the snapshot (2026-05). The cost guard imports — does NOT redefine — those constants. T-2.7 review re-verifies the imports are byte-identical. ARCH §13 footnote calls this out; Phase 4 may add a remote-config refresh. |
| 2 | **False alarm in warm-up** — meeting starts, 1 expensive Haiku call lands in first 5 s → projected $X/h is wildly inflated. | `minElapsedMsForProjection` (default 60 000 ms) gates the projection. Inside the warm-up, projection reads 0; outside, projection is the real number. Tunable per-test. |
| 3 | **Latch never resets across meetings** — same `CostGuard` instance carried into a new meeting with a stale latch → alert never fires for the new meeting. | `reset()` is called on `meetingStore.startNew()` (T-2.8 wiring). Tests verify post-reset alert can fire again. |
| 4 | **`onAlert` callback throws inside React render path** — unhandled rejection breaks the worker drain. | Callback is wrapped in `try { onAlert?.(snap) } catch {}`. Test CG-S23 verifies. |
| 5 | **Pause flag race with in-flight Haiku call** — user pauses while a Haiku call is mid-flight → flag is checked synchronously *before* the call, so this race is benign for the next call but not for the in-flight one. | Documented as expected behavior — the in-flight call completes and its usage is recorded (per AC-9). Phase-2.x may add `AbortController` plumbing to the wrapper. |
| 6 | **Threshold semantics ambiguous (`>` vs `>=`)** — reviewer reads "fires at $0.50" and infers `>=`. | Spec + implementation both use strict `>`. Test CG-S5 / CG-S9 reads $0.49 (no fire) + $0.51 (fire); the boundary case `=== $0.50` is documented as no-fire to keep the math reproducible under floating-point math. |
| 7 | **Cost guard only counts what's *recorded*** — if a caller forgets to call `record*Usage`, the counter underreports silently. | The composer `guardedClassifyWithHaiku` is the canonical Haiku integration. T-2.6 worker forwards Sonnet usage via `onItemDone(item, result)` — the T-2.8 wiring is responsible for calling `recordSonnetUsage(result.usage)` from inside that callback; the wiring lives in T-2.8 and is documented in the hand-off section below. |

## Hand-off to T-2.8 (UX wiring)

T-2.8 wires the cost guard into the AnswerPanel header + a banner that flashes when `thresholdCrossed: true`. Wiring sketch:

```ts
// In the App-level wiring (T-2.8 scope):
const costGuard = useMemo(
  () => createCostGuard({
    onAlert: (snap) => {
      // Surface a non-blocking toast / banner. Pause is opt-in via T-2.9.
      uiBus.emit("cost-guard-alert", snap);
    },
  }),
  [],
);

// Detector pipeline (T-2.3 caller):
const result = await guardedClassifyWithHaiku(text, classifyWithHaiku, costGuard);
if (result.status === "skipped-paused") return null;

// Worker:
const worker = createQueueWorker({
  // ... existing wiring ...
  onItemDone: (_item, result) => {
    costGuard.recordSonnetUsage(result.usage);
  },
});

// React selector for the banner:
const snap = useSyncExternalStore(
  costGuard.subscribe ?? (() => () => {}), // T-2.7 ships pure read; T-2.8 may add subscribe
  () => costGuard.snapshot(),
);
```

Note: T-2.7 does NOT ship `subscribe`. T-2.8 either polls `snapshot()` on a 1 s `setInterval` or threads the snapshot through the `onAlert` event bus (the latter is cheaper since the only state-change UI cares about is the threshold crossing — the live counter can be event-driven by re-snapping on every `record*Usage` call).

## Hand-off to T-2.9 (Settings — pause toggle)

T-2.9 binds a checkbox to `costGuard.setPaused()` and persists the flag in `localStorage`:

```ts
const [paused, setPausedLocal] = useLocalStorage("haiku-paused", false);
useEffect(() => {
  costGuard.setPaused(paused);
}, [paused]);
```

The Haiku-disable toggle in T-2.9 is a separate setting from the cost-guard pause: T-2.9's "disable Haiku entirely" short-circuits the detector pipeline upstream of the guard (heuristic-only mode = $0 filter cost). The cost-guard pause is the *post-alert* brake — user wants Haiku in general but stop it for this meeting after the alert. The two settings interact OR-style: detector skips Haiku if **either** is active.
