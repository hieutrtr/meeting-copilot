## Scope

A pure function for request shape + parser, plus an async classifier wrapping the Anthropic SDK's `messages.create`:

```ts
buildHaikuRequest(text: string): HaikuRequestBody
parseHaikuVerdict(raw: string): { isQuestion, confidence, reason }
classifyWithHaiku(text: string, opts?: ClassifyOptions): Promise<HaikuClassification>
```

Where:

- `HaikuRequestBody` mirrors the Phase-1 request shape: `model: "claude-haiku-4-5-20251001"`, `max_tokens: 80`, `temperature: 0`, `system: [STATIC_INSTRUCTIONS]` with `cache_control: ephemeral`, single user message containing the utterance.
- `HaikuClassification = { isQuestion, confidence, reason, rawText, latencyMs, usage, costUsd }`.
- Parser maps a single-line `YES <reason>` / `NO <reason>` reply to:
  - `YES` → `{ isQuestion: true, confidence: 0.9 }`
  - `NO`  → `{ isQuestion: false, confidence: 0.1 }`
  - anything else → `{ isQuestion: false, confidence: 0.5, reason: rawText }` (treated as ambiguous; the queue admits only ≥ 0.7).
- Threshold gate (`HAIKU_ADMIT_THRESHOLD = 0.7`) is exported as a constant; the queue (T-2.5) does the comparison. T-2.3 itself returns the classification without short-circuiting.

`MissingApiKeyError` is re-exported from `claudeClient.ts` semantics (subclassed via shared base) so a missing key surfaces synchronously and the queue can drop the candidate without crashing — same shape as `askClaude()`.

## Acceptance Criteria

Verbatim from plan (T-2.3, lines 81–82):

> Mỗi candidate (~3-10/phút) gửi qua Haiku với prompt: "Câu sau có phải câu hỏi user nên trả lời không? Trả YES/NO + 1 câu lý do."
> Threshold: chỉ trigger answer nếu confidence ≥ 0.7. Cost: ~$0.0002/call, < $0.005/giờ meeting.

Translated to numeric AC:

1. **Structural request shape** (mocked SDK):
   - body.model === `"claude-haiku-4-5-20251001"`
   - body.max_tokens ≤ 100 (we pin to 80)
   - body.temperature === 0
   - body.system has exactly one block with `cache_control: { type: "ephemeral" }`
   - body.messages has 1 user message with the utterance text embedded
   - byte-identical body across two calls with same input (cache-key stability)
2. **Gold-label agreement** on the 100-sample fixture: end-to-end `classifyWithHaiku(sample.text)` agrees with `sample.expected` ≥ **85 %** (= 85 / 100). Numeric metric printed by the AC test and recorded in `T-2.3-review.md`.
3. **Parser robustness**: `YES`, `Yes`, `YES.`, `YES,`, `YES — reason`, leading whitespace, trailing punctuation all parse to `isQuestion: true`. Same for `NO`. Garbage replies (`MAYBE`, empty, multi-line preamble) classify as `isQuestion: false, confidence: 0.5` (will not trip the 0.7 threshold).
4. **Latency budget plumbing**: classification result carries `latencyMs` measured around the SDK call; mocked-SDK call yields a real (small) number ≥ 0 from `performance.now()`. Live AC (< 500 ms / target 200 ms per ARCH §12) is hardware-blocked — annotated in browser-test as a manual host check (same shape as Phase-1 sign-off blockers).
5. **Cost plumbing**: `pricing.ts` exports `HAIKU_4_5_PRICING_USD_PER_MTOK` + `computeHaikuCostUsd(usage)`. Result carries `costUsd` derived from the usage block. Per-call cost on a typical mocked usage (≈ 150 in / 30 out) lands in $0.0001 – $0.0005 — the exact per-call number is recorded in `T-2.3-review.md`. T-2.7 consumes these constants for the cost guard.
6. **Credentials**: `MissingApiKeyError` thrown synchronously when `ANTHROPIC_API_KEY` is missing AND no `apiKey` opt is passed. Error message contains no key bytes. Fallback to env var when no opt is passed.

## Out of Scope (explicitly deferred)

- True log-prob derived confidence — Anthropic SDK does not expose token logprobs; rule-based 0.9/0.1 mapping is the v0.2 surrogate.
- Streaming / first-token render — Haiku output is short (≤ 80 tokens) and the consumer (queue) only needs the final verdict; non-streaming `messages.create` is faster end-to-end at this length.
- Tool-use / structured-output mode — overkill for a binary verdict; the YES/NO + reason single-line shape is the contract.
- JSON-mode response — Anthropic does not expose a strict JSON-mode flag at the message level on Sonnet/Haiku in this SDK version (you can prompt it but it's still text); we keep a simple line parser instead.
- Multi-lingual beyond EN+VI — TH/JA/ZH not required by current PRD personas; Haiku will still classify, but agreement on those is unmeasured.
- Embedding-based dedup (T-2.4 hash-only ships in v0.2; embedding similarity is Phase-2.x backlog).

## Hand-off to T-2.4 / T-2.5 / T-2.7

- **T-2.4 dedup** — consumes the parsed `text` (after Haiku says YES) and runs hash-dedup. Haiku's `reason` is logged for telemetry only.
- **T-2.5 queue** — admit gate: `result.confidence >= HAIKU_ADMIT_THRESHOLD` (0.7). Drops with reason `"haiku-rejected"` if below threshold.
- **T-2.7 cost guard** — sums `result.costUsd` per meeting; cross-references `pricing.ts::HAIKU_4_5_PRICING_USD_PER_MTOK`.
- **T-2.9 settings** — exposes a "skip Haiku filter" toggle (heuristic-only mode = $0 filter cost) and a sensitivity slider that is functionally equivalent to lowering / raising `HAIKU_ADMIT_THRESHOLD`.
