## Out-of-Scope (deferred from spec)

- True log-prob derived confidence — Anthropic SDK does not expose token logprobs in this version; rule-based 0.9 / 0.1 / 0.5 mapping is the v0.2 surrogate.
- Streaming / first-token render — Haiku output is short (≤ 80 tokens); the consumer (queue) only needs the final verdict. Non-streaming is the right fit.
- Tool-use / structured-output / strict JSON-mode — overkill for a binary verdict + reason. Single-line `YES <reason>` / `NO <reason>` shape is the contract.
- Multi-lingual beyond EN+VI — TH/JA/ZH not covered by current PRD personas.

## Hand-off to T-2.4

T-2.4 (dedup window) consumes the verdict's parsed `text` (the original utterance, not Haiku's reason) and runs hash-based dedup. The threshold gate (`confidence ≥ 0.7`) lives in T-2.5's queue admit logic, not in T-2.4 itself. Integration sketch:

```ts
// In the queue worker (T-2.5):
const heuristic = detectCandidate(utt.text);            // T-2.1
if (!heuristic.isCandidate) return;
const verdict = await classifyWithHaiku(utt.text);      // T-2.3 (this task)
if (verdict.confidence < HAIKU_ADMIT_THRESHOLD) return;
const accepted = dedupAdmit(utt.text);                  // T-2.4
if (!accepted) return;
queue.push({ utterance: utt, verdict });                // T-2.5
```

The hand-off shape is stable as of this task: T-2.4 / T-2.5 do not need to touch `haikuFilter.ts` to integrate. Cost accumulation for T-2.7 reads `verdict.costUsd` per call; threshold enforcement for T-2.9 will mutate `HAIKU_ADMIT_THRESHOLD` via a settings store (or pass a per-call override into a future signature extension — choice deferred to T-2.9).
