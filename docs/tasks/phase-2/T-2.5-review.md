### Per-call cost projection (for T-2.7 cost guard input)

Pure-JS module — **$0.000000 / call**. No LLM call, no network, no SDK overhead. The queue is a *back-pressure regulator* for downstream Sonnet (`askClaude()`); T-2.7 will read `inFlight()` to attribute Sonnet usage to the right queued item id but the queue itself is free.

### Latency

Pure synchronous JS (`Array.push` / `Array.shift` for FIFO, `Map` ops in the persistence adapter). Per-call worst case at the AC stress envelope (`maxDepth = 5`, < 20 admits in 60 s):

- `enqueue` — O(maxDepth) for the eviction loop (≤ 5 shifts) + O(items) for the persistence-snapshot copy (≤ 6 items). Sub-microsecond on a modern laptop.
- `dequeue` — O(1) head shift + O(items) snapshot copy.
- `complete` / `fail` — O(1) compare + O(items) snapshot copy.

Well under the < 50 ms admit budget per ARCH §12 (the queue is not on the hot path beyond the push/pop operations themselves).

## Hand-off to T-2.6

T-2.6 (auto-trigger) consumes the queue API directly. Stable integration shape:

```ts
// In the meeting bootstrap (T-2.6 / T-2.9):
const queue = createQuestionQueue({
  maxDepth: settings.queueMaxDepth,
  persistence: createQueuePersistenceAdapter(localCheckpointStore, meetingId),
});

// In the detector pipeline (T-2.1 → T-2.2 → T-2.3 → T-2.4 → here):
const dedupResult = dedup.admit(utt.text, utt.startTs);
if (!dedupResult.admitted) return;
const { admitted, itemId, droppedItemIds } = queue.enqueue({
  meetingId,
  utterance: utt,
  verdict,
  dedupHash: dedupResult.hash,
});
if (droppedItemIds?.length) {
  log("queue-drop", { reason: "backpressure", droppedItemIds });
}

// Worker loop (single-flight, driven by useEffect on size/busy changes):
useEffect(() => {
  if (queue.isBusy()) return;
  const next = queue.dequeue();
  if (!next) return;
  const ctrl = new AbortController();
  askClaude(next.utterance.text, { signal: ctrl.signal })
    .then(() => queue.complete(next.id))
    .catch((err) => queue.fail(next.id, String(err)));
  return () => ctrl.abort();
}, [queue.size(), queue.isBusy()]);
```

T-2.5 owns the lifetime: instantiates one `QuestionQueue` per meeting; `clear()` on meeting end / `meetingStore.startNew()`. T-2.9 settings will wire the `maxDepth` slider value into the constructor at meeting start.
