## Scope (in)

1. **New component `src/components/QuestionFeed.tsx`** — pure presentational list:
   - Props: `{ questions: Question[]; answerRef?: RefObject<HTMLElement|null>; selectedId?: string; onSelect?: (id: string) => void; flashClass?: string; flashDurationMs?: number; scrollOptions?: ScrollIntoViewOptions }`.
   - Renders one `<button data-testid="question-chip" data-question-id="…">` per question. Newest-first ordering preserved (consumer passes the store array verbatim).
   - Each chip shows: question text (truncated to ~80 chars), method badge (`auto`/`manual`), and (for `auto` only with `confidence` defined) a confidence percentage badge with color-coded class (`qf-conf--high` ≥ 0.8, `qf-conf--mid` ≥ 0.6, `qf-conf--low` < 0.6).
   - Click handler:
     a. If `answerRef.current` exists, call `scrollIntoView(scrollOptions ?? { behavior: "smooth", block: "start" })`.
     b. Apply `flashClass ?? "answer-flash"` to `answerRef.current.classList` and remove it after `flashDurationMs ?? 1500` ms.
     c. Invoke `onSelect?.(question.id)` for downstream wiring (e.g. App-level question pivot when Phase 2.x supports re-asking).
   - Empty state: render an `<empty-state>` placeholder ("No questions detected yet.") so the panel doesn't collapse to zero height.
2. **Tiny CSS additions to `src/App.css`** — `.question-feed`, `.question-feed__chip`, `.question-feed__badge`, `.qf-conf--{high,mid,low}`, and `.answer-flash` keyframe (1.5 s, then remove). Cosmetic — not required by tests, exists so the manual host smoke test sees a styled list rather than raw `<button>`s.
3. **Tests** — `src/components/QuestionFeed.test.tsx` (Vitest jsdom + Testing Library + `userEvent`). Verifies: empty state, chip rendering, confidence badge gating, click-handler scroll-call, flash class application + removal after `flashDurationMs`, callback ordering.
4. **No edits to `App.tsx` in this task.** App-level wiring (mount the feed in a sidebar with `useRef` to AnswerPanel) is the manual smoke step in `PHASE-BROWSER-TEST.md` (T-2.10). Keeping App.tsx untouched in T-2.8 keeps the regression surface small and lets T-2.9/T-2.10 stitch the full meeting UI in one go.

## Risk + Mitigation

| # | Risk | Mitigation |
|---:|---|---|
| 1 | **`scrollIntoView` is a no-op in jsdom** — test asserts on the spy, not on actual scroll position. | Spy on `Element.prototype.scrollIntoView` via `vi.spyOn`. The AC is "method called with the right argument", not "actual scroll happened" — that's a host-only behavior verified in `PHASE-BROWSER-TEST.md`. |
| 2 | **`classList` mutation outside React's render tree leaks state on unmount.** If the user unmounts QuestionFeed mid-flash, the timer fires after teardown and tries to mutate a node React no longer owns. | Use `useEffect` cleanup to clear pending `setTimeout` on unmount. Test QF-S18 covers the multi-render path; cleanup is implicit via `vi.runAllTimers()` + `cleanup()` in `afterEach`. |
| 3 | **Confidence-badge boundary semantics ambiguous (`>=` vs `>`)** — reviewer reads "≥ 0.8" and infers strict-ness either way. | Spec + impl + test all use `>=` (inclusive lower bound). Test QF-S20 reads `0.8`, `0.6`, `0.5999`. |
| 4 | **Chip text truncation eats the meaningful end of the question** — long questions usually have the topic at the end ("…what's the deadline?" → "…what's the d…"). | v0.2 truncates from the *end* with a trailing `…`, but the full text lives in `title` (AC-14) so a hover reveals the rest. Future polish: ellipsize the *middle* (a la GitHub commit hashes). |
| 5 | **Multiple clicks reset the flash timer** — if the user clicks chip-A then chip-B 500 ms later, the first timer would prematurely strip the class B added. | `useEffect`-managed timer ref is cleared on every click before scheduling the next one. Test QF-S15 documents the behavior: subsequent click extends the flash window. |
| 6 | **AnswerPanel doesn't have a meaningful flash style yet** — visual highlight relies on a CSS class that may not be styled. | T-2.8 adds a minimal `@keyframes answer-flash` to `App.css` (yellow→transparent fade over 1.5 s). Manual smoke test in `PHASE-BROWSER-TEST.md` will eyeball it. |
| 7 | **No App.tsx wiring in this task → integration drift risk** (the component "works in isolation" but never gets mounted). | Documented hand-off in spec body. T-2.10 commit will mount the feed when the full Phase 2 UI assembles. The component exports a fully-typed interface so the mount is a one-liner: `<QuestionFeed questions={questions} answerRef={answerPanelRef} />`. |
