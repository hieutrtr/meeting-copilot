## Risks Realized vs Forecast

Per `T-2.8-question-feed.md` Risk + Mitigation table:

| Risk | Forecast | What happened | Action |
|---|---|---|---|
| 1. `scrollIntoView` no-op in jsdom | spy on `Element.prototype.scrollIntoView` | jsdom 29.x doesn't ship the method on the prototype at all — `vi.spyOn` errored with "property is not defined". | Module-level `Object.defineProperty` installs a no-op stub on `Element.prototype.scrollIntoView` so `vi.spyOn` can replace it cleanly. Documented inline in test file. |
| 2. classList mutation across unmount | `useEffect` cleanup | Implemented as forecast. QF-S18 covers the multi-render path. No leak observed. | — |
| 3. Confidence boundary `>=` vs `>` | spec uses `>=` (inclusive lower bound) | Test QF-S20 explicitly hits 0.8, 0.6, 0.5999 to lock the boundary. | — |
| 4. Truncation eats meaningful tail | trailing `…` + full text in `title` | Implemented as forecast. AC-14 verifies. v0.2 acceptable. | — |
| 5. Multiple clicks reset timer | clear pending timeout on each click | Implemented; QF-S15 verifies prior timer is cancelled and new flash window starts. | — |
| 6. AnswerPanel has no flash style yet | App.css adds `@keyframes answer-flash-fade` | Implemented (yellow→transparent, 1.5 s ease-out). Manual smoke test in T-2.10 will eyeball it. | — |
| 7. App.tsx wiring drift | hand-off documented for T-2.10 | T-2.8 ships isolated component; T-2.10 mounts it next to AnswerPanel. Component interface fully typed → one-line mount. | — |

Unanticipated risk that surfaced during impl:

| # | Risk | Resolution |
|---|---|---|
| 8 | **`userEvent.click` deadlocks under `vi.useFakeTimers()`** — userEvent v14 schedules pointer-event ticks via `setTimeout(0)` chains; await loop blocks waiting for timers we control. | Flash + rerender tests switched to `fireEvent.click` (synchronous). Click-only tests (no fake timers) keep `userEvent` for the proper user-interaction simulation. Documented inline in the flash describe block. |
