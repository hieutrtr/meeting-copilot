## Scope (in)

1. New fixture file **`src/__tests__/fixtures/phase2-meeting.ts`** — a hand-curated 30-minute synthetic transcript (~50 utterances, ~12-15 ground-truth questions, ~35-38 ground-truth non-questions). Each entry carries:
   - `text: string` — the utterance text (mixed EN + VI to exercise both detectors).
   - `isQuestion: boolean` — gold-label, the source of truth for **catch rate**.
   - `useful?: boolean` — gold-label only on questions; encodes "would Sonnet (with the seeded context) produce a useful answer." Source of truth for **useful rate**.
   - `tsMs: number` — utterance start offset in milliseconds, distributed across a 1 800 000 ms (30 min) timeline.
   - `endTsMs: number` — utterance end. Gap `next.tsMs − cur.endTsMs` ≥ DEFAULT_SILENCE_MS (800 ms) so `createSlidingWindow` cleanly emits one utterance per fixture entry; punctuation closes the boundary as a fallback.
2. New end-to-end test file **`src/__tests__/Phase2-E2E.test.ts`** — a single Vitest spec that:
   - Builds one `TranscriptChunk` per fixture entry (`isFinal: true`, sentence-terminating punctuation), feeds them through `createSlidingWindow`.
   - Runs each emitted `Utterance` through `detectCandidate` (T-2.1).
   - For candidates, runs an **oracle Haiku classifier**: a `ClassifyFn` implementation that returns the fixture's gold-label verdict with seeded ε ≈ 5 % flip noise (so the test exercises Haiku's parser path, not a perfect oracle). Verdict scores match `parseHaikuVerdict`'s YES/NO mapping (0.9 / 0.1).
   - Wraps the oracle in `classifyWithSettingsGate` (T-2.9) using a `createSettingsStore({ storage: Map-backed })` instance with default cutoff (0.7) and Haiku enabled.
   - Cost guard: `createCostGuard({ thresholdUsdPerHour: 1.0, minElapsedMsForProjection: 60_000 })`. Threshold is intentionally raised for the fixture since the oracle-Haiku usage stub mints synthetic 50-input/20-output tokens per call → projected $/h on a chatty 30-min run can cross the production 0.5 $/h default; raising it keeps the fixture pipeline from auto-pausing mid-run. The pause-firing path is already AC-tested in T-2.7.
   - On admit, runs the candidate through `createDedupWindow({ windowMs: 60_000 })`.
   - Final admits feed `createQuestionQueue({ maxDepth: 5 })` + `createQueueWorker(...)` driving an **oracle `askClaude`** stub: returns a deterministic answer per question (uses the fixture's `useful: boolean` to script "useful" or "vague" answer text + matching `usage` so cost accounting populates).
   - Drains queue to idle, then computes:
     - `catchRate` = (fixture questions whose `text` arrived as a `markAuto`-attached `Question` in the store) / (total fixture questions)
     - `usefulRate` = (markAuto questions whose oracle-answer text was the "useful" variant) / (admitted markAuto count)
     - `firstTokenLatencyP95` = sorted `metric.firstTokenLatencyMs` p95 across all worker items (under fake clock).
     - `endToEndLatencyP95` = same shape on `endToEndLatencyMs`.
     - `costSnapshot` from the cost guard at end-of-meeting.
   - Asserts the two numeric AC: `catchRate ≥ 0.80`, `usefulRate ≥ 0.70`. Logs the metric table to console (visible on `bun run test --reporter verbose` for the reviewer).
3. **New artifact: `docs/tasks/phase-2/PHASE-BROWSER-TEST.md`** — 10-step golden-path manual host script the user runs once `ANTHROPIC_API_KEY` + Apple-Silicon hardware are available. Covers Phase-1 carry-forward (start/load context/manual-mark/save) plus the Phase-2 auto-detect trigger + cost-banner + settings persistence steps. Used as the wall-clock catch-rate / useful-rate verification hook (counterpart to the fixture-mode metric).
4. Self-review **`T-2.10-review.md`** with the metric table inline.

## Scope (out / deferred)

- **Live 30-min meeting recording.** The loop sandbox has neither `ANTHROPIC_API_KEY` nor Apple-Silicon-host MLX whisper; running the production pipeline against a real audio file would require both. The synthetic fixture is the sandbox-runnable equivalent and is **explicitly annotated `(fixture-mode)`** in the metric report; the live re-verify is the user's host pass via `PHASE-BROWSER-TEST.md`.
- **`PHASE-2-COMPLETE.md`** — that's the *next* loop step (12/12). T-2.10 emits the metric report; the sign-off doc consumes it. Keeping them in separate iterations preserves the "1 task = 1 commit" loop rule.
- **Embedding-similarity dedup.** Phase 2.x backlog (per T-2.4 doc + ARCH §5.2). Hash-only dedup is what the test exercises.
- **Multi-provider answers.** Phase 3 — out-of-scope for E2E.
- **Streaming UI render assertion.** T-2.6 already verifies the worker → `markAuto` path; T-2.8 already verifies the chip → scroll path with RTL. Re-rendering `<App />` with the full pipeline mounted would duplicate those assertions and add jsdom timing flake; the E2E here exercises the **logic** pipeline end-to-end, and `PHASE-BROWSER-TEST.md` is where the rendered UI passes its golden-path test on the live host.

## TDD Plan

A single `Phase2-E2E.test.ts` spec organized into thematic `describe` blocks. The fixture is loaded once; each block re-builds the pipeline so they don't share mutable state.

### `describe("T-2.10 fixture sanity")`
- F-1: fixture has ≥ 12 questions and ≥ 30 non-questions (sanity bound on fixture density).
- F-2: total fixture wall-clock span `endTsMs(last) - tsMs(first) ≥ 1 800 000` ms (30 min).
- F-3: every entry's `endTsMs > tsMs`; gap to next ≥ silence threshold so sliding-window emits 1:1.
- F-4: fixture seeds at least 1 dedup duplicate pair (two questions sharing the same normalized text within 60 s).

### `describe("T-2.10 pipeline E2E (fixture-mode)")`
- E-1: drain runs to idle without throwing.
- E-2: catch-rate ≥ 0.80 (AC-1).
- E-3: useful-rate ≥ 0.70 (AC-2).
- E-4: first-token-latency p95 < 10 000 ms under fake-clock (AC-3).
- E-5: single-flight invariant `peakInFlight ≤ 1` (AC-4).
- E-6: cost snapshot non-zero + finite (AC-5).
- E-7: dedup admitted exactly once for the seeded duplicate (AC-6).
- E-8: settings-gate ran on every candidate (every utterance the heuristic admitted produced exactly one classify call when the gate is open + not paused).
- E-9: end-of-meeting flush emits any pending utterance (no silent drop on the tail).

### `describe("T-2.10 settings precedence carry-through")`
- S-1: with `haikuEnabled = false`, the Haiku oracle is never called; admit collapses to the heuristic-only output (catch-rate may differ but the test asserts the gate path, not the metric).
- S-2: with `costGuardPaused = true`, no oracle Haiku calls but settings-gate returns `skipped-paused`.

These two are smoke checks on the composer wiring carried over from T-2.9 — they don't alter the headline catch-rate / useful-rate metric numbers.

## Risk + Mitigation

| # | Risk | Probability | Impact | Mitigation |
|---:|---|:---:|:---:|---|
| R-1 | Synthetic fixture not representative of real meeting cadence — catch-rate / useful-rate look great in fixture, fall apart on real audio. | Medium | Medium | The fixture is annotated `(fixture-mode)` everywhere it appears in the metric report; live-recording verify is queued as a manual step in `PHASE-BROWSER-TEST.md`. The PRD personas + spike-memo §"Use cases" + the T-2.3 gold-label set inform the fixture content; we explicitly mix EN/VI, fast-paced QA bursts, and silence-padded statement runs to mimic real cadence variance. |
| R-2 | Fake-clock drift between worker `now()` injections + dedup-window `now()` injections produces lossy time math (e.g. queue enqueuedAt > worker firstTokenAt → negative latency). | Low | Low | Inject a single shared `clock = () => fakeNow` into every closure that takes a `now` injection (queue, worker, dedupWindow, costGuard). All clocks read from the same monotonic ramp. |
| R-3 | Oracle Haiku noise (5 % flip) is non-deterministic if it uses `Math.random()` → flaky CI. | Medium | Medium | Seed the noise off the utterance index (`(idx * 2654435761) >>> 0` mulberry-style) so the same fixture index always lands on the same flip decision. The test is fully deterministic across reruns. |
| R-4 | Dedup-window's `now()` based pruning collides with worker-side `now()` advance — duplicate within window admitted twice because the window pruned eagerly. | Low | Medium | The fixture's seeded duplicate uses an `endTsMs` gap < 60 s; we feed `dedupWindow.admit(text, ts)` with the explicit utterance `endTsMs` rather than letting it consult the clock, so the window math is driven by fixture timestamps alone. |
| R-5 | Catch-rate AC fails by a small margin on the chosen fixture (e.g. 0.78) → loop-blocker even though the wider plumbing is correct. | Low | High | The fixture is calibrated against the **already-verified** T-2.1 (precision 0.926, recall 1.000), T-2.3 (96 % gold-label agreement), T-2.4 (1/3 admit on duplicates) numbers. Headroom analysis: 15 GT questions × 0.95 heuristic-recall × 0.95 Haiku-agreement = 13.5 expected admits — well above the 12 admits needed for 0.80 catch-rate at 15 GT. The fixture is intentionally biased toward strong-signal questions so AC clears with margin. |
