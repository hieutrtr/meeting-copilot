### Catch-rate reconciliation

19 GT questions / 51 utterances (37.3 % question density).

- 19 → heuristic candidates (recall = 1.000 on this fixture; 2 false-positive non-Q candidates carry forward)
- 21 → Haiku oracle classifications. At seed `0xa5a5_a5a5` the noise flipped 0 entries (`< 0.05 * 21 = 1.05` expected; 0 observed is in-distribution).
- 19 YES verdicts (Q's only — both FPs got NO).
- 1 dedup-rejected (the seeded "What's the deadline for the launch?" pair).
- **18 queue admits = 18 caught GT questions** → catch rate = 18 / 19 = **0.947**.

The 1 missed GT question is the duplicate of an already-admitted question — the user would still see exactly one answer, which is the user-visible behavior we want. Counting it as "missed" against catch-rate is the conservative reading of the plan's metric definition.

### Useful-rate reconciliation

18 detected questions:
- 16 are GT questions with `useful: true` → contributes 16/18 = 0.889
- 2 are GT questions with `useful: false` (the 2 trailing "rhetorical wrap-up" Qs at fixture indices 47 + 50) → counted as not-useful per gold label
- 0 are false positives (the 2 heuristic FPs were correctly NO'd by the Haiku oracle and never admitted)

useful rate = 16 / 18 = **0.889**.

### Latency reconciliation

Under the fake clock the oracle ask advances `fakeNow += 1500` before the first delta yield. The worker reads `enqueuedAt = item.enqueuedAt` from the queue (set via the **shared** `clock` injection) and `firstTokenAt = clock()` on first delta — so `firstTokenLatencyMs = 1500` for every item. p95 = 1500 ms.

End-to-end latency adds two more 200 ms delta gaps + queue.complete = 1900 ms p95. Both well under the 10 s plan AC.

The live-host first-token latency is what `PHASE-BROWSER-TEST.md` step 4 measures; the fixture mode is a **logic** check on the latency-recording plumbing, not a real-clock measurement.

### Cost reconciliation

- Haiku: 21 calls × $0.000109 ≈ $0.002289 (4 input + 50 cache-read + 20 output tokens per call)
- Sonnet: 18 calls × $0.003330 ≈ $0.059940 (10 input + 8000 cache-read + 60 output tokens per call)
- Total: $0.062229
- Projected $/h on a 31.76 min meeting: $0.117438

Well under the **$0.50/h Phase-2 budget**. The cost-guard threshold for the fixture run is set to $1.0/h to avoid auto-pausing mid-run; the production default of $0.50/h is verified separately in T-2.7's AC suite (32 / 32 cost-guard tests; threshold latched alert fires at $0.51/h projection).
