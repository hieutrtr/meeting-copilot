### Per-call cost projection (for downstream sanity)

The cost guard itself runs entirely in-process, no SDK calls — **$0.000000 / call**. Its overhead per `recordHaikuUsage` / `recordSonnetUsage` is:

1. `computeHaikuCostUsd` / `computeCostUsd` — 1 multiply + 4 divides + 1 add (sub-microsecond).
2. `addUsage` — 6 numeric adds.
3. `maybeFireAlert` (only on first crossing) — 2 comparisons + at most 1 callback.
4. `buildSnapshot` — 1 object spread (defensive copy).

Worst-case worker overhead per record < 100 µs. The cost-guard call frequency is bounded by Haiku candidate rate (≤ 10/min on a talky meeting) + Sonnet answer rate (≤ 1 in-flight at a time, ≤ 60/h). Total < 1 ms/min on the cost-guard hop — negligible vs. ARCH §12 latency budget.

### Pricing constant verification

The cost guard's math chains directly through `pricing.ts` helpers. Test `CG-Sanity: counter cost equals pricing helper sum exactly` cross-checks Haiku + Sonnet sums to 12 decimal places against a separate `.map(computeXxxCostUsd).reduce((a,b)=>a+b)` invocation. A drift in the constants (Anthropic re-prices Haiku / Sonnet) would surface in the existing `pricing.test.ts` (T-1.10 + T-2.3 extension) before any test in this suite — those tests pin the per-MTok rates by name. T-2.7 imports the helpers but does not redefine the constants, so the audit trail is exactly one place to update if Anthropic re-prices.

## Hand-off to T-2.8 (UX wiring)

T-2.8 wires the cost guard into the AnswerPanel header + a banner. Wiring sketch (verbatim from spec):

```ts
const costGuard = useMemo(
  () => createCostGuard({
    onAlert: (snap) => {
      uiBus.emit("cost-guard-alert", snap);
    },
  }),
  [],
);

// Detector pipeline (T-2.3 caller):
const result = await guardedClassifyWithHaiku(text, classifyWithHaiku, costGuard);
if (result.status === "skipped-paused") return null;

// Worker:
const worker = createQueueWorker({
  // ... existing wiring ...
  onItemDone: (_item, result) => {
    costGuard.recordSonnetUsage(result.usage);
  },
});
```

The cost guard does NOT expose a `subscribe`; T-2.8 either polls `snapshot()` on a 1 s interval or threads the snapshot through the `onAlert` event bus (the latter is cheaper since the only state-change UI cares about is the threshold crossing — the live counter can be event-driven by re-snapping on every `record*Usage` call).

## Hand-off to T-2.9 (Settings — pause toggle)

T-2.9 binds a checkbox to `costGuard.setPaused()` and persists the flag in `localStorage`:

```ts
const [paused, setPausedLocal] = useLocalStorage("haiku-paused", false);
useEffect(() => {
  costGuard.setPaused(paused);
}, [paused]);
```

The Haiku-disable toggle in T-2.9 is a separate setting from the cost-guard pause: T-2.9's "disable Haiku entirely" short-circuits the detector pipeline upstream of the guard (heuristic-only mode = $0 filter cost). The cost-guard pause is the *post-alert* brake. The two settings interact OR-style.
