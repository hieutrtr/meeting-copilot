## Scope

Pure, side-effect-free *factory* (closure state, no module-level mutable state — same shape as the sliding-window assembler T-2.2 so two meetings can hold independent dedup windows simultaneously):

```ts
function normalizeQuestion(text: string): string;
function hashQuestion(text: string): string;

interface DedupAdmitResult {
  admitted: boolean;
  hash: string;
  reason?: "duplicate";        // populated when admitted === false
  matchedAt?: number;          // ts of the prior admit that blocked this one
  matchedHash?: string;        // === hash on duplicate
}

interface DedupWindowOptions {
  windowMs?: number;           // default 60_000 (per plan; ARCH says 30_000)
  now?: () => number;          // injectable clock for tests; defaults to Date.now
}

interface DedupWindow {
  admit(text: string, ts?: number): DedupAdmitResult;
  size(): number;              // pruned size — entries older than windowMs evicted
  reset(): void;               // hard clear (e.g. between meetings)
}

function createDedupWindow(opts?: DedupWindowOptions): DedupWindow;
```

### Normalization

`normalizeQuestion(text)` is the canonicalization step before hashing:

1. **Unicode NFKC** — collapses fullwidth ASCII (`？` → `?`), Vietnamese precomposed glyphs, etc.
2. **Lowercase** — `toLocaleLowerCase()` (handles VI diacritics consistently).
3. **Strip leading filler** — common spoken hedges that vary across repetitions: `^(um|uh|er|ah|so|well|actually|basically|like|you know|i mean|à|ờ|ừ|thì|thế|kiểu|nói chung|thật ra|thực ra)[,\s]+` (matched repeatedly). This catches "um, what's the deadline?" vs "what's the deadline?".
4. **Strip punctuation** — drops `?!.,;:…—–-"'""''«»()[]{}` and CJK equivalents. Keeps letters, digits, and inter-word whitespace.
5. **Collapse whitespace** — `\s+` → single space.
6. **Trim** — leading/trailing whitespace.

The output is the canonical form fed to `hashQuestion`. Examples:

- `"What's the deadline?"` → `"what's the deadline"` → after step 4 → `"whats the deadline"`
- `"  WHAT'S THE DEADLINE?? "` → `"whats the deadline"`
- `"Um, what's the deadline?"` → `"whats the deadline"`
- `"What's the deadline."` → `"whats the deadline"` (declarative-with-typo handled identically — known soft mismatch with intent, but acceptable given Stage 2 already gated)

### Hash

`hashQuestion(text)` runs `normalizeQuestion` then a deterministic 64-bit FNV-1a (32 hex chars) over the canonicalized bytes. Pure JS, no `crypto` import (keeps the module Tauri / Rust-port-friendly and avoids `crypto.subtle` async surface).

### Window semantics

- Each `admit(text, ts)` call:
  1. Compute `hash`.
  2. Prune: drop entries with `recordedAt < ts - windowMs`.
  3. Look up `hash` in the live map.
  4. If present → reject `{ admitted: false, hash, reason: "duplicate", matchedAt, matchedHash }`. **Do NOT update the timestamp** — sliding window resets only when the entry expires; otherwise a stuttering speaker could keep the entry alive forever and never get the question through after the original window expires.
  5. If absent → insert `{ hash, recordedAt: ts }`, return `{ admitted: true, hash }`.
- `ts` defaults to `opts.now()` (injected for tests); if both are absent, `Date.now()`. The caller (queue) typically passes `Utterance.startTs` so dedup is meeting-clock-aligned, not wall-clock-aligned.
- `size()` returns the post-prune count (callers can sanity-check the live window).
- `reset()` clears the entire map (T-2.5 calls this on meeting end / meeting switch).

## Acceptance Criteria

Verbatim from plan (T-2.4):

> Dedup window (60s, embedding similarity > 0.85). AC: cùng câu hỏi 3× trong 30s → 1 admit.

Translated to numeric AC:

1. **Repeat-rejection AC GATE** — `admit("what's the deadline?", t)` × 3 with `t = 0, t = 10_000, t = 25_000` (all within the 60 s window) → **exactly 1 admit, 2 rejections**. Rejections carry `reason: "duplicate"` and `matchedAt === 0`.
2. **Window expiry** — with `windowMs = 60_000`, admit at `t = 0`, then admit again at `t = 60_001` → **both admitted**. The 60 s boundary uses strict `<` so `t = 60_000` exactly is still considered duplicate (deterministic edge).
3. **Normalization equivalence** — `"What's the deadline?"`, `"  WHAT'S THE DEADLINE?? "`, `"Um, what's the deadline?"`, `"what's the deadline."` all hash to the same canonical key → only the first admits within the window.
4. **Paraphrase known-limitation** — `"what's the deadline?"` and `"when is the deadline?"` produce **distinct hashes** → both admitted within the window. Test asserts both admit and includes a comment marking this as documented out-of-scope behavior (embedding similarity is Phase 2.x backlog).
5. **Hash determinism** — `hashQuestion(x)` returns the same value across two calls; case-only / punctuation-only differences collide; hex output is exactly 16 chars (64-bit FNV-1a).
6. **Independent windows** — two `createDedupWindow()` instances do not share state. A duplicate in window A does not affect admits in window B.
7. **Size + reset** — after 3 distinct admits inside the window, `size() === 3`. After `reset()`, `size() === 0` and previously-rejected hashes admit again.
8. **Vietnamese support** — `"Deadline là khi nào?"` and `"deadline là khi nào"` (no punctuation, lowercased manually) collide. Diacritic-stripped variant `"deadline la khi nao"` is treated as a *different* question (stripping diacritics is the upstream STT's responsibility, not the dedup layer's — we don't want to over-merge).
9. **Empty / whitespace input** — `admit("")` and `admit("   ")` both normalize to `""`; both produce a stable hash; first call admits, second call within window rejects. (Caller is expected to filter empties upstream, but the dedup layer must not crash.)

| **Window-boundary off-by-one** — `<` vs `≤` ambiguity around `windowMs` boundary. | Low | Low | Spec pins strict `<` (entry expires when `recordedAt < now - windowMs`); test covers `t = 60_000` (still dup) and `t = 60_001` (fresh admit). |

## Out of Scope (explicitly deferred)

- **Embedding cosine similarity** (ARCH §5.2 v1 ideal) — requires `nomic-embed-text` local model; out of scope for v0.2. Filed as Phase 2.x backlog. Hash-only is the v0.2 surrogate; the AC test for paraphrase explicitly admits both as documentation of the known limitation.
- **Cross-meeting dedup** — `reset()` is meeting-scoped; questions repeated across meetings are not deduped. Intentional.
- **Question intent grouping** (e.g. "what's the deadline" + "when's it due" → same intent) — same dependency on embeddings; deferred.
- **Persistence of dedup map** — meetings restart with a fresh window. SQLite checkpointing of the dedup state is unnecessary; if a meeting crashes mid-stream, the worst case is one extra answer fires for a recently-asked question on resume. Acceptable.
- **Configurable filler list at runtime** — the filler enum is hardcoded. T-2.9 settings exposes the dedup *window* duration (slider) but not the filler list (out of scope; would require a custom-words UI we don't ship in v0.2).

## Hand-off to T-2.5 / T-2.7 / T-2.9

- **T-2.5 queue** — calls `dedupAdmit(text, ts)` after the Haiku threshold gate. Rejected results are logged with `reason: "duplicate"` and matched-hash for telemetry. T-2.5 owns lifetime: instantiates one `DedupWindow` per meeting, calls `reset()` on meeting end / `meetingStore.startNew()`.
- **T-2.7 cost guard** — N/A; dedup is free (pure JS, zero LLM calls). Acts as a cost reducer for Sonnet (no answer fires on duplicates) but the cost guard tracks Haiku spend independently.
- **T-2.9 settings** — exposes `dedupWindowMs` slider (default 60_000, range 30_000 – 120_000) so users can tune sensitivity. The slider value flows into `createDedupWindow({ windowMs })` at meeting start.

Integration sketch (queue worker, T-2.5):

```ts
const dedup = createDedupWindow({ windowMs: settings.dedupWindowMs });

async function onUtterance(utt: Utterance) {
  const heuristic = detectCandidate(utt.text);            // T-2.1
  if (!heuristic.isCandidate) return;
  const verdict = await classifyWithHaiku(utt.text);      // T-2.3
  if (verdict.confidence < HAIKU_ADMIT_THRESHOLD) return;
  const dedupResult = dedup.admit(utt.text, utt.startTs); // T-2.4 (this task)
  if (!dedupResult.admitted) {
    log("dedup-rejected", { hash: dedupResult.hash, matchedAt: dedupResult.matchedAt });
    return;
  }
  queue.push({ utterance: utt, verdict, dedupHash: dedupResult.hash }); // T-2.5
}
```

The hand-off is stable: T-2.5 needs only `createDedupWindow` + the `admit()` signature.
