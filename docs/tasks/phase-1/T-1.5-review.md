### Static-trace verification of the 17 tests

All test logic was math-checked by hand before commit:

- **`fake_stt_segment_duration_matches_chunk_samples`**: 8000 samples ÷ 16 000 Hz = 0.5 s → ts 100 ms + 500 ms = 600 ms `end_ts_ms`. ✓
- **`fake_stt_segment_text_is_configurable`**: 16 000 samples ÷ 16 000 Hz = 1.0 s → ts 4 000 ms + 1 000 ms = 5 000 ms. ✓
- **`fake_stt_consumes_chunker_output`**: 80 000 samples / 32 000 samples-per-window = 2.5 windows → 2 full windows + 16 000 residual; chunker stamps ts_ms 0, 2 000. ✓
- **`build_segments_offsets_by_chunk_ts_and_filters_empty`**: 3 segments [0.0–0.5, 0.5–1.0 (whitespace), 1.0–1.5], chunk ts 4 000 ms → output segs [4000–4500 "hello", 5000–5500 "world"], whitespace seg filtered. Confidence for seg 1: `1.0 - 0.1 = 0.9` ✓
- **`build_segments_falls_back_to_full_text_when_segments_empty`**: 32 000 samples @ 16 kHz = 2 000 ms → start 100 + 2000 = 2 100 `end_ts_ms`. ✓
- **`parse_script_output_accepts_ok_payload`** + **`…_rejects_empty_stdout`**: Decode error path covered separately from spawn path (decode failures shouldn't be re-raised as Subprocess errors). ✓
- **`mlx_subprocess_writes_chunk_wav_with_correct_format`**: 16 000 f32 samples = 16 000 i16 samples; hound's `WavReader::duration()` reports frame count for mono = 16 000. ✓
- **`mlx_config_default_picks_python3_and_medium_model`**: doesn't mutate env (parallel-test-safe); asserts both branches (env-set / env-unset). ✓
- **`sttprovider_is_object_safe_and_send`**: `Box<dyn SttProvider>` compiles → object-safe. `std::thread::spawn(move || boxed.transcribe_chunk(...))` exercises the `Send` bound at the type system level. ✓
- **`mlx_subprocess_transcribes_short_utterance`** (integration): three soft-skip branches verified in code (no `mlx_whisper`, no `say`, no `ffmpeg`); only one path ends in real subprocess. Body is the textbook "say + ffmpeg → WavFileSource → SttProvider" pipeline that T-1.6 will run in the Tauri event loop. ✓
