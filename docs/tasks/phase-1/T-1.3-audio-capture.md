## Goal

Create the `crates/audio-capture` workspace member crate that provides the **first half of the audio→STT pipeline**: a pluggable `AudioSource` trait with two implementations:

1. **`WavFileSource`** — reads any 16-bit PCM WAV via `hound`, yields `PcmChunk { samples: Vec<f32>, sample_rate, ts_ms }` items in configurable chunk sizes. This is the **fixture-driven test target** — every later capture/STT/chunker test feeds a known WAV through this source instead of the mic, so TDD stays deterministic and CI-friendly.
2. **`CpalMicSource`** — opens the macOS default input device via `cpal`, runs the audio callback on its real-time thread, forwards 32-bit float PCM samples to a `mpsc::Receiver` consumed by `next_chunk()`. This is the **production mic path**; runtime correctness is **hardware-verify pending** because (a) `cargo` is not on this loop's sandbox host (per INDEX §"Inputs Carried Forward From Phase 0" blocked-action #3), and (b) the BlackHole driver / Aggregate Input Device aren't installed yet (blocked-action #1) which is the only path for system-audio capture per ARCH §2.1.

Both impls satisfy the same `trait AudioSource` so T-1.4's chunker, T-1.5's STT adapter, and T-1.6's event bridge can be written **once** against `Box<dyn AudioSource>` and tested against the WAV fixture without ever opening a real device.

### Why split capture from chunker (T-1.3 vs T-1.4)?

ARCH §2.1 reads "2 stream → resample về 16kHz → đẩy vào ring buffer → flush mỗi 100ms thành chunks 100ms". The "ring buffer + 100ms flush" half is T-1.4. T-1.3 owns only **source → bytes/samples**; resampling and the fixed 2-s sliding window are T-1.4's job. Keeping them separate means:

- T-1.3 tests can use any sample rate (the WAV fixture's native rate) without coupling assertions to "must be 16 kHz at this layer".
- T-1.4 unit tests can drive the chunker with a synthetic in-memory PCM stream (bypassing both the WAV reader and cpal) — the chunker doesn't need to know what produced the samples.
- The cpal-only failure modes (device-not-found, permission-denied) stay isolated to one module.

### Mic-only this iteration

INDEX §"Loop renumbering" T-1.3 row reads: "system-audio path stays a `cfg(feature = "blackhole")` stub". This iteration ships **microphone source only**; the system-audio Aggregate Device path (BlackHole loopback) is documented as a follow-up — code path is identical (cpal opens whichever input device the user names), only the device-selection helper changes. The Aggregate Device case is gated behind blocked-action #1.

### Test fixture strategy

No binary WAV files committed. Fixtures are **generated in-memory** via `hound::WavWriter` writing to a `Cursor<Vec<u8>>`, then re-opened with `hound::WavReader::new(Cursor::new(bytes))`. This keeps the repo lean, makes fixture changes a code edit (not a binary checkin), and isolates assertions from filesystem state.

A small `test_util` module (cfg(test) only) exposes `make_wav_bytes(samples: &[i16], sample_rate: u32) -> Vec<u8>` consumed by all six test cases.

### Test cases (matrix)

| # | Test | Fixture | Asserts |
|---|---|---|---|
| 1 | `wav_source_metadata_matches_header` | 16-sample sine, 16 kHz, mono | `sample_rate()==16000`, `channels()==1` |
| 2 | `wav_source_emits_all_samples_concatenated` | 1000-sample ramp, 16 kHz, mono, chunk=128 | concat of all chunks' samples == ramp normalized; total len == 1000 |
| 3 | `wav_source_chunks_at_configured_size` | 1000-sample ramp, chunk=300 | first 3 chunks have 300 samples; last chunk has 100 |
| 4 | `wav_source_timestamps_monotonic` | 800-sample ramp, 16 kHz, chunk=200 | ts_ms = [0, 12, 25, 37] (= chunk_idx * 200 * 1000 / 16000, integer div) |
| 5 | `wav_source_returns_none_after_exhaustion` | 100-sample ramp, chunk=128 | first call → Some(100 samples); second → None; third → None (idempotent) |
| 6 | `audio_source_trait_is_object_safe_and_send` | (none — type-level) | `let _: Box<dyn AudioSource + Send> = Box::new(WavFileSource::…);` compiles |

## Risk + Mitigation

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| `cpal` 0.15 fails to link without Xcode CLI tools | Low | Medium | T-0.8 Phase 0 sign-off requires `xcode-select --install`; this is already done. If it regresses, fallback is to gate `mic.rs` behind `#[cfg(feature = "mic")]` and disable feature in CI. |
| `hound` doesn't accept arbitrary WAV variants (e.g. 24-bit, IEEE float) | Medium | Low | Constrain `WavFileSource` to **16-bit PCM** via explicit assertion on `WavSpec::sample_format == SampleFormat::Int && bits_per_sample == 16`. Future PRs add 32-bit float support when STT adapter outputs WAV in that format (T-1.5 may not need it). Error variant `AudioError::UnsupportedWavFormat` makes the failure mode explicit. |
| cpal callback runs on real-time audio thread; blocking allocations there cause audio glitches | Low | Medium | Use `std::sync::mpsc::sync_channel(64)` (bounded). On full, callback drops the chunk + bumps a metric counter (no panic, no block). T-1.4 introduces a proper lock-free ring buffer; T-1.3 ships the simpler bounded-mpsc variant. Drop strategy is documented in `mic.rs`. |
| cpal `Stream` is `!Send` on macOS | Medium | Medium | Build the stream **inside** the audio-thread closure spawned via `std::thread::spawn`. Stream lives the entire thread lifetime; thread is joined on drop. The `CpalMicSource` struct holds only the receiver + a shutdown signal `Sender<()>`, both of which are `Send + Sync`. |
| WAV header sample rate 16 kHz vs cpal default 44.1/48 kHz drift in tests | Low | Low | Tests assert on the WAV's reported rate, not a hardcoded 16 kHz. Resampling is T-1.4's job. |
| Float normalization: `i16 / 32767` vs `i16 / 32768` debate | Low | Low | Use `i16::MAX as f32 = 32767.0`; clamp result to `[-1.0, 1.0]` (only matters for sample value `i16::MIN = -32768` whose normalized form would be `-1.0000305…`; we clamp to `-1.0`). Document in `source.rs` rustdoc. |
| Fixture generation in tests adds wallclock noise (file IO) | Low | Low | All fixtures use `Cursor<Vec<u8>>` — pure in-memory, sub-millisecond. No tempfiles. |
| Adding `audio-capture` to workspace breaks Tauri build (target/ rerouted, etc.) | Low | Low | Phase 0 T-0.8 + T-1.2 already validated workspace-on-Tauri. New member crates are additive; `cargo build --workspace` is the canonical gate (hardware-verify pending). |
