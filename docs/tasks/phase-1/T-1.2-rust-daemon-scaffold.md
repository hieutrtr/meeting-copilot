## Goal

Create the first Cargo workspace member crate — `crates/helper-daemon` — with the smallest possible surface that proves the **scaffold is alive** and that **Tauri can call into it**:

1. `helper-daemon` crate exposes `ping() -> "pong"` as the canonical liveness function.
2. `src-tauri` depends on `helper-daemon`, registers `#[tauri::command] async fn ping()` that delegates to the crate, and exposes it through `invoke_handler`.
3. The Phase 0 `greet` smoke command stays in place untouched (T-0.8 sign-off artifact); `ping` lives next to it as the new Phase 1 entry point. Removal of `greet` is a Phase 1.x cleanup, not this task.
4. Cargo workspace plumbing (deferred from T-1.1) is wired here: a top-level `Cargo.toml` with `[workspace]` members covering `src-tauri` and `crates/helper-daemon`.

The `meeting_start` / `meeting_stop` / `meeting_status` stubs originally listed in INDEX T-1.2 are **scoped to T-1.9** (Start/Stop controls) where they actually drive UI state. Doing them here would couple this scaffold to a meeting-state machine that doesn't exist yet. The user's loop step explicitly narrows this iteration to a `ping` smoke — keep the surface to one verifiable command and let T-1.9 add the real controls on top of the working bridge.

| 2 | `src-tauri/src/lib.rs` `mod tests` | `cargo test` | `ping_command_returns_pong()` — the Tauri command function (when called as a plain async fn from a test, sans IPC layer) returns `"pong"`. |

| 4 | `src/ping.test.ts` | Vitest + mocked `@tauri-apps/api/core` | `await invoke<string>('ping')` resolves to `"pong"`; mock is configured so the test fails if the command name string changes. |

### RED → GREEN cycle

- **RED A** — `cargo test` (workspace not yet declared) → cargo errors `current package believes it's in a workspace when it's not`. **GREEN A** — add root `Cargo.toml` `[workspace]`.
- **RED B** — `cargo test --workspace` (helper-daemon crate empty / missing) → fails compilation on the crate's own `tests::ping_returns_pong`. **GREEN B** — add `pub fn ping() -> &'static str { "pong" }` to `crates/helper-daemon/src/lib.rs`.
- **RED C** — `cargo test -p meeting_copilot_lib` (command not yet registered, test refers to undefined symbol `ping`) → compile error. **GREEN C** — add the `#[tauri::command]` and call it from the test using its plain-fn form (Tauri's command attribute leaves the underlying fn callable directly in tests).
- **RED D** — `bun test` (no `src/ping.test.ts` yet, or assertion fails because mock is wrong) → vitest red. **GREEN D** — add the mocked-`invoke` test.
- **REFACTOR** — verify both daemon-test and command-test return the same string; if drift, make the command call `helper_daemon::ping()` directly (no `.to_string()` until needed). Tests stay green.

## Risk + Mitigation

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Cargo workspace declaration breaks `tauri-cli` (looks for a non-virtual root) | Medium | Medium | Use a **virtual workspace** (root `Cargo.toml` has `[workspace]` only, no `[package]`) — `tauri-cli` resolves the `src-tauri` member by path, same as the upstream Tauri 2 monorepo template (`https://github.com/tauri-apps/tauri/blob/dev/Cargo.toml` has the same shape). If it breaks on hardware, fallback is to keep `src-tauri/Cargo.toml` as its own root and use a `[workspace]` block inside it that points at `../crates/*`. The fallback is documented in `T-1.2-review.md` if needed. |
| `#[tauri::command]` macro hides the underlying fn signature, making it un-callable from `mod tests` | Low | Low | The macro generates a wrapper but leaves the original async fn intact — the test calls the inner async fn (`futures::executor::block_on` or `tokio_test::block_on` if needed). For a fn that returns a literal it's effectively `async fn` → `tokio::runtime::Runtime::new().unwrap().block_on(ping())`. Avoid pulling tokio if `tauri` already gives us a runtime via dev-dep transitive — measure on hardware and downgrade to a sync fn if needed (which Tauri also accepts for `#[tauri::command]`). |
| Adding the workspace silently reroutes `src-tauri/target/` to a workspace `target/`, breaking `.gitignore` | Low | Low | `.gitignore` already lists both `target/` and `src-tauri/target/`. No change needed. |
| `helper-daemon` crate name collides with the namespaced `helper_daemon` Rust module name | Low | Low | Cargo translates `-` → `_` in identifiers; `helper-daemon` (Cargo) ↔ `helper_daemon` (Rust) is the canonical pattern (e.g. `serde-json` ↔ `serde_json`). Crate name is stable. |
| Vitest mock leaks to other tests (global module mock) | Low | Low | Use `vi.mock('@tauri-apps/api/core', () => …)` **inside** `src/ping.test.ts`; vitest scopes mocks per-file by default. |
| `bun test` picks up the new `src/*.test.ts` glob but fails because the existing vitest config hasn't been touched | Low | Low | `vitest.config.ts` already includes `src/**/*.test.{ts,tsx}` (T-1.1 work) — confirmed by reading the file before implementing. |

## Scope Guardrails (what this task does NOT do)

- ❌ `meeting_start` / `meeting_stop` / `meeting_status` Tauri commands — those land in T-1.9 where the meeting state machine actually exists. Adding them here would force placeholder state types that get rewritten in T-1.9.
- ❌ Audio capture (cpal) — T-1.3.
- ❌ Tauri event emission (`emit_all('transcript:chunk')`) — T-1.6.
- ❌ Real RPC (Unix socket / stdio framing per ARCH §8.2) — daemon stays in-process (linked as a Rust crate). Out-of-process RPC moves to a Phase 1.x decoupling task only if startup-time profiling shows the daemon needs lifecycle independence from the Tauri webview.
- ❌ Removing the Phase 0 `greet` command — keeps the smoke test from T-0.8 alive as a regression baseline.
