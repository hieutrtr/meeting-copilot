### Static-trace verification of the 6 Rust tests

- **`recorder_sink_captures_emitted_events`** — `RecorderSink::default()` initialises both `Mutex<Vec<…>>`s as empty; `emit_transcript_chunk(&ev)` clones into `transcripts`. `transcripts()` snapshot returns `vec![ev.clone()]`. `states()` empty. ✓
- **`event_bridge_pumps_chunker_through_stt_to_sink`** — 80 000 samples @ 16 kHz pushed at ts_ms=1; T-1.4 chunker (canonical 16 kHz / 32 000 samples-per-window) drains 2 windows. The chunker sets `ts_ms` per window starting at the first push offset's relative position — per T-1.4 review the first chunk's `ts_ms = 0`, second `= 2_000`. `FakeStt::new("hello").transcribe_chunk(&chunk)` returns 1 segment; `start_ts_ms = chunk.ts_ms`, `end_ts_ms = chunk.ts_ms + 2_000` (32 000 samples / 16 000 Hz = 2 000 ms). Bridge emits 2 events with ids `m1-0`, `m1-1`. ✓
- **`event_bridge_increments_chunk_idx_across_pump_calls`** — Two `pump_one` calls × 2 windows each = 4 events, ids `m1-0`..`m1-3`. `chunk_idx` is `&mut self`-stored, not reset per call. ✓
- **`event_bridge_serialises_to_canonical_json`** — Hand-built event matches the fixture literal byte-for-byte after `serde(rename_all = "camelCase")`: `start_ts_ms` field name → wait, the struct field is `start_ts: u64`, not `start_ts_ms` — I deliberately chose `start_ts` to match `shared/types.ts:TranscriptChunk.startTs` (camelCase output: `startTs`). The `_ms` suffix lives in the Rust `SttSegment` (`start_ts_ms`); the bridge translates `seg.start_ts_ms → event.start_ts` (no rename in the field name itself, just in the JSON). `serde_json::to_value(&ev)` produces a `Value::Object` with keys `id, meetingId, text, startTs, endTs, isFinal, confidence` (speaker omitted via `skip_serializing_if`). `from_str(SAMPLE_TRANSCRIPT_JSON)` produces the same. `Value::PartialEq` compares by structure → equal. ✓
- **`event_bridge_emits_state_transitions`** — `emit_state(&sink, MeetingStatus::Active, 1234)` → `MeetingStateEvent { meeting_id: "m1", status: "active", at_ts: 1234 }`. Two calls land in `recorder.states()`; `transcripts()` empty. ✓
- **`meeting_status_display_matches_ts_contract`** — `Display` impl literal-matches `"idle"|"active"|"ended"`. The TS union (`shared/types.ts:MeetingStatus`) is the same three strings. If anyone changes one side, this test (Rust) or the TS compiler (frontend) flags it. ✓

### Static-trace verification of the 1 src-tauri test

- **`tauri_event_sink_implements_event_sink`** — Compiles iff `TauriEventSink: helper_daemon::EventSink`. The impl in `src-tauri/src/lib.rs` requires `&self`-method conformance + `Send + Sync` (since `EventSink: Send + Sync`). `AppHandle` is `Send + Sync + Clone` per Tauri 2 docs → `TauriEventSink { app: AppHandle }` inherits both. The React hook's `listen()` is non-blocking; chunk delivery happens via Tauri's IPC channel (cross-thread message passing, no main-thread blocking).

### Cross-cutting Phase 1 concerns covered

1. **Schema parity guard** — both sides reference `shared/fixtures/transcript_chunk.sample.json`. Rust verifies `to_value(&ev) == from_str(fixture)`; TS verifies the parsed fixture deep-equals the literal mirror. Drift on either side fails on the next run.
2. **Future-proofing for out-of-process daemon** — `EventSink` is the seam Phase 1.x's WebSocket / Unix-socket sink swaps in. The bridge code itself never sees `AppHandle`; the only Tauri-aware code is the 30-line `TauriEventSink` adapter in src-tauri.
3. **Pluggable provider parity** — `pump_one` takes `&mut dyn SttProvider`; works equally with `FakeStt`, `MlxWhisperSubprocess`, and (Phase 3) `DeepgramStt` / `ElevenLabsStt`. No bridge code changes when a new provider lands.
4. **Sequential id ordering** — `chunk_idx` monotonic across `pump_one` calls means downstream consumers (T-1.7 virtualised list, T-1.12 SQLite write-ahead) get a stable insertion order without needing a UUID lib in this iteration.
5. **MeetingStatus enum vs string union** — the Rust enum is the single source of truth for transitions; the JSON contract uses lowercase strings via `Display`. T-1.9 will model the actual state machine (`Idle → Active → Ended`); T-1.6 ships only the type + the wire format.
