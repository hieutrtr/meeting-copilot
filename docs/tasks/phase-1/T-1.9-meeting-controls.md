## Acceptance Criteria (verbatim from INDEX)

> **T-1.9** — `Start Meeting` / `Stop Meeting` controls + `Mark as question` on chunk hover. **AC:** clicking Start → meeting state goes `listening`; clicking a chunk's "?" → emits `question:marked` with the chunk text; Stop → state `ended`. Dep: T-1.6, T-1.7, T-1.8.

The INDEX wording predates the `shared/types.ts:MeetingStatus` finalisation in T-1.6 (`"idle" | "active" | "ended"`). The `"listening"` token from the original raw plan was renamed to `"active"` to match the Rust `MeetingStatus::Active` enum already shipping in `crates/helper-daemon/src/bridge.rs`. Treat AC text as: clicking Start → state `active`.

The loop driver narrowed the per-chunk hover affordance to a single **"Mark Question"** action on the controls bar that captures the most recent N transcript chunks into a `Question` payload. Reason: the per-chunk hover button would require a Tauri-event-side round-trip + a `TranscriptView` re-render contract change (`onMarkChunk` prop). The controls-bar approach is the minimum-viable mark UX (matches PRD §6 wireframe) and unblocks T-1.10 (Claude Q&A) without touching T-1.7's contract. Per-chunk hover button is captured under §"Out-of-scope (deferred)" for Phase 1.x.

Decomposed:

- **AC-1** `useMeetingStore` zustand slice exposes `status: MeetingStatus`, `meetingId: string | null`, `startedAt: number | null`, `endedAt: number | null`, plus three actions:
  - `start(opts?: { meetingId?: string; now?: number })`: `idle` → `active`. Generates a `meetingId` if absent. Sets `startedAt = now()`. Rejects (no-op + error toast slot) if state is `active` or `ended`.
  - `stop(opts?: { now?: number })`: `active` → `ended`. Sets `endedAt = now()`. No-op if state is not `active`.
  - `reset()`: forces back to `idle` with all timestamps cleared (test affordance + lets the user start a follow-up meeting after `ended`).
- **AC-2** `useQuestionStore` zustand slice exposes `questions: Question[]`, `markFromChunks(chunks: TranscriptChunk[], opts?: { lastN?: number; meetingId?: string; now?: number; method?: QuestionMethod }): Question | null`, and `clear()`. The mark action:
  - Returns `null` if `chunks.length === 0`.
  - Defaults `lastN = 3`. Joins the last N chunks' text with a single space.
  - Builds a `Question` with `method = "manual"`, `status = "open"`, `detectedTs = chunks[last].endTs` (so persistence ordering by `detectedTs` lines up with the source transcript), `meetingId` from opts or the meeting store, `id = "q-<random>"` (random suffix from `crypto.randomUUID()` slice — deterministic-overridable in tests via `now`/`id` injection).
  - Pushes the new question to the front of the list (newest-first per PRD §7.2 sidebar).
- **AC-3** `MeetingControls` React component renders:
  - "Start meeting" button when `status === "idle"`. Disabled when `useContextStore().source === null` (per AC: a loaded context is the demo gate).
  - "Stop meeting" + "Mark question" buttons when `status === "active"`. Mark Question reads the live transcript chunks (passed in as a prop — kept off the global event listener to avoid coupling to `useTranscriptStream`) and pipes them into `useQuestionStore.markFromChunks`.
  - "Start new meeting" button when `status === "ended"` (calls `reset()` then `start()`).
  - A status badge (`<span data-testid="meeting-status">{status}</span>`) so tests can assert the transition.
- **AC-4** Wire `MeetingControls` into `App.tsx` next to `ContextLoader` + `TranscriptView`. The chunks prop comes from `useTranscriptStream()` so the user-visible flow is: Load context → Start → speak → Mark Question (captures last 3 chunks) → Stop.
- **AC-5** No new runtime production deps — zustand v5 (already added by T-1.8) handles both new slices. No `tauri-plugin-dialog` (deferred to Phase 1.x — text-input path from T-1.8 is the single-user demo path).
- **AC-6** State-machine invariants enforced as guards (no exceptions thrown — `start()` on a non-idle state is a silent no-op so a double-click can't crash the demo). The store is the single source of truth; the component is render-only.

Test fixtures (transcript chunks) re-use the `TranscriptChunk` shape from `shared/types.ts`. Both store and component tests construct them inline (3-5 chunks each) — no new fixture files needed for this task.

## Risk + Mitigation

| Risk | Likelihood | Mitigation |
|---|---|---|
| `meetingId` collision across rapid Start/Reset/Start cycles in dev hot-reload. | L | `crypto.randomUUID()` is monotonic-enough for a dev-only loop. T-1.12 persistence layer hardens this with a UNIQUE constraint. |
| zustand stores leak across test files (singleton import). | M | Each test file calls `useMeetingStore.setState(initialState)` / `useQuestionStore.setState({ questions: [] })` in a `beforeEach`. |
| Tauri-side IPC for Start/Stop is not yet wired (helper-daemon doesn't have a `start_meeting` / `stop_meeting` command). | M | Phase 1 keeps the meeting state machine **front-end only** for the MVP — the back-end pump (T-1.13 wires audio → chunker → STT → bridge) drives transcript events independently. Captured in §"Out-of-scope" — front-end Start ≠ back-end pipeline start until T-1.13. |
| Accidental double-Start from a user clicking the button twice fires two `start_meeting` IPC calls (once T-1.13 wires it). | L | AC-6's no-op guard catches it on the front-end. The Rust side will get one IPC; if T-1.13 surfaces a duplicate, the helper-daemon logs + ignores per ARCH §3.2. |
| Mark Question with `lastN > chunks.length` would slice out-of-bounds in JS. | L | `Array.prototype.slice(-N)` is bounds-safe — returns the whole array if `N > length`. Test QS-S2 includes an `lastN === chunks.length + 5` edge case. |
| Question text grows unbounded if user marks all chunks of a 30-min meeting. | L | MVP — not in AC. Phase 1.x trims to last ~512 chars before sending to Claude (T-1.10 prompt builder). |
| `reset()` after `ended` then `start()` reuses the same `meetingId` if not regenerated. | L | `start()` always generates a fresh `meetingId` unless the caller passes one explicitly. Covered by MS-S6 + a follow-up assertion. |
| Disabling "Start" until context loaded blocks the demo if the user wants to start without a PRD. | L | Documented in `PHASE-BROWSER-TEST.md` step 2 ("load any small TXT file first"). Phase 1.x can relax this with a "no context, ask anyway" toggle. |
