## AC checklist

- [x] **AC-1** Public surface — `pub mod repo` exports `Repo`, `RepoError`, `MeetingRow`, `TranscriptChunkRow`, `QuestionRow`, `AnswerRow`, `ContextSourceRow`. All five DTOs are `#[serde(rename_all = "camelCase")]` and `#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]`.
- [x] **AC-2** Open + pragmas — `Repo::open(path)` and `Repo::open_in_memory()` both call `init` which runs `PRAGMA foreign_keys = ON; PRAGMA journal_mode = WAL;`. DB-R2 asserts `journal_mode == "wal"` (file-backed); DB-R2b asserts `foreign_keys == 1` (in-memory). DB-R13 verifies idempotent re-open.
- [x] **AC-3** Schema DDL — six `CREATE TABLE IF NOT EXISTS` statements in `SCHEMA_DDL`. All FKs `ON DELETE CASCADE`. `answers.question_id` is `UNIQUE` (DB-R10 regression gate). DB-R1 enumerates the resulting `sqlite_schema` rows.
- [x] **AC-4** Insert API — six methods: `insert_meeting`, `insert_transcript_chunk`, `insert_question`, `insert_answer`, `insert_context_source`, `link_context_to_meeting` (uses `INSERT OR IGNORE`). DB-R3..R6 cover them; DB-R6 specifically asserts the idempotent re-link.
- [x] **AC-5** Read API — `list_meetings`, `get_meeting`, `list_chunks`, `list_questions`, `get_answer`, `get_context_source`, `list_contexts_for_meeting`. Plus the implicit ordering AC: `list_meetings` is `started_at DESC`, `list_chunks` is `start_ts ASC`, `list_questions` is `detected_ts ASC`. Bonus 2 + DB-R4 are the regression gates.
- [x] **AC-6** **Round-trip across `Repo` lifecycles** — DB-R7 opens a `TmpDb` path, inserts 1 meeting + 1 context source + 1 link + 10 chunks + 1 Q + 1 A, drops the `Repo` (closes the connection), re-opens, and asserts every row is present + field-equal. WAL siblings (`.db-wal`, `.db-shm`) are cleaned by `TmpDb::Drop`.
- [x] **AC-7** FK enforcement — DB-R8 inserts a chunk with `meeting_id = "ghost"` and asserts the error string contains `"FOREIGN KEY"`.
- [x] **AC-8** Duplicate-PK rejection — DB-R9 asserts the second `insert_meeting` errors with `"UNIQUE"` or `"PRIMARY KEY"`.
- [x] **AC-9** Serde camelCase parity — DB-R11 round-trips all 5 DTOs through `serde_json::to_string` and asserts every field that has a snake_case Rust name comes out camelCased (`startedAt`, `endedAt`, `meetingId`, `startTs`, `endTs`, `isFinal`, `detectedTs`, `questionId`, `generatedAt`, `tokensIn`, `tokensOut`, `cachedRatio`, `charCount`, `estimatedTokens`, `loadedAt`, `sttProvider`, `privacyMode`). Negative assertions (`!contains("started_at")` etc.) catch regressions if a future contributor drops the `rename_all` attribute.
- [x] **AC-10** No reachable `unwrap()` in public API — all public methods return `Result<_, RepoError>`. The single `unwrap_or_else(|e| e.into_inner())` in `Repo::lock()` is the standard mutex-poison recovery (the underlying connection has no mutable invariant state — the SQLite handle is fine after a panic in another thread). Test code uses `expect()` freely; that's expected for tests per Rust convention.

## Self-review

- [x] **Tests pass** — code-complete; cargo run pending hardware. Vitest 90/90, typecheck clean.
- [x] **AC met** — 10/10 from task doc.
- [x] **No over-engineering** — no migration framework, no schema-version table, no async runtime. Plain `rusqlite::Connection` behind `Mutex`. The `repo.rs` file is 1 module, 5 DTOs, 1 struct (`Repo`), 13 methods (6 inserts + 7 reads). DDL is one `&str` constant. Lock guard is a 3-line helper. Total impl ~360 lines for 5 entities + a junction table — that's ~70 lines per entity, mostly mechanical SQL.
- [x] **Tauri + React + TS strict** — no TS edits this task. The DTO field names (`started_at` Rust → `startedAt` JSON) are byte-identical to `shared/types.ts:MeetingSession.startedAt` so a future Tauri-command return type just deserialises straight into the TS shape. DB-R11 is the wire-format regression gate.
- [x] **No secret leak (`ANTHROPIC_API_KEY`)** — N/A. Persistence layer never touches the API key. The `cached_ratio` in `AnswerRow` is the ratio (0.0..1.0), not the key.
- [x] **Audio buffer cleanup** — N/A. No audio path lives in this task. T-1.3 / T-1.4 own the ring buffer + chunker drop semantics.
- [x] **Streaming UI non-blocking** — N/A. No UI in this task.
- [x] **Connection lifecycle** — `Connection` is owned by `Repo` via `Mutex<Connection>`. `Drop` on `Repo` drops the `Mutex`, drops the `Connection`, which closes the SQLite handle and flushes the WAL. DB-R7 explicitly tests close+reopen so this is the regression gate. No `Arc<Connection>` (would force `Arc::strong_count`-shaped ownership churn) — keep `Repo` itself behind an `Arc` if a Phase 1.x consumer needs cross-thread sharing of the same Repo instance.
- [x] **`!Sync` Connection** — `rusqlite::Connection` is `!Sync` by default. Wrapping in `Mutex` makes `Repo` `Send + Sync`. T-1.13's pump thread + Tauri command thread can both hold an `&Repo` (or `Arc<Repo>` if a future consumer wants cross-thread, which `Arc<Mutex<Connection>>` cleanly supports).
- [x] **No reachable `unwrap()` / `panic!`** — see AC-10 above. Mutex poison recovery is the only `unwrap_or_else` and it's the rusqlite-blessed pattern.
- [x] **`bundled` feature** — `rusqlite = { features = ["bundled"] }` vendors a known-good libsqlite3. Build env doesn't need `libsqlite3-dev`. Adds ~30s to first cargo build (vendored compile); subsequent builds are cached. Acceptable cost vs the runtime brittleness of dynamic linking.

## Risks revisited

- **rusqlite + cc bundle on first build** — first `cargo build` will compile vendored SQLite (`cc` from Xcode CLT, already a Phase 0 prerequisite). Adds ~30s first-time. Cached after; no per-test overhead.
- **WAL files leak under panic** — `TmpDb::Drop` removes the `.db`, `.db-wal`, `.db-shm` siblings. `Repo::open` is infallible up to the connection layer; if it panics (it doesn't), the `TmpDb` already exists and Drop cleans up.
- **FK CASCADE on accidental delete** — Phase 1 has no row deletion in any code path. The clause is defensive for Phase 1.x's eventual "delete meeting" feature.
- **Schema drift between `shared/types.ts` and Rust DTOs** — DB-R11 is the regression gate. If a future contributor renames `startedAt` to e.g. `startTime` on the TS side, the parity test still passes (it doesn't read the TS file) but the type-check on the Tauri command return type will surface the mismatch. Phase 2 may codegen the DTOs from `shared/types.ts` to remove the drift surface entirely (e.g. `ts-rs` or `serde_with` macros).
- **Big transcript performance** — single-meeting `list_chunks` is a single indexed-FK select; SQLite handles 10k chunks in <1ms. Phase 1.x adds an explicit `CREATE INDEX idx_chunks_meeting_starts` if the query plan needs it; Phase 1 demo workload is ~1k chunks per hour.
- **`cached_ratio` precision** — REAL = IEEE 754 double; `cacheReadRatio` from `pricing.ts` is also a double. Round-trip is bit-identical for non-NaN values. NaN is upstream-guarded by `pricing.ts:cacheReadRatio` (returns 0 if total=0).
- **Concurrent `Repo` opens** — single Repo per process in Phase 1 demo. Phase 1.x adds `busy_timeout` if a menubar app + main app both want to write.
