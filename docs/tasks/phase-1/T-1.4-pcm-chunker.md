## Goal

Add the **second half of the audio→STT pipeline** — a `Chunker` that wraps any upstream PCM source and emits **2-second windows of canonical 16 kHz mono f32 PCM**, backed by a bounded `RingBuffer<f32>` with a deterministic drop-oldest policy when the consumer falls behind. Synthetic-PCM-driven TDD; same fixture-friendly pattern as T-1.3.

The chunker absorbs three concerns the cpal source intentionally punts:

1. **Resample** — cpal's mic stream emits at the device's native rate (typically 48 kHz on Apple Silicon); MLX whisper expects 16 kHz. Linear interpolation is sufficient for MVP per ARCH §3.1 (the model itself is robust to ≤ 1% rate drift). High-quality polyphase resampling (e.g. `rubato`) is a Phase 1.x optimization.
2. **Mono mixdown** — cpal's default config on macOS is stereo; whisper expects mono. We average interleaved frames per sample.
3. **Re-window to a 2-s sliding boundary** — the 100-ms cpal callback chunks (`DEFAULT_CHUNK_SIZE = 1600`) are too small for whisper's encoder block. ARCH §3.1 says "30s sliding window + VAD" for the streaming model, but T-1.5 uses a simpler **fixed 2-s window** for MVP — VAD is deferred to Phase 1.x (`T-1.5b` per spike-memo C-1).

### Why split chunker from capture (T-1.3 vs T-1.4)?

T-1.3 owns "source → bytes/samples". T-1.4 owns "samples → canonical 16 kHz 2-s windows". The split lets:

- T-1.3's tests assert against the WAV's native rate without hardcoding 16 kHz.
- T-1.4's tests drive a synthetic `&[f32]` stream directly through `Chunker::push(...)` — no `AudioSource`, no cpal, no WAV reader needed in the chunker's unit tests.
- T-1.5 layer on top of `Chunker::try_next_chunk()` without learning what a `WavFileSource` is.

### Push/pull split (chunker doesn't own the source)

`Chunker` is **push-based**: it has `push(samples, source_rate, channels)` + `try_next_chunk() -> Option<PcmChunk>`. Higher layers (T-1.5 STT loop, T-1.6 Tauri bridge) own the call site that pulls from the upstream `AudioSource` and pushes into the chunker. This is the same pattern Tokio's `Framed` and `tokio::io::ReadBuf` use: keep the I/O loop in one place, keep the chunking pure.

A small `chunker_source.rs` adapter that turns a `Box<dyn AudioSource> + Chunker` pair into another `AudioSource` is **deferred** — neither T-1.5 nor T-1.6 needs it (both run their own loop). If a third consumer appears, we add it then.

## TDD Plan

### RED → GREEN cycles

- **RED 1** — `cargo test ring_buffer_push_within_capacity_no_drop` fails (no `RingBuffer`). **GREEN 1** — add `RingBuffer { buf: VecDeque, capacity }` + `new` + `push_slice`.
- **RED 2** — `ring_buffer_push_overflow_drops_oldest` fails (push doesn't truncate). **GREEN 2** — pre-push: if `len + slice.len() > capacity`, pop `(len + slice.len() - capacity)` from front; return drop count.
- **RED 3** — `ring_buffer_drain_n_returns_none_when_too_few` fails (panics or returns short Vec). **GREEN 3** — `drain` checks `len >= n` else returns `None`.
- **RED 4** — `ring_buffer_drain_n_extracts_exact_count` fails (returns wrong length). **GREEN 4** — `drain` calls `buf.drain(..n).collect::<Vec<_>>()`.
- **RED 5** — `chunker_emits_two_chunks_for_5s_synthetic_pcm` fails (no `Chunker`). **GREEN 5** — add `Chunker` + `ChunkerConfig` + `push` (mono-passthrough at 16k for now) + `try_next_chunk` returning ring-drained window.
- **RED 6** — `chunker_timestamps_are_deterministic_per_chunk_index` fails (ts_ms = 0 always). **GREEN 6** — increment `chunk_idx` after each window; `ts_ms = chunk_idx * window_seconds_in_ms`.
- **RED 7** — `chunker_resamples_48khz_to_16khz_mono` fails (asserts buffered len wrong; chunker doesn't resample). **GREEN 7** — add linear resampler in `push`: input pos `i_in = i_out * source_rate / target_rate`; carry the last input sample across calls via `resample_carry` + fractional `resample_phase`. Output count ≈ `input_len * target / source`.
- **RED 8** — `chunker_mixes_down_stereo_interleaved_to_mono` fails (samples not averaged). **GREEN 8** — in `push`, when `channels > 1`, average `frame_idx * channels .. frame_idx * channels + channels` to one mono sample, **before** resampling.
- **RED 9** — `chunker_drop_releases_buffer_no_panic` fails (only if `Drop` panics — the test catches that). **GREEN 9** — `Chunker` holds only `RingBuffer` (which holds `VecDeque<f32>`) + a few primitives. No custom `Drop` needed; std drop is leak-free.
- **RED 10** — `chunker_drop_strong_count_via_arc_tracer` fails (chunker leaks the Arc somewhere). **GREEN 10** — design holds: chunker doesn't take `Arc<...>` at all in production code; the test wraps both in a `ChunkerHarness { chunker, _tracer: Arc<()> }` newtype, dropping the harness drops both.
- **REFACTOR** — extract `mixdown_interleaved_to_mono(samples, channels) -> Vec<f32>` + `linear_resample(samples, &mut state, source_rate, target_rate) -> Vec<f32>` helper free fns (private to chunker module). Each gets its own micro-test if the cycles above didn't already cover them.

### Test fixture strategy

No WAV files; everything is a `Vec<f32>` synthesized in the test (e.g. `vec![0.0; 80_000]` = 5 s of silence at 16 kHz mono, or `(0..N).map(|i| (i as f32 / N as f32))` for a deterministic ramp). The chunker doesn't care about audio content — only sample counts + timestamps — so a ramp + asserting on `samples[0]` / `samples[last]` is enough to detect off-by-one or stale-buffer regressions.

For the resampler test, push 6000 samples @ 48 kHz; the linear resampler emits `floor(6000 * 16000 / 48000) = 2000` output samples (give or take the carry/phase boundary — the test asserts `1995..=2001` to absorb the ±1 from the integer-vs-fraction edge).

## Risk + Mitigation

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Linear resampling introduces audible aliasing → STT accuracy drop | Medium | Medium | MVP target — whisper's encoder is robust to mild aliasing per ARCH §3.1. Phase 1.x swaps in `rubato` polyphase if STT word-error-rate regresses. |
| Off-by-one in resample count breaks downstream window math | Medium | Low | Test 7 asserts a tolerance window `1995..=2001` (not exact 2000) to acknowledge the ±1 from carry-over. The next chunker `push` reuses the carry, so cumulative drift stays bounded. |
| Stereo mixdown drops important content (e.g. one mic on Aggregate Device) | Low | Medium | Average-mixdown is the simplest; ARCH §2.1 anticipates "2 stream → resample → ring buffer" — both streams contribute equally. If a mic-only device ships stereo (rare), both channels carry the same content; averaging is a no-op. |
| Ring buffer drop-oldest hides bugs (silently lose audio) | Medium | Medium | `push_slice` returns the dropped count; T-1.6's Tauri event bridge surfaces this as a `meeting:dropped_samples` warning event. Defaults: 30 s buffer is generous (3 windows × 5 = ~15 windows of slack), so drops only happen when the consumer is severely wedged. |
| Chunker `Drop` test is "no panic" → too weak | High | Low | Pair with the Arc-tracer test (#10) which catches accidental retention via internal closures or threads. If a future refactor adds an `std::thread::spawn` inside `Chunker`, the tracer test fails — covered. |
| Resample state across `push` calls incorrect when buffer empties + refills | Medium | Medium | `resample_carry: Option<f32>` is reset to `None` only when the chunker is `new`'d, never on `push` — carry persists across calls. Test 5 + Test 6 push in chunks (e.g. 16_000 at a time) and verify cumulative chunk emission matches the total. |
| `f64` resample math vs `f32` ring storage causes subtle drift | Low | Low | Use `f64` only for the phase accumulator (`source_rate / target_rate` ratio); convert each interp output to `f32` via a single cast. No long `f32` accumulator chains. |
| `VecDeque::drain(..n).collect::<Vec<_>>()` allocates each window | Low | Low | Allocation is `n * size_of::<f32>() = 32_000 * 4 = 128 KB` per 2 s window = 64 KB/s = trivial. Stream-API alternative (custom iterator) is a Phase 1.x micro-optimization. |
| Timestamp uses chunk_idx not source ts → drifts vs wall clock if buffer accumulates | Medium | Low | Documented in chunker rustdoc: `ts_ms` is **emission time relative to chunker start**, not wall clock. T-1.6's Tauri event tags add a wall-clock `received_at` field. T-1.5's STT gets the `ts_ms` for transcript indexing, which is exactly what the schema (`TranscriptChunk.startTs`) wants. |

## Scope Guardrails (what this task does NOT do)

- ❌ STT integration — T-1.5 (subprocess + JSON parse).
- ❌ Tauri command exposing chunked output — T-1.6 (event bridge).
- ❌ VAD / utterance assembly — Phase 2 T-2.2 (silence-based boundaries) and spike-memo `T-1.5b` (Silero VAD upgrade).
- ❌ High-quality polyphase resampler (e.g. `rubato`) — Phase 1.x optimization gated on whisper WER measurement.
- ❌ Dropping new (vs oldest) — drop-oldest is the only policy. Drop-newest is rare in audio (you lose the most recent moment) and adds branching with no MVP benefit.
- ❌ Multi-source mixing (mic + system audio) — covered by `cpal` device-selection at the source layer (T-1.3 / T-1.6 configure aggregate input device). The chunker sees one stream regardless.
- ❌ Lock-free SPSC ring (`ringbuf` crate) — `VecDeque` is single-threaded (push side and drain side are the same thread per the push/pull model). T-1.6's Tauri event bridge runs both sides on a dedicated worker thread; no contention. If T-1.6 changes that, `ringbuf` swap is a 30-line change.
- ❌ Persisting chunks to disk — T-1.12 (SQLite via `tauri-plugin-sql`).
