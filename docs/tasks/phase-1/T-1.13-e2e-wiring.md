### Decomposed AC

- **AC-E1** App boots and renders the four canonical sections (`ContextLoader`, `MeetingControls`, `TranscriptView`, `AnswerPanel`) without console errors.
- **AC-E2** Loading a context source through `ContextLoader` (mocked `invoke("read_context_file")`) populates the `useContextStore` so the Start button leaves the disabled state.
- **AC-E3** Clicking Start flips the meeting status to `"active"` and reveals the Stop + Mark question buttons (the Start button is replaced).
- **AC-E4** A simulated `transcript:chunk` Tauri event sequence (driven by the existing `useTranscriptStream` listener seam — the same one shipped in T-1.6) appends chunks to the on-screen `TranscriptView` in order, in the canonical camelCase JSON shape from `shared/fixtures/transcript_chunk.sample.json`.
- **AC-E5** Clicking Mark question pushes the latest 3 transcript chunks (joined with single spaces) onto `useQuestionStore.questions[0]`. The same chunk text appears in the `[data-testid=question-list]` (or equivalent) row that T-1.13 introduces alongside the panel — even one row of marked-question read-back is fine; the headline is "the marked question is visible".
- **AC-E6** The mocked Anthropic SDK delivers a streamed answer (≥ 2 deltas + a `finalMessage` with `usage`). The `AnswerPanel` renders the aggregated text incrementally (the test asserts at least one mid-stream snapshot AND the final state). The `costUsd` readout appears once the stream completes.
- **AC-E7** Clicking Stop flips status to `"ended"` AND triggers a single `invoke("save_meeting", …)` call. The serialised payload contains: 1 meeting row (status `"ended"`, `endedAt` set), N transcript-chunk rows (every chunk seen during the meeting), 1 question row, 1 answer row (`text` = the streamed Claude output), 1 context-source row + a meeting↔context link.
- **AC-E8** On (re-)mount the App calls `invoke("load_meetings")` once. The mocked response (the same payload shape that AC-E7 produced) is stored in a `useHistoryStore` (or fold into the meeting store — task picks the smaller surface) and a tiny `[data-testid=past-meetings]` block renders the count. This is what the user perceives as "meeting persisted across re-open".
- **AC-E9** No `unhandledRejection` / no React `act(...)` warnings during the harness — the test fails noisily if either fires (vi.spyOn over `console.error`).
- **AC-E10** End-to-end test runs in < 2 s on a warm M1 (no real timers, no real Anthropic network call, no real Tauri runtime).

### Persistence-layer surface (the actual code change)

This is the wiring that lives on top of T-1.12's `Repo`:

1. **`crates/helper-daemon/src/repo.rs`** — gain `save_meeting_snapshot(&self, &MeetingSnapshot) -> Result<(), RepoError>` on the existing `Repo`. `MeetingSnapshot` is a new sibling DTO bundling: `MeetingRow`, `Vec<TranscriptChunkRow>`, `Vec<QuestionRow>`, `Option<AnswerRow>`, `Option<ContextSourceRow>`. The method is a single transaction (`conn.unchecked_transaction()` → insert all → commit) so a partial failure rolls back the meeting cleanly. Cargo tests assert idempotent inserts within the snapshot ordering (meeting before chunks, question before answer) and FK-pre-flight (a snapshot with an answer but no question rejects).
2. **`src-tauri/src/lib.rs`** — register two new `#[tauri::command]`s:
   - `save_meeting(state: State<RepoHandle>, snapshot: MeetingSnapshot) -> Result<(), String>` — wraps `state.repo.save_meeting_snapshot(&snapshot)` and stringifies the error.
   - `load_meetings(state: State<RepoHandle>) -> Result<Vec<MeetingRow>, String>` — wraps `state.repo.list_meetings()`.
   Plus `RepoHandle { repo: Repo }` registered with `tauri::Builder::manage(...)` inside `run()`. The DB path is `~/Library/Application Support/meeting-copilot/meetings.db` on macOS — picked here (not in T-1.12) because Tauri owns the path-resolver. For the cargo test side we keep the older `Repo::open_in_memory()` path; the Tauri-side path resolution lives behind `#[cfg(not(test))]` so the unit tests for the command wrappers pass an explicit `Repo` instance.
3. **`src/persist/persistClient.ts`** — new TS module with: `saveMeetingSnapshot(snapshot: MeetingSnapshot): Promise<void>`, `loadMeetings(): Promise<MeetingSession[]>`, plus the `MeetingSnapshot` shape (re-uses `MeetingSession`, `TranscriptChunk`, `Question`, `Answer`, `ContextSource` from `shared/types.ts`). Pure `invoke` wrappers; the test mocks `@tauri-apps/api/core` directly.
4. **`src/hooks/useMeetingPersist.ts`** — new React hook:
   - On mount → `loadMeetings()` once → cache into a `useHistoryStore`.
   - When `useMeetingStore.status` flips to `"ended"`, gather the in-flight state (chunks, questions, answer, context) and call `saveMeetingSnapshot(...)` exactly once per meeting (idempotency keyed on `meetingId`).
5. **`src/store/historyStore.ts`** — tiny zustand slice: `pastMeetings: MeetingSession[]; setPastMeetings(...)`. Single consumer (the `<PastMeetings>` block).
6. **`src/components/PastMeetings.tsx`** — read-only count + list. Shows `0 past meetings` on a fresh install, `N past meetings` after AC-E8.
7. **`src/App.tsx`** — wire `useMeetingPersist()`, render `<PastMeetings />` below `<AnswerPanel />`.

### E2E test surface

`src/__tests__/E2E.test.tsx` (new, jsdom). Drives:

- `vi.mock("@tauri-apps/api/core")` with a per-call dispatcher: `read_context_file → fixture`, `save_meeting → record`, `load_meetings → fixture-or-recorded`.
- `vi.mock("@tauri-apps/api/event")` with the same `listen()` handle approach the existing `useTranscriptStream.test.ts` uses — the test pushes events on demand.
- `vi.mock("@anthropic-ai/sdk")` with a fake `Anthropic` class whose `messages.stream(body)` returns an event-emitter shaped object identical to the one `claudeClient.test.ts` already uses (the seam is `.on("text", cb)` + `.finalMessage()`).
- The test exercises the full flow: render → load context → start → push 3 transcript chunks → mark question → assert mid-stream answer text → assert final answer text → click Stop → assert `save_meeting` called once with the expected snapshot → re-mount → assert `load_meetings` called → past meetings count = 1.

## Risk + Mitigation

| Risk | Likelihood | Mitigation |
|---|---|---|
| The E2E test's mocked `@anthropic-ai/sdk` drifts from the real SDK shape; future SDK upgrade silently breaks prod. | M | The mock duplicates the same seam `claudeClient.test.ts` already uses (`messages.stream(body)` → `.on("text", cb) + .finalMessage()`). If the SDK changes either method, **the existing T-1.10 unit tests fail too** — the regression gate is the union of T-1.10 + T-1.13, not T-1.13 alone. |
| `useMeetingPersist` fires `saveMeetingSnapshot` twice if the parent re-renders mid-Stop. | M | The hook keeps a `lastSavedMeetingIdRef` that the effect compares against `meetingId` before invoking. E13 is the regression gate. |
| `loadMeetings` rejects on a fresh install (DB doesn't exist yet). | M | The Tauri side ensures the DB path's parent dir exists before calling `Repo::open(path)`; `Connection::open` creates the file on first call. The hook treats `loadMeetings` errors as "no past meetings yet" (sets `pastMeetings = []` + logs a warn) — verified by E11's twin test that injects a rejection and asserts `pastMeetings = []`. |
| The E2E test relies on real timers via `setTimeout` inside `claudeClient.ts`'s `DeltaQueue` and ends up flaky. | L | `DeltaQueue` does NOT use `setTimeout`. The mock SDK pushes events synchronously inside `messages.stream(...)` callback so all yields land on microtasks. `act()` awaits each `await` boundary. |
| Tauri command path resolution (`app_data_dir`) is unavailable in unit tests. | L | The `save_meeting_inner` / `load_meetings_inner` free functions take a `&Repo` directly — the tests pass `Repo::open_in_memory()`. The path-resolver is the production-only adapter. |
| `useMeetingPersist`'s save fires before the answer stream finishes (race: status → `"ended"` while `useAskClaude.status === "streaming"`). | M | The hook gathers the answer **state** at fire time. If the answer is mid-stream, `text` is the partial buffer — that's the demoed behaviour ("user closed the meeting before the answer finished, partial text saved"). E21's assertion uses the FINAL stream text because the test waits for the stream to complete before clicking Stop. Phase 1.x can add a "wait for answer to complete before stopping" UX gate; Phase 1 keeps the brittle truth (your data is saved at the moment you press Stop). |
| The new Tauri commands need a `RepoHandle` in `tauri::State` — but the `run()` function constructs the AppHandle synchronously, before `Repo::open` returns. | L | `Repo::open(path)` is synchronous + < 50 ms on first call (creates file, runs DDL, sets pragmas). Tauri's `Builder::setup(...)` closure runs after the event loop is up but before the first command — perfect spot to construct `Repo` and `manage(...)` it. Same pattern as e.g. `tauri-plugin-store`. |
| Test pollution from `historyStore` zustand singleton between tests. | L | Every test calls `useHistoryStore.setState({ pastMeetings: [] })` in `beforeEach`. Same pattern as `meetingStore.test.ts`'s `useMeetingStore.setState(... )` resets. |
| `MeetingSnapshot` shape drifts between Rust DTO + TS interface. | M | DB-R11 (T-1.12) already tests Rust-side camelCase. T-1.13 adds an E7 test that asserts the TS-side `MeetingSnapshot` keys match what `MeetingRow` serialises to (passes the Rust shape JSON-stringified into a TS `as` cast). |
| JSDOM clipboard mock missing for `AnswerPanel`'s Copy button — a stray click in the E2E test triggers `navigator.clipboard.writeText` undefined. | L | Copy button visible only on `status === "done"` (which the test reaches), but the test never clicks it. If a future E2E test does click it, the panel already swallows clipboard errors (T-1.11 AC). |
