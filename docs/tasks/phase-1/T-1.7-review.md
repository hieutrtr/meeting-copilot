## Self-review checklist

- [x] **Tests pass** — 6 net new vitest cases, all GREEN; cumulative 15/15. `bun run typecheck` clean.
- [x] **AC met** — every UI-T# row in the table above traces to a passing assertion.
- [x] **Not over-engineered** — no virtualization library; the windowing math is ~10 lines (`startIdx`/`endIdx`/`visible`). No speaker coloring (Phase 1.x), no result-count badge (not in AC), no scroll-suppression heuristic (T-1.9 follow-up). Inline `style={{}}` for layout primitives that depend on JS-computed values (row height, list height); class names exposed for future stylesheet wiring without touching the component.
- [x] **Tauri + React + TS strict** — no `any`; explicit `ReactNode` for the highlight return; `TranscriptChunk` imported from `shared/types`; component compiles under `tsconfig.json` `strict: true` + `noUnusedLocals`/`noUnusedParameters`.
- [x] **No secret leak** — pure client component, reads no env vars, accepts no API tokens, renders only the props provided. `ANTHROPIC_API_KEY` is irrelevant at this layer.
- [x] **Audio buffer cleanup** — N/A (no audio path); chunks owned by parent state via `useTranscriptStream`. Unmount drops React refs; no manual cleanup needed.
- [x] **Streaming UI not blocking thread chính** — `useLayoutEffect` runs synchronously after commit but only does O(1) work (set scrollTop + spy call). Render path: `filter` is O(N) per query change (acceptable — N ≈ 1800 max per spike memo); window slice is O(end-start) ≈ 25. No layout thrash, no React 18 concurrency hazards (no suspense, no transitions).

## Cross-cutting Phase 1 concerns covered

1. **vitest dual-environment** — node-env existing tests (9) untouched; jsdom-env scoped to the new file via `// @vitest-environment jsdom` pragma. `vitest.config.ts` global `environment: "node"` deliberately preserved so future hook tests stay deterministic without per-test env choreography.
2. **scrollIntoView jsdom shim** — installed/restored at suite scope; reset in `beforeEach` via `mockClear()`. Real browser path is unaffected because the spy only replaces `Element.prototype.scrollIntoView` inside the test process.
3. **Highlight casing parity** — `<mark>` content is `text.slice(idx, idx + query.length)`, i.e., the *original* casing from the chunk text, not the user's query string. UI-T5 explicitly asserts this so a future "normalize for display" regression would fail loudly.
4. **Future-proofing for T-1.9** — `TranscriptView` ignores click/hover events on rows. T-1.9's "Mark as question" lives in a parent wrapper that consumes the same `chunks` array and overlays its own controls; no API change required.
5. **Future-proofing for T-1.13** — the component renders deterministically given a fixture array, so the E2E smoke harness can drive it without a live Rust runtime.
6. **Bun lockfile churn** — 4 dev deps + 57 transitive added in one commit. No runtime deps changed; bundle size for `bun run build` stays at the Phase 0 baseline.
