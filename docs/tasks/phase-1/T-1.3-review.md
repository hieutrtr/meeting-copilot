## Notable design decisions

1. **Trait surface is intentionally minimal** — `sample_rate()`, `channels()`, `next_chunk()`. No `start()` / `stop()` on the trait itself: `WavFileSource` doesn't need them (eager-load), and `CpalMicSource::start()` returns `Result<(), AudioError>` which can't be uniformly modeled across all sources without `async`. T-1.6 (Tauri event bridge) wraps `Box<dyn AudioSource>` and handles lifecycle externally.
2. **Eager WAV load** — Phase 1 fixtures are < 10 s; eager `Vec<f32>` load is < 1 MB. Streaming-read of multi-minute meeting recordings is a Phase 1.x optimization; T-1.5's STT adapter operates on the cpal source for live meetings, not WAV files.
3. **`mpsc::sync_channel(64)` is a 100ms-chunk × 64 = 6.4-second backlog at ARCH §2.1's stated chunk size.** That's far more than the < 3 s end-to-end latency budget (§12). On a healthy consumer the queue is near-empty; the bound exists only to prevent unbounded memory growth on a wedged consumer. T-1.4's lock-free ring buffer replaces this with proper back-pressure (drop-oldest vs drop-newest is configurable there).
4. **`f32` sample-format assumption for cpal callback.** macOS native input format on Apple Silicon is f32; if a device returns i16/u16, `build_input_stream` errors and `start()` returns `AudioError::CpalStream`. Multi-format dispatch (T-1.4 or later) is out of scope.
5. **No `examples/` binary in this iteration.** A `cargo run --example mic_smoke` would be useful but requires a UI sink; defer to T-1.6 when the Tauri event bridge gives us one. Documented in task file §"Hardware-blocked verification".
6. **System-audio (BlackHole) loopback intentionally deferred.** ARCH §2.1 default is the Aggregate Input Device path (mic + BlackHole in one cpal stream). The cpal device-open code stays the same; only the device-selection helper grows. Tracked as Phase 1.x follow-up; blocked-action #1 in INDEX.

## Follow-ups for next iteration (T-1.4)

1. **Resample to 16 kHz** — the cpal source emits at device-native rate (typically 48 kHz). The chunker's first responsibility is to resample mono into 16 kHz mono using a polyphase / linear-interp filter (rubato crate is the typical pick; std-lib linear interp is acceptable for MVP).
2. **Lock-free ring buffer** — replace `mpsc::sync_channel(64)` semantics with `ringbuf` or hand-rolled SPSC. T-1.4 owns this.
3. **2-second sliding window** — chunker emits one `PcmChunk` every 2 s for the STT subprocess (T-1.5). The cpal source is unchanged; the chunker wraps `Box<dyn AudioSource>`.
4. **Synthetic PCM test source** — add a `SineWaveSource` (or generic `IteratorAudioSource<I: Iterator<Item = f32>>`) so the chunker test doesn't need a WAV file. Keep `WavFileSource` for end-to-end fixtures.

No deferred items spilled out of this task — the scope guardrails held. Trait-and-impl decoupling means T-1.4 / T-1.5 / T-1.6 only see `Box<dyn AudioSource>` and never touch cpal directly.
