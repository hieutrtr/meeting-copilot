### Static-trace verification of the 5+10 tests

All test logic was math-checked by hand before commit:

- **Ring overflow** (`push_overflow_drops_oldest`): cap=4, push [1,2,3] then [10,20,30,40] → `len=3+4=7 > 4 → drop=3 → final=[10,20,30,40]`. Drained head matches `[10,20,30,40]` in FIFO order.
- **Ring under-fill** (`drain_n_returns_none_when_too_few`): push 3, drain 5 → `None`, len untouched (no partial extraction).
- **Single push > capacity** (`single_push_larger_than_capacity_keeps_tail`): special-case in `push_slice` clears the buf, copies the tail. cap=3, push [1..=5] → keeps [3,4,5], dropped=2. (Path checked because cpal's 100 ms callback might burst more than 30 s of buffer if T-1.6 stalls; the special case keeps memory bounded without surprise.)
- **Chunker 5 s → 2 chunks**: 80 000 mono samples @ 16 kHz, default config. Source rate == target rate so the resample path is bypassed; mono pass-through. `RingBuffer.len()` reaches 80 000, `drain(32_000)` succeeds twice, third call returns `None`, `buffered_samples() = 16_000`. ✓
- **Chunker timestamps**: `ts_ms = chunk_idx * window_seconds_in_ms = chunk_idx * 2000`. For 4 windows: `[0, 2000, 4000, 6000]`. ✓
- **Chunker resamples 48 → 16 kHz**: step = 48000/16000 = 3.0. With 6000 input samples, no carry on first call, loop emits at `pos = 0, 3, 6, …, 5997`. Loop terminates when `i0 + 1 >= 6000`. Last successful iter: `pos=5997, i0=5997, i0+1=5998<6000` → output. Next iter: `pos=6000, i0+1=6001 >=6000` → break. Total outputs = 2000 (k = 0..1999). ✓ within tolerance `1995..=2001`.
- **Chunker mixes stereo → mono**: 1000 frames `[0.4, 0.6, 0.4, 0.6, …]`, ch=2. `mixdown_interleaved_to_mono` averages each frame → 1000 mono samples each ≈ 0.5 (f32 rounding ≈ 6e-9, well within 1e-5 tolerance). ✓
- **Chunker drop no-panic**: 400_000 samples @ 16 kHz mono. Capacity = 30·16_000 = 480_000 ≥ 400_000 → no overflow → `buffered=400_000`. `drop(chunker)` runs `VecDeque::drop` (which deallocates the backing slab); no thread/fd/channel held → trivially leak-free.
- **Arc-tracer leak proof**: `ChunkerHarness { chunker, tracer: Arc<()> }`; outer `tracer_clone` keeps strong-count = 2 while harness is alive; after `drop(harness)`, only `tracer_clone` holds a ref → strong-count = 1. ✓

### Resampler carry-over math (the one subtle invariant)

`linear_resample` keeps two pieces of state across calls:

- `carry: Option<f32>` — the last input sample of the previous call, used as the "left neighbor" for interpolation across the call boundary.
- `phase: f64` — the fractional position of the next desired output sample, **measured from the carry sample at logical idx 0**.

The carry-update formula (which I had to amend during this iteration after a static trace flagged a bug):

```rust
*phase = pos - logical_len as f64;   // not (logical_len - 1)
```

Trace for the 48 → 16 kHz test (single 6000-sample push):

- start: `prev=None, phase=0.0, pos=0.0, logical_len=6000, step=3.0`
- end of loop: `pos = 6000.0` (one step past the last successful read)
- after: `carry = Some(input[5999])`, `phase = 6000 - 6000 = 0.0` ✓

If a hypothetical second call comes in with another 6000 samples @ 48 kHz:

- `prev = Some(input1[5999]), phase = 0.0, pos = 1.0 + 0.0 = 1.0`, `logical_offset = 1`, `logical_len = 6001`
- The next output reads `read(1) = input2[0]` and `read(2) = input2[1]` (interp `frac=0`) → `out = input2[0]` — correctly continuing the cadence at original-stream coord 6000.
- Loop terminates at `pos = 6001`; `phase = 6001 - 6001 = 0`. Drift is bounded across arbitrarily many calls.

A naive `phase = pos - (logical_len - 1)` would have given `phase = 1.0` after call 1 → next pos = `1 + 1 = 2.0` → would skip `input2[0]` and start at `input2[1]`. That kind of one-sample-per-call drift would compound over a 30-min meeting (~1800 calls @ 1 s push cadence = 1800 sample drift = 112 ms drift, audible to whisper). The fix lands the formula at `pos - logical_len`.

The equal-rate path (test 14, `linear_resample_identity_when_rates_equal_via_skip_path`) lands `phase = pos - logical_len = 3 - 4 = -1.0` after a 4-sample call; the `if *phase < 0.0 { 0.0 }` clamp absorbs the equal-rate edge where one sample is held back for interp. The chunker bypasses this path for `source_rate == target_rate` so production code never hits it; the test exists only to nail down the helper's behavior in isolation.

## Notable design decisions

1. **Push/pull split, chunker doesn't own the source.** `Chunker::push(samples, source_rate, channels)` + `try_next_chunk()` keeps the I/O loop in the consumer (T-1.5 STT loop, T-1.6 Tauri event bridge), keeps the chunker pure. A `Box<dyn AudioSource> + Chunker` adapter is **deferred** — neither downstream consumer needs it (both run their own loop). This is also why the chunker is single-threaded internally: push side and pull side run on the same worker thread per the consumer's design. `ringbuf` swap (lock-free SPSC) is a 30-line change if T-1.6 chooses to split the threads.
2. **`VecDeque<f32>` over `[f32; N]`-backed slab** — VecDeque's amortized O(1) front+back gives drop-oldest in O(n) for the evicted prefix only, with no copy of the retained tail (it's a ring index update). For 30-s buffer at 16 kHz that's 480 KB; `with_capacity(480_000)` allocates once at construction. No allocations on the hot path of `push_slice` for steady-state pushes that don't overflow.
3. **Resample carry as `Option<f32>` + `f64` phase, not a sample-rate converter object.** A full SRC (e.g. `rubato::FftFixedIn`) would be 100+ lines of state and a heap allocation per chunk; for MVP linear interp is "good enough" per ARCH §3.1 and the static trace shows zero drift across calls. The phase-formula-bug found and fixed in this iteration (`pos - logical_len`, not `pos - (logical_len - 1)`) is documented in the rustdoc + the carry-over math section above. If we end up needing higher-quality resampling (e.g. STT word-error-rate regresses on cross-rate inputs), the swap is contained: replace the body of `linear_resample` and the two state fields, leave the public API alone.
4. **Mixdown happens *before* resample** — averaging samples then resampling is identical mathematically to resampling each channel then averaging, but the former halves the resampler workload for stereo input. Order documented in the module preamble.
5. **`#[cfg(test)] use std::sync::Arc;` only** — the `Arc<()>` tracer pattern in test 10 keeps production code free of Arc references. If a future refactor wants to share the chunker across threads (e.g. STT runs on its own thread), the swap is `Arc<Mutex<Chunker>>` at the *call site*, not inside the type.
6. **No `examples/` binary in this iteration.** A `cargo run --example chunker_smoke` would require a synthetic source + a logging consumer; defer to T-1.6 when the Tauri event bridge gives a real sink. Documented in task file §"Hardware-blocked verification".
7. **Source-rate change resets resample state** — `last_source_rate` field tracks the previous push's rate. If it changes (device hot-swap, BlackHole loopback toggle), the resampler's carry+phase are reset. This loses one sample of cross-call interp continuity at the rate-change boundary (acceptable: the meeting just resumed audio with new device characteristics anyway).
