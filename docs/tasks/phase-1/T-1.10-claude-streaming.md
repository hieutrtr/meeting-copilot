## Acceptance Criteria (verbatim from INDEX)

> **T-1.10** — Claude API client with prompt cache (two `cache_control: ephemeral` system blocks per ARCH §6.2/§7.2). Streams answer tokens. **AC:** mocked-SDK test asserts `system[0]/system[1]` both have `cache_control`, recent transcript on `messages[0].user` content **without** `cache_control`, byte-identical request body across 2 calls. Cost AC = $0.015/warm-call advisory (per spike-memo C-3). Dep: T-1.9. **Hardware-blocked**: live latency / cache-ratio AC pending `ANTHROPIC_API_KEY`.

Decomposed:

- **AC-1** Public surface: `askClaude(input: AskClaudeInput, opts?: AskClaudeOptions): AsyncGenerator<AskClaudeEvent, AskClaudeResult>` exported from `src/llm/claudeClient.ts`. `AskClaudeInput = { question: string; contextDoc: string; recentTranscript?: string }`. `AskClaudeEvent` is a discriminated union (`{ type: "delta"; text: string } | { type: "usage"; usage: AnthropicUsage } | { type: "stopReason"; reason: string }`). The async generator's return value is the final `AskClaudeResult { text: string; usage: AnthropicUsage; cacheReadRatio: number; costUsd: number; stopReason?: string }`. The generator-with-final-return shape lets T-1.11 (`AnswerPanel`) `for await` deltas while still picking up the aggregated result for cost-readout / cache-ratio surfacing.
- **AC-2** Request shape (asserted byte-by-byte against a captured-args mock):
  - `model = "claude-sonnet-4-6"` (constant; spike memo §"Stack decision").
  - `max_tokens = 600` (matches ARCH §7.2 example + T-0.5 prod default).
  - `temperature = 0` (deterministic for cache reproducibility).
  - `system` is a **2-element array** of `{ type: "text"; text; cache_control: { type: "ephemeral" } }`. Order is fixed: `system[0]` = static instructions ("You are Meeting Copilot…"), `system[1]` = the user-supplied context doc.
  - `messages` is `[{ role: "user", content: [...] }]` with **two** content parts: a recent-transcript text part and the question text part. Both parts are plain `{ type: "text"; text }` — **no `cache_control`** anywhere on the user message (volatile per ARCH §7.2).
- **AC-3** **Byte-identical request body across calls.** Two consecutive `askClaude(input)` calls with the same input must produce identical JSON-stringified request bodies. Required for the prompt-cache key to hash stably (a single byte drift on `system[1]` triggers a cache miss and pushes warm-call cost from $0.005 to $0.015+).
- **AC-4** Streaming: deltas arrive **as text becomes available**, not after the full response. The generator yields `{ type: "delta", text }` events synchronously off the SDK's `text` event, and aggregates the streamed text into the final `result.text`. Internal buffering must not block the consumer (`for await` in `AnswerPanel` should see incremental output).
- **AC-5** Missing API key path: if `ANTHROPIC_API_KEY` (or the explicit `apiKey` opt) is absent, `askClaude` throws `MissingApiKeyError` **before** instantiating the SDK and **before** the first `.next()` (synchronous throw in the wrapping factory function so the UI can surface a friendly message without entering the async generator). Error message must not include any candidate key value.
- **AC-6** No secret leakage. The implementation:
  - Never logs the API key (no `console.log(apiKey)`, no `JSON.stringify({ apiKey })`).
  - Never embeds the key in returned events / errors.
  - Lets the user inject `apiKey` explicitly via `opts.apiKey` so tests can pass a fake key (`"test-key"`) without setting the global env var.
- **AC-7** Usage + cost surfacing: the final `AskClaudeResult` reports `usage` (input/output/cache_creation/cache_read tokens), `cacheReadRatio` (per `experiments/T-0.5/src/pricing.ts:cacheReadRatio`), and `costUsd` (per `experiments/T-0.5/src/pricing.ts:computeCostUsd`). Pricing constants ported into `src/llm/pricing.ts` so the prod path doesn't reach into `experiments/`.
- **AC-8** Recent transcript fallback: when `recentTranscript` is absent or empty, the user message still has 2 content parts (transcript part holds the literal string `"(no recent transcript yet)"`) so the cache hashing on `system[*]` is fully decoupled from transcript presence. This guarantees AC-3 even when the meeting just started and no chunks have arrived.

Out-of-scope for AC (deferred under explicit notes below): live API latency / cache-ratio bench numbers (Phase 0 T-0.5 already proved them on M1 Max; T-1.13 re-runs the structural smoke on M1 Pro hardware once `ANTHROPIC_API_KEY` is in env).

## TDD plan

Test runner: Vitest with `vi.mock("@anthropic-ai/sdk", ...)` to inject a deterministic SDK stub. Tests file: `src/llm/claudeClient.test.ts`. Pricing tests: `src/llm/pricing.test.ts` (port of `experiments/T-0.5/tests/pricing.test.ts` against the prod copy of the constants — keeps the experiment file untouchable per phase rule).

Fake SDK shape — the constructor mock captures the most-recent `apiKey` arg + the most-recent request body, and the returned `messages.stream(body)` returns an `AsyncIterable`-compatible object that:
- emits `text` events via `.on("text", cb)` with deterministic text fragments (`"hel"`, `"lo"`),
- exposes a `finalMessage()` promise resolving to a fake message with a `usage` block that matches a warm-cache call (1 input, 22 000 cache_read, 8 cache_creation, 50 output),
- exposes a `streamEvent` listener (matching the T-0.5 spike harness shape) so the implementation has parity options.

Tests authored RED-first:

The empty-transcript placeholder check (CL-S6) is the AC-3 corollary — without it, byte-identity holds only when both calls use the same `recentTranscript` value, which is too narrow to give T-1.13 the cache-stability we want when the user marks a question right after Start.

## Risk + Mitigation

| Risk | Likelihood | Mitigation |
|---|---|---|
| SDK upgrade changes the streaming-event shape (`.on("text", …)` vs `streamEvent`). | M | Pin `@anthropic-ai/sdk@^0.40.0` (same as T-0.5 spike). Implementation reads via the high-level `text` event which has been stable through 0.30+. The fake SDK in tests mirrors both event shapes so a refactor toward `streamEvent` is a one-line change. |
| Adding `@anthropic-ai/sdk` as a prod dep bloats the bundle (~80 KB minified). | L | Acceptable — Tauri bundles are ~10 MB baseline; an SDK that ships the streaming + cache wiring out of the box saves us ~400 LOC of fetch + SSE parsing. ARCH §7 already specifies the official SDK. |
| Byte-identical request body (AC-3) drifts due to silent JSON serialisation differences (key order, whitespace). | M | Build the body via a single `buildRequest(input)` pure function. Test CL-S7 is the regression gate. Avoid spreading user-typed objects into the body — only typed fields. |
| `ANTHROPIC_API_KEY` env-var leak into a stack trace if SDK throws "401 Unauthorized" with the key in the message. | M | The official SDK does not echo the key; AC-6 guard is the test (CL-S11 asserts the error message excludes the key). If a future SDK version regresses, the test fails loudly. |
| Test suite reads `process.env.ANTHROPIC_API_KEY` from the dev's actual environment and fires a real call. | H | Tests vi.mock the SDK module; the real SDK is never imported during the test. CL-S10 sets `process.env.ANTHROPIC_API_KEY` to `"env-key"` and restores afterward in `afterEach`. |
| Non-jsdom Vitest environment can't import `@anthropic-ai/sdk` in some paths (depends on `node:stream`). | L | The mocked test uses `vi.mock("@anthropic-ai/sdk", ...)` so the real module is never resolved. Default `node` env is enough; no per-file `// @vitest-environment jsdom` pragma needed. |
| Cost AC ($0.015/warm-call advisory) regresses if `max_tokens` is bumped (output tokens dominate at $15/MTok). | L | Constant `MAX_TOKENS = 600` matches ARCH §7.2 example. Phase 1.x can lift to 1200 if user feedback says answers truncate; cost AC re-checks at that gate. |
| User-supplied context doc contains rare bytes (BOM / NUL) that break SDK serialisation. | L | `contextDoc` flows from `read_context_file` (T-1.8) which already strips no bytes — UTF-8 round-trip. SDK takes raw strings; no further sanitisation required. |
| Hot-reload during a streaming call leaks the AbortController. | L | The async generator naturally exits when the consumer stops `for await`-ing. T-1.13 wraps the call in a React effect with a cleanup that calls `.return()` on the generator; that signal lands then. Phase 1 demo path doesn't hot-reload mid-stream. |

## Hardware-blocked verification

Live API call (real `ANTHROPIC_API_KEY`, real network) is **not** part of T-1.10's TDD gate. Reasons:

1. Phase 0 spike `T-0.5` already proved the structural request shape + the warm-cache latency / cost AC on M1 Max (`experiments/T-0.5/results.md`). The shape this task ships is byte-equivalent (see CL-S2..S5).
2. The loop runs in a sandbox without `ANTHROPIC_API_KEY`. Per loop rule "code complete, hardware verify pending" applies.
3. T-1.13 (E2E smoke, loop position 14/16) re-runs a single live call against `claude-sonnet-4-6` once `ANTHROPIC_API_KEY` is in env. AC there: 1 successful streamed response, warm-call cost recorded, cache-read-ratio > 0.9 on call #2 of the smoke.

If T-1.13 finds the live AC fails, the regression lands as a P0 bug against this task.

## Out-of-scope (deferred)

- **Settings UI + macOS Keychain API key storage** — raw plan T-1.11. MVP reads `process.env.ANTHROPIC_API_KEY` (or explicit opt). Keychain lands Phase 1.x.
- **Markdown rendering of the streamed answer** — T-1.11's `AnswerPanel` owns it. T-1.10 yields raw text deltas only.
- **Retry / timeout policy** — Phase 1 calls fail-fast. T-1.13 might add a single retry on transient HTTP errors; for now the SDK's defaults (5 s connect, no auto-retry) are sufficient for a single-user dev tool.
- **Token-budget guard before sending** — `tiktoken` integration deferred to Phase 1.x cost-AC re-check. T-1.8's `chars/4` proxy gives the user a coarse estimate; if context > 180k chars (~45k tokens) the call still goes through, and Anthropic's 200k context window is the hard ceiling.
- **Live latency / cache-ratio bench numbers** — Phase 0 T-0.5 owns them. T-1.13 re-runs structural smoke only.
- **Multi-question parallel streams** — Phase 1 sends one question at a time. ARCH §11 limits to one in-flight LLM call per meeting; concurrency lands in Phase 2.
- **`streamEvent` migration** — current implementation uses `.on("text", …)` for clarity. If SDK 0.50+ drops the high-level helper, switch in a follow-up.
