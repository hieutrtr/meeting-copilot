## Goal

Add the **third half of the audio→STT pipeline** — a Rust `trait SttProvider` with two implementations:

1. **`FakeStt`** — deterministic in-process impl that returns a configurable fixed text per chunk. This is the **TDD test target** — every layer above (T-1.6 event bridge, T-1.9 meeting state machine, T-1.13 E2E) tests against this fake instead of the real MLX subprocess so CI stays deterministic and toolchain-free.
2. **`MlxWhisperSubprocess`** — the production path. Per ARCH §3.2, MLX local with the `medium` model (per spike-memo §"Stack decision"). Each call spawns Python with an embedded `transcribe.py` script (same pattern as T-0.4 spike `bench.py`), passes the chunk as a temp WAV file, parses one JSON line on stdout, returns `Vec<SttSegment>`.

Both impls satisfy the same `trait SttProvider` so consumers (T-1.6 event bridge, T-1.9 state machine, future Deepgram/ElevenLabs adapters in Phase 3) write **once** against `Box<dyn SttProvider>`. Cargo feature `mlx-runtime` (default-on) gates compilation of the MLX module — hosts without Python can `cargo build --no-default-features` and still get the trait + fake.

### Why subprocess, not FFI?

ARCH §3.2 line: *"`mlx-whisper` (Apple MLX framework, Apple Silicon only)"*. MLX is a Python-first framework; there is no stable C ABI to call from Rust. The T-0.4 spike validated the subprocess path on a 5-model × 5-sample matrix (20/20 runs ok, RTF median 0.059 on `medium`). The subprocess overhead is amortised because:
- The model loads cold at ~28 s for `medium`; warm-loaded subprocess (Phase 1.x — long-lived stdin-pipe daemon) cuts this to zero.
- Phase 1 MVP **does** spawn one subprocess per chunk (worse perf, simpler code). RTF on `medium` is 0.059 → a 2-s chunk transcribes in ~120 ms; spawn overhead (~80 ms) keeps the per-chunk wall < 250 ms, well under the 500 ms ARCH §11 partial-transcript budget.

Phase 1.x optimisations (long-lived subprocess, mlx-whisper streaming API, `large-v3-turbo` upgrade gated by `T-1.5b` Silero VAD) are explicitly **out of scope**.

### Why a single `transcribe_chunk(&PcmChunk) -> Vec<SttSegment>` API, not `start(stream) -> stream`?

ARCH §3.1 reads `start(stream: AsyncIterable<PCMChunk>): AsyncIterable<TranscriptChunk>`. That's the **TS interface contract** for the helper-daemon's IPC layer. The Rust trait only needs the per-chunk transformation; T-1.6 will own the loop that pumps `Chunker::try_next_chunk()` → `SttProvider::transcribe_chunk()` → `app.emit("transcript:chunk", payload)`. Keeping the trait sync + chunk-at-a-time means:

- No tokio dep on `stt-mlx` (defers tokio churn until T-1.6 when Tauri's runtime is the real consumer).
- Tests stay simple: feed one `PcmChunk`, assert one `Vec<SttSegment>`.
- The async stream is a concern of the **consumer**, not the provider.

If a future Phase 3 provider (Deepgram WebSocket) needs persistent connection state, it owns it inside its impl; the trait stays a unit step.

### Test fixture strategy

- `provider.rs` tests use synthetic `PcmChunk { samples: vec![0.0; N], sample_rate: 16_000, ts_ms }` — no audio content, no I/O, deterministic.
- `mlx.rs` integration uses macOS `say "Hello world." -o /tmp/x.aiff` + `ffmpeg -ar 16000 -ac 1 -c:a pcm_s16le /tmp/x.wav` (same pattern as T-0.4 `gen_samples.sh`). The fixture is regenerated on every test run; no committed binary. **Soft-skip** if either `say` or `ffmpeg` is missing.
- The `transcribe.py` script is embedded via `include_str!("../scripts/transcribe.py")`; the source file lives in the repo for human review and is rewritten to `work_dir/transcribe.py` at construction time (cargo treats it as a build input via the `include_str!` macro — touching the script invalidates the rebuild cache).

## Risk + Mitigation

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Subprocess spawn overhead per chunk dominates wall time | High (Phase 1) | Medium | RTF on `medium` is 0.059; spawn overhead ~80 ms; per-2-s chunk wall ≈ 200 ms — under 500 ms partial-transcript budget. Phase 1.x adds long-lived subprocess via `T-1.5b`. |
| Per-chunk hallucination on silence (`large-v3-turbo` failure mode) | High (`turbo`), Low (`medium`) | High | Phase 1 default is `medium` per spike-memo §"Stack decision". `turbo` upgrade is gated by `T-1.5b` (Silero VAD insertion). |
| `mlx_whisper` not on host Python → integration test fails CI | High (sandbox) | Medium | `is_available()` runtime probe + soft-skip in test. Documented re-run via `MLX_WHISPER_PYTHON` env var. |
| `say` / `ffmpeg` not on host → fixture generation fails | Medium (CI) | Low | Soft-skip; fixture re-generates on every test run on hosts that have the tools (macOS dev machines). |
| Temp WAV dir grows unbounded (one file per chunk × infinite meeting) | Medium | Low | `transcribe_chunk` removes the temp WAV after subprocess returns (success or failure). `invocation_idx` keeps unique names; no collision. |
| JSON parse failure on subprocess crash → meeting halts | Medium | High | `SttError` is `Result`-returned; T-1.6's event-bridge loop catches and emits `meeting:stt_error` event. Loop continues; user sees a UI badge. |
| Script path race (two `MlxWhisperSubprocess::new` writing to same `work_dir/transcribe.py` simultaneously) | Low | Low | Both writes have identical content (same `include_str!` constant); last writer wins, data is byte-identical. No correctness impact. |
| Unicode in transcript (Vietnamese, emoji) breaks `from_utf8` parse | Low | Medium | `serde_json` handles UTF-8 natively; the script uses `json.dumps(..., ensure_ascii=False)` would be needed for non-ASCII output. **Phase 1 AC explicitly limits the integration test to ASCII-only ("Hello world.")** to avoid this dep until Phase 1.x. |
| `f32 → i16` clipping in `write_chunk_wav` distorts loud audio | Low | Low | Clamp to `[-1.0, 1.0]` before `* 32767`; whisper's encoder is robust to mild clipping (it's trained on real-world audio with clipping artifacts). |
| `feature = "mlx-runtime"` disabled at compile → tests skipped silently | Low | Low | `#[cfg(feature = "mlx-runtime")]` on the entire `mlx` module; the 5 provider tests remain. CI invokes both `cargo test -p stt-mlx` (default features) and `cargo test -p stt-mlx --no-default-features`. |

## Scope Guardrails (what this task does NOT do)

- ❌ Tauri command exposing transcript stream — T-1.6 (event bridge owns the pump loop + `transcript:chunk` event emission).
- ❌ Long-lived MLX subprocess (warm-loaded model) — Phase 1.x `T-1.5b` (Silero VAD + warm-load + `large-v3-turbo` upgrade).
- ❌ Streaming partial transcripts (`isFinal: false` updates while utterance-in-progress) — Phase 1 emits `is_final: true` per chunk; mlx-whisper doesn't expose token-streaming via subprocess. ARCH §3.2 "Streaming: chunked với 30s sliding window + VAD" is post-VAD work.
- ❌ Confidence calibration — `confidence = Some(1.0 - no_speech_prob)` is a rough proxy; Phase 2 detector uses it as one signal among many.
- ❌ Speaker diarisation — ARCH §10 schema has a `speaker` column; Phase 1 leaves it `None`. Diarisation is a Phase 4 stretch.
- ❌ Deepgram / ElevenLabs adapters — Phase 3 (`T-3.1` extracts the trait into a `providers/` module; this task already lands the trait shape).
- ❌ STT result persistence — T-1.12 (SQLite via `tauri-plugin-sql`) pulls `Vec<SttSegment>` + meeting/chunk IDs and writes to the `TranscriptChunk` table.
