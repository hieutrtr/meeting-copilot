# T-1.1 — Monorepo layout + shared TypeScript types

> **Phase**: 1 — MVP Local-only

## Goal

Establish the monorepo layout per ARCH App A and seed the **shared TypeScript types module** with the canonical entities the rest of Phase 1 will touch:

1. `TranscriptChunk` — emitted by STT pipeline, rendered by `TranscriptView` (T-1.7), persisted by T-1.12.
2. `MeetingSession` — top-level meeting record (`Meeting` in ARCH §10; loop driver names it `MeetingSession` so the runtime in-memory active-session shape and the persisted entity diverge cleanly later if needed).
3. `QAEntry` — paired `Question` + `Answer` row used by T-1.9 (mark-as-question), T-1.10 (Claude streaming), T-1.11 (AnswerPanel), T-1.12 (persist).
4. `Question`, `Answer`, `ContextSource` — sibling entities exported from the same module (used by T-1.8, T-1.10, T-1.12).

**Layout decision (per INDEX.md):** ARCH App A canonical
```
meeting-copilot/
├── src/                    React/TS frontend (Phase 0, unchanged)
├── src-tauri/              Tauri 2 host (Phase 0, unchanged)
├── crates/                 NEW — Cargo workspace members (filled in T-1.2+)
├── shared/                 NEW — TS-only types module (this task)
└── docs/
```

The user's loop prompt mentioned `app/`, `daemon/`, `shared/` as a possible layout. The INDEX picked ARCH App A because Phase 0's `src/` + `src-tauri/` already work and renaming them to `app/` is cosmetic churn. `daemon/` collapses into `crates/helper-daemon/` (T-1.2). This task only creates `shared/` + reserves `crates/`; actual Cargo workspace plumbing lands in T-1.2 alongside the first member crate.

## TDD Plan

### Test cases (Vitest, `shared/types.test.ts`)

1. **`exports TranscriptChunk with required fields`** — assigns a literal matching ARCH §3.1 (`text`, `isFinal`, `startTs`, `endTs`, plus `id` + `meetingId` for persistence per §10), asserts `text === "hello"`. Verifies the type is exported, importable via the `@shared/types` alias, and structurally compatible with the ARCH spec.
2. **`exports MeetingSession with required fields`** — assigns a literal matching ARCH §10 `Meeting` (`id`, `title`, `startedAt`, `status`), asserts `id === "m1"`. Verifies the loop's `MeetingSession` rename keeps ARCH semantics.
3. **`exports QAEntry pairing Question + Answer`** — assigns `{ question, answer: null }` (answer is null until T-1.10 streams a response), asserts `qa.answer === null`. Implicitly verifies `Question` shape (`id`, `meetingId`, `text`, `detectedTs`, `method`).

### RED → GREEN cycle

- **RED 1** (file missing): test file imports from `@shared/types` before `shared/types.ts` exists → `vitest` errors with module not found.
- **GREEN 1**: create `shared/types.ts` with all three named exports as the minimal interface bodies.
- **RED 2** (alias missing): even with the file present, vitest cannot resolve `@shared/types` → install vitest + add `vitest.config.ts` with the alias.
- **GREEN 2**: alias resolves, all three tests pass.
- **REFACTOR**: extract shared field shapes (e.g., `id: string`, ISO ms timestamps) consistently; no behavior change; tests stay green.

## Risk + Mitigation

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Vitest install breaks Tauri dev server (port/script conflict) | Low | Medium | Separate `vitest.config.ts` (not inlined into `vite.config.ts` which Tauri reads); `bun run tauri dev` script untouched. |
| Path alias `@shared/*` collides with future package or shadows a node_module | Low | Low | `@shared` is not a published npm scope; project-internal only. If conflict surfaces, rename to `@meeting-copilot/shared` later. |
| ARCH `Meeting` ↔ loop `MeetingSession` rename diverges from persisted SQLite schema (T-1.12) | Medium | Medium | T-1.12 review explicitly maps `MeetingSession` ↔ `Meeting` row; aliased export `Meeting = MeetingSession` ships in this task to keep the mapping trivial for any future contributor reading ARCH §10. |
| `noUnusedLocals` strict-mode breaks the test (typed-but-unused vars) | Low | Low | Tests `expect()` on at least one field per literal — variable is consumed. |
| Empty `crates/` dir gets pruned by git | Low | Low | `.gitkeep` placeholder + the dir is created by hand, so future T-1.2 just adds a sibling. |

## Scope Guardrails (what this task does NOT do)

- ❌ Cargo workspace wiring — deferred to T-1.2 (needs a real member crate first; empty `members = []` is a cargo error).
- ❌ `bun` workspaces / `package.json` workspace declaration for `shared/` — single-consumer, alias-only is sufficient.
- ❌ Runtime helpers (factories, validators, type guards) — pure types only; runtime logic accumulates in later tasks where it has callers.
- ❌ `ContextSource` schema deep-design (token-counting strategy etc.) — placeholder shape only; T-1.8 owns the field-level design.
