## Risks revisited

- **Front-end Start ≠ back-end pipeline start** — captured in §"Out-of-scope" of the task doc; T-1.13 owns the wiring of audio source → Chunker → SttProvider → EventBridge driven by the Start action. The current Start click only flips front-end state (and would later carry an IPC call). For PHASE-BROWSER-TEST.md, Start currently shows `meeting:state` events only when T-1.13 lands.
- **`lastN = 3` heuristic** — works for the demo (a question is usually 1-2 sentences ≈ 2-3 chunks at 2-second windows). Phase 1.x can switch to `markRangeByTime(now - Δ, now)` once we have user feedback on what feels right.
- **Disabling Start without context** — `PHASE-BROWSER-TEST.md` step 2 documents the constraint. If a reviewer wants to test STT alone without a PRD they can paste the path of any small `.txt` file (or we can relax the gate in Phase 1.x with a "no context, ask anyway" toggle).
- **Question accumulates unbounded memory** — Phase 1 demos cap at ~30 marks per session. Phase 1.x trims old questions once T-1.10 sends them to Claude (status flips to `answered`).
- **`crypto.randomUUID()` undefined under jsdom < 19** — fallback uses `Date.now() + Math.random()` which is good enough for an in-process dev tool. Tested implicitly by MS-S2-auto-id (passes under the project's jsdom).
