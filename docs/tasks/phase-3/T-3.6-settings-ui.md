## Goal

Add a **Settings sheet** UI surface with three new controls — (1) STT provider picker, (2) per-provider API key field, (3) "Test connection" button — and bump the persisted settings schema from `:v1` to `:v2` with a first-read migration. The picker and key fields persist through the existing store; "Test connection" round-trips a tiny request through an injectable adapter and surfaces a success/fail toast within 3 s.

Privacy mode constraints (Local-first → MLX only; Cloud → unlocks Deepgram + ElevenLabs) are wired in T-3.8. Advanced model knobs (Deepgram `tier`, ElevenLabs `voice_id`) are explicitly deferred to Phase 3.x.

## Design

### 1. Settings store v2 schema

```ts
export const SETTINGS_STORAGE_KEY = "meeting-copilot:settings:v2";
export const LEGACY_SETTINGS_STORAGE_KEY = "meeting-copilot:settings:v1";

export interface SettingsApiKeys {
  deepgram: string;
  elevenlabs: string;
}

export interface SettingsValues {
  // v1 (carry-forward, byte-identical defaults)
  haikuConfidenceCutoff: number;
  haikuEnabled: boolean;
  silenceThresholdMs: number;
  costGuardThresholdUsdPerHour: number;
  costGuardPaused: boolean;
  // v2 additions (T-3.6)
  sttProvider: SttProviderId;
  apiKeys: SettingsApiKeys;
}

export const SETTINGS_DEFAULTS: SettingsValues = {
  // ...v1 defaults verbatim
  sttProvider: "mlx",
  apiKeys: { deepgram: "", elevenlabs: "" },
};
```

Migration:

- On `loadFromStorage`, attempt v2 key first. If absent, attempt v1; if v1 present, parse + lift fields into v2 shape (zero-filling new keys with defaults), write v2 back, leave v1 in place (non-destructive — survives a downgrade roll-back).
- The migration is a pure function `coerceLoaded` extension (no time-of-day / Math.random) — testable in isolation.

API key storage:

- Strings stored verbatim in `localStorage` under `apiKeys.deepgram` / `apiKeys.elevenlabs`. Empty string means "use env-var default at adapter construction time" (the Rust factory already falls back to `DEEPGRAM_API_KEY` / `ELEVENLABS_API_KEY`).
- The Tauri keychain swap-in is gated behind `defaultStorage()` (one place to change). Tracked as Phase 3.x follow-up; not in T-3.6 scope.

### 2. Test Connection seam

```ts
// src/settings/testConnection.ts
export interface TestConnectionResult {
  ok: boolean;
  message: string;
  latencyMs: number;
}

export type TestConnectionFn = (
  provider: SttProviderId,
  apiKey: string,
) => Promise<TestConnectionResult>;

export const defaultTestSttConnection: TestConnectionFn = async (
  provider,
  apiKey,
) => { /* env-aware stub; live impl in T-3.10 follow-up */ };
```

The component takes `testConnection?: TestConnectionFn` as a prop (defaults to the stub). RTL tests pass a deterministic mock.

- The picker `<select>` has `data-testid="settings-provider-select"`.
- The API key `<input type="password">` has `data-testid="settings-api-key-input"`.
- The Test button has `data-testid="settings-test-connection-button"`.
- The status pill has `data-testid="settings-test-connection-status"` + `data-status="idle|pending|success|fail"`.

### 4. Forward-compat with T-3.8 (privacy modes)

T-3.8 will:

- Add a `privacyMode` field to the v2 schema (v3 bump only if shape changes incompatibly — T-3.6 leaves room by NOT freezing v2 in stone).
- Compute the **available** provider set as a pure function `availableProvidersForMode(mode)` and feed it to this component as a prop (or via a selector).
- Disable the picker option + show a tooltip on options outside the available set.

T-3.6 lays the groundwork by keeping the picker rendering a pure function of `STT_PROVIDER_IDS` — T-3.8 will swap the source list to `availableProvidersForMode(privacyMode)` without touching the component's render tree.

## Risk + mitigation

| # | Risk | Mitigation |
|---|---|---|
| R-3.6-1 | **Schema migration corrupts existing v1 data.** A user with v1 settings sees defaults instead of their saved values. | SS-S34 asserts v1 → v2 round-trip preserves every v1 field byte-identically. v1 key is left in place (non-destructive) so a downgrade roll-back recovers. |
| R-3.6-2 | **API key leaks into logs / telemetry.** A future telemetry ticket might serialize the settings snapshot wholesale. | Privacy audit in `T-3.6-review.md` documents that `apiKeys` must NOT appear in telemetry log lines. T-3.9 will enforce via grep test. |
| R-3.6-3 | **Test Connection blocks UI.** Network roundtrip stalls render. | Button + pill use the standard async-task pattern (state machine `idle → pending → ok/fail`), debounced. Mock RTL test asserts no double-fire. |
| R-3.6-4 | **Scope creep into model knobs.** Tier / voice_id / sample-rate dropdowns. | Out-of-scope per AC; documented above. T-3.10 carries forward to Phase 3.x backlog. |
| R-3.6-5 | **Provider ID drift between TS and Rust.** Picker option strings must match `ProviderKind::as_str()`. | Picker reads from `STT_PROVIDER_IDS` (T-3.5), which is parity-tested via ST-S9. No new strings in T-3.6. |
