## Goal

Add a per-provider STT cost calculator that consumes audio-seconds against an active `ProviderKind` and produces a running USD total + projected $/h. Surface its updates as a snapshot stream so Phase 3 T-3.6 (Settings UI) can render a live cost meter and Phase 3 T-3.9 (telemetry) can audit provider switches without depending on the LLM-side cost guard internals.

## Design

### 1. Rate table (`src/llm/sttPricing.ts`)

```ts
export const DEEPGRAM_USD_PER_MINUTE = 0.0043 as const;       // ARCH §3.2 line 113
export const ELEVENLABS_USD_PER_HOUR = 0.40 as const;          // ARCH §3.2 line 119
export const ELEVENLABS_USD_PER_MINUTE = ELEVENLABS_USD_PER_HOUR / 60;

export const STT_PROVIDER_USD_PER_MINUTE = {
  mlx: 0,
  fake: 0,
  deepgram: DEEPGRAM_USD_PER_MINUTE,
  elevenlabs: ELEVENLABS_USD_PER_MINUTE,
} as const;

export type SttProviderId = keyof typeof STT_PROVIDER_USD_PER_MINUTE;

export function computeSttCostUsd(provider: SttProviderId, audioSeconds: number): number;
```

- Constants pinned to ARCH §3.2 quoted prices; cross-link comment carries the line numbers + a TODO on `provider-comparison.md` (T-3.10) so a price drift is one-grep findable.
- IDs (`mlx`, `fake`, `deepgram`, `elevenlabs`) match the Rust `ProviderKind::as_str()` returned by `crates/stt-mlx/src/providers/mod.rs:67`. Drift here breaks settings persistence — covered by a parity test.
- `computeSttCostUsd` clamps negative `audioSeconds` to 0 (defensive — `(endTs - startTs)` may go negative on out-of-order chunks).

### 2. Calculator (`src/cost/sttCostMeter.ts`)

Closure-scoped counter, identical pattern to `costGuard.ts:96`:

```ts
export interface SttProviderCounter {
  audioSeconds: number;
  costUsd: number;
}

export interface SttCostSnapshot {
  activeProvider: SttProviderId | null;
  perProvider: Record<SttProviderId, SttProviderCounter>;
  totalAudioSeconds: number;
  totalCostUsd: number;
  elapsedMs: number;
  projectedCostPerHourUsd: number;
}

export interface SttCostMeter {
  setActiveProvider(provider: SttProviderId): SttCostSnapshot;
  getActiveProvider(): SttProviderId | null;
  recordAudioSeconds(audioSeconds: number, providerOverride?: SttProviderId): SttCostSnapshot;
  recordTranscriptChunk(chunk: TranscriptChunk, providerOverride?: SttProviderId): SttCostSnapshot;
  snapshot(): SttCostSnapshot;
  reset(): void;
}

export function createSttCostMeter(opts?: CreateSttCostMeterOptions): SttCostMeter;
```

Invariants (carry-forward from `costGuard.ts:1-22`):

1. Counters are closure-scoped — no module mutable state.
2. `snapshot()` returns defensive copies so React `useState` comparisons stay shallow-safe.
3. `recordTranscriptChunk` uses `(chunk.endTs - chunk.startTs) / 1000` for seconds; non-positive durations are no-ops (segment is dropped from the meter, not from the transcript stream).
4. `recordAudioSeconds` without an active provider AND without an override is a no-op (returns current snapshot unchanged); never throws on the hot path.
5. `setActiveProvider` is **stateful** — subsequent `recordAudioSeconds` without override use this provider. Switch is instantaneous; previously-recorded seconds remain attributed to the prior provider.
6. `onUpdate(snapshot)` fires after every state-mutating call (record/setActive/reset) with the **already-built** snapshot — a single allocation per event, no double-snapshot.
7. Projection uses `(totalCostUsd / elapsedMs) * 3_600_000`, gated by `minElapsedMsForProjection` (default 60_000 ms — matches `costGuard.ts:31` warm-up). Returns 0 inside warm-up.

### 3. Stream wiring (`src/cost/attachSttCostMeter.ts`)

```ts
export async function attachSttCostMeter(
  meter: SttCostMeter,
  opts?: { providerForChunk?: (chunk: TranscriptChunk) => SttProviderId | null },
): Promise<UnlistenFn>;
```

- Subscribes via `subscribeTranscriptStream` (Phase 1 T-1.6 seam — already mocked in vitest).
- Each chunk is routed to `meter.recordTranscriptChunk(chunk, providerOverride)`. The default `providerForChunk` returns `null` (i.e. trust the meter's `activeProvider`), which is the path Settings UI (T-3.6) will use after `setActiveProvider` on picker change. Custom resolver supports forward-compat with `TranscriptChunk` carrying a `provider` field if T-3.6 / T-3.9 wants per-segment attribution.
- Returns the inner `UnlistenFn` verbatim so the caller can clean up on unmount.

### 4. Forward-compat with the LLM cost guard

The Settings sheet (T-3.6) will compose two snapshots — the LLM-side `costGuard.snapshot()` and the STT-side `sttCostMeter.snapshot()` — and display `total = guard.totalCostUsd + meter.totalCostUsd` plus `projected $/h = sum of both projections`. That composition is intentionally outside this task: the meter is unit-testable in isolation, and the cost guard's existing 30 tests stay byte-identical.

## Risk + mitigation

| # | Risk | Mitigation |
|---|---|---|
| R-3.5-1 | **Pricing drift.** Deepgram or ElevenLabs revises rates between now and ship. | Constants pinned + cross-linked to ARCH §3.2 line numbers; T-3.10 `provider-comparison.md` bakes a single source of truth that gets updated next price snapshot. |
| R-3.5-2 | **Provider ID drift between Rust + TS.** `ProviderKind::as_str()` and `SttProviderId` keys must match for settings persistence (T-3.6 v2 schema). | ST-S9 assertion + comment cross-link in `sttPricing.ts`. |
| R-3.5-3 | **Negative / out-of-order chunk durations.** `(endTs - startTs)` may underflow if the helper-daemon emits late-arriving partials. | Non-positive durations are no-ops in `recordTranscriptChunk` (SCM-S10 + ST-S7). |
| R-3.5-4 | **Floating-point drift on cumulative sum.** Long meetings (8 h × 60 min × $0.0043) ≈ $2.06 — within `Number` precision; tests assert with `toBeCloseTo(_, 9)`. | Existing `costGuard` uses 12-decimal closeness; STT meter uses 9 (matches the smaller magnitude). |
| R-3.5-5 | **Hot path overhead in `onUpdate`.** Could allocate a snapshot per chunk × 30 chunks/min × 60 min = 1800 allocs/h. | `onUpdate` is opt-in; callers that don't pass it get zero allocation. The closure path is one O(1) read of the snapshot — measured by SCM-S16 firing parity, no profiling required at this scale. |
