## Goal

Ship a sync, per-chunk ElevenLabs Scribe streaming STT adapter that plugs into the
`SttProvider` trait extracted by T-3.1 and behaves operationally identical to the
Deepgram adapter (T-3.2 + T-3.3) so the helper-daemon's hot-swap pattern
(`Mutex<Box<dyn SttProvider>>`) treats both cloud providers as substitutable.

End-state:

1. A new module `crates/stt-mlx/src/providers/elevenlabs.rs` holding `ElevenLabsConfig`
   + `ElevenLabsAdapter` (the latter implements `SttProvider`).
2. A new `elevenlabs` cargo feature, default-on at the crate level (matches the
   `deepgram` feature pattern); helper-daemon stays `default-features = false` until
   T-3.6 wires the picker.
3. `ProviderKind::ElevenLabs` + `ProviderConfig::ElevenLabs(ElevenLabsConfig)` variants
   wired into `factory(...)`. Persisted-settings string ID = `"elevenlabs"` (used by
   `as_str()`, telemetry log lines, and the `v2` settings migration in T-3.6).
4. A typed-error path when `ELEVENLABS_API_KEY` is missing/empty:
   `SttError::Config("ELEVENLABS_API_KEY missing or empty")` surfaces at construction
   time, before any network IO. Settings UI (T-3.6) maps this to a "missing API key"
   tooltip on the picker entry; the privacy-mode constraint (T-3.8) maps it to a
   greyed-out option.
5. A mocked-WebSocket structural test driving the full adapter→server round-trip with
   a golden Scribe `transcription` envelope, asserting:
   - The upgrade request carries `xi-api-key: <key>` (raw key, no prefix — distinct
     from Deepgram's `Authorization: Token <key>`).
   - PCM is sent as a binary frame (linear16 little-endian, same wire format as
     Deepgram).
   - Interim hypotheses (`is_final = false`) are filtered (Phase 2 question detector
     reads only finalized strings).
   - Non-`transcription` envelopes (`metadata`, `ping`) are filtered.
   - Empty / whitespace-only `transcript` field is filtered.
   - Finalized JSON → `SttSegment { text, start_ts_ms, end_ts_ms, is_final = true,
     confidence = language_probability }` with timestamps offset against the first
     chunk's `ts_ms` (session base — same anchoring rule as Deepgram).
6. Bounded-reconnect path via the shared `BackoffConfig` (relocated from
   `providers::deepgram` to `providers::backoff` so the type isn't gated on the
   `deepgram` feature). Operational reuse of T-3.3's schedule math; the schedule's
   pure unit tests stay where they were authored (in `providers::deepgram::tests`).
   T-3.4 adds two operational tests that exercise the reuse on the ElevenLabs side
   so a future change to one adapter's connect path doesn't silently degrade the
   other.

### ElevenLabs Scribe — endpoint shape

Per ARCH §3.2 (lines 116–120) — Streaming Scribe model, ~200 ms latency, ~$0.40/hour,
cloud privacy:

```
wss://api.elevenlabs.io/v1/speech-to-text/scribe-v1/stream?sample_rate=16000&model_id=scribe_v1
xi-api-key: <ELEVENLABS_API_KEY>
```

The adapter sends PCM as binary frames (linear16 LE i16, same format as Deepgram);
ElevenLabs replies with text frames containing JSON envelopes:

```json
{
  "type": "transcription",
  "is_final": true,
  "transcript": "What time is the meeting?",
  "start_time": 1.5,
  "end_time": 3.8,
  "language_probability": 0.987
}
```

`type` may also be `metadata`, `ping`, `error`, etc — non-`transcription` envelopes
are silently dropped. For `transcription`, the adapter ignores `is_final = false`
(interim) and only emits when `is_final = true` AND `transcript` is non-empty after
trimming.

**Documented-at-runtime caveat**: The Scribe streaming API is newer (2025) than the
Deepgram one and may continue to iterate. The adapter's expected envelope shape lives
in `EsEnvelope` + `parse_transcription` (one file) so when the live API drifts, this
is the single point that needs updating. `provider-comparison.md` (T-3.10) will
reference this file as the canonical record for the version T-3.4 targets.

### Trait shape — streaming source through a sync per-chunk API

Identical contract to the Deepgram adapter (T-3.2 §"Trait shape" — §3.1's async-stream
shape is the IPC contract for the helper-daemon, not the per-provider trait):

1. Lazy-connect on first call (so `new()` doesn't bind a socket ahead of `start`).
2. Encode the chunk to little-endian i16 PCM and send as a binary frame.
3. Drain pending text frames using a short read timeout (`read_drain_timeout`,
   default 50 ms); for each `transcription` envelope with `is_final = true` and
   non-empty trimmed `transcript` build an `SttSegment` and push to the result vector.
4. Return the drained vector. Many calls return `vec![]` (Scribe batches across
   utterance boundaries).

**Timestamp policy**: Scribe's `start_time` and `end_time` fields are absolute
session-relative seconds (offset from when *Scribe* started receiving audio = our
first chunk's send). The adapter records the first chunk's `ts_ms` as
`session_base_ts_ms`; segment timestamps are
`session_base_ts_ms + Scribe.start_time * 1000` and
`session_base_ts_ms + Scribe.end_time * 1000`. Best-effort heuristic — within ~200 ms
on localhost. Identical anchoring rule to Deepgram; the only difference is Scribe
emits `end_time` directly (Deepgram emits `start + duration`), which is a parser-side
detail not a contract change.

**Confidence policy**: Scribe surfaces `language_probability` as a per-utterance
proxy for confidence (no separate `confidence` field at this version). Threading
through to `SttSegment.confidence` lets the question-detector dedup window (T-2.4)
and cost-meter bucketing (T-3.5) read a uniform `confidence` shape across both cloud
providers.

## API-Key Handling

`api_key` is read from `ELEVENLABS_API_KEY` env var via `ElevenLabsConfig::default()`
or set explicitly by callers. Sent only over the WebSocket upgrade `xi-api-key`
header, never logged. `SttError::ProviderUnavailable.last_error` carries the
underlying `tungstenite::Error` display string, which does **not** include header
values. T-3.9 telemetry will explicitly grep for `xi-` substrings in addition to
`Token ` (T-3.3's defense-in-depth assertion) so neither provider's key leaks into
log lines.

The construction-time `SttError::Config("ELEVENLABS_API_KEY missing or empty")` does
not include the (zero-length / `None`) key — the error message is a static string
referencing the env var name. Settings UI (T-3.6) maps this to a "no API key set"
tooltip.
