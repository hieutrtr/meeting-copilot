## Spec — `docs/ARCHITECTURE.md` Phase 3 addendum

### Where each addendum block lands

The existing ARCH stays untouched. Each Phase 3 update block sits **after** the section it amends, separated by a `---` divider, and starts with a verbatim header:

```
### 3.4 Phase 3 update — Provider trait + factory (T-3.1..T-3.4)
```

Five addendum blocks total:

1. **§3.4 Phase 3 update — Provider trait + factory.** Documents:
   - Trait + factory live in `crates/stt-mlx/src/providers/` (T-3.1: `mod.rs`, `mlx.rs`).
   - `factory(kind, cfg) -> Result<Box<dyn SttProvider>, FactoryError>` + `factory_with_privacy(mode, kind, cfg)` (privacy short-circuit, T-3.8).
   - Deepgram WebSocket adapter at `providers/deepgram.rs` (T-3.2) — `wss://api.deepgram.com/v1/listen?model=nova-2&...`. Reconnect/backoff at `providers/backoff.rs` (T-3.3, reused by ElevenLabs).
   - ElevenLabs Scribe adapter at `providers/elevenlabs.rs` (T-3.4) — `wss://api.elevenlabs.io/v1/speech-to-text/scribe-v1/stream`, `xi-api-key` auth.
   - `tungstenite = 0.21` is the only new transport dep (handshake + framing). TLS / production reconnect deferred to Phase 3.x.

2. **§4.x Phase 3 update — TTS feature flag (T-3.7).** Documents:
   - Cargo `tts` feature default OFF (`crates/stt-mlx/Cargo.toml`); zero new deps. TS gate `VITE_ENABLE_TTS` (default off) read by `src/tts/featureFlag.ts`.
   - ElevenLabs TTS adapter at `crates/stt-mlx/src/tts/elevenlabs.rs` (Rust, transport-injected) + `src/tts/elevenLabsTts.ts` (TS, prop-injected `fetch`).
   - `<AnswerPanel/>` Speak button rendered iff `onSpeak` prop is passed; App.tsx gates the prop on `ENABLE_TTS && isTtsAllowed(privacyMode)` so default builds tree-shake the TTS modules out of the initial bundle.
   - BlackHole virtual-output routing (existing §4 paragraph) stays a **v2 deliverable** — Phase 3 ships local-speaker output only.

3. **§11.x Phase 3 update — Privacy mode constraint enforcement (T-3.8).** Documents:
   - Default mode is `"local-first"` (privacy-by-default). Audio never leaves the machine in this mode.
   - 3×3 STT constraint matrix lives in `src/privacy/privacyMode.ts` (TS, single source of truth) and `crates/stt-mlx/src/providers/privacy.rs` (Rust mirror).
   - `factory_with_privacy(mode, kind, cfg)` short-circuits **before** construction — privacy violation cannot be bypassed by skipping UI checks. New `FactoryError::PrivacyModeViolation { mode, kind }` variant.
   - Cloud mode mounts a red `role="alert"` consent banner above `<TranscriptView/>` (`<CloudConsentBanner/>`); Local-first / Mixed render none.
   - "Off the record" 30-s drop window (existing §11 paragraph) stays a **v2 deliverable** — Phase 3 ships mode picker + constraint enforcement only.

4. **§14 Telemetry (NEW, T-3.9).** Documents:
   - Opt-in only. Default `telemetryEnabled = false` in the settings store (`src/store/settingsStore.ts`).
   - Three event types: `provider_switch`, `stt_error`, `stt_latency`. Each event is scrubbed via `src/telemetry/scrub.ts` against a fixed `FORBIDDEN_KEYS` list (`text`, `transcript`, `pcm`, `audio`, `apiKey`, `api_key`, `key`, `secret`, `token`, `password`).
   - Allow-list of top-level event fields: any unknown field fails closed (the whole event drops).
   - Rotating in-memory sink at `src/telemetry/sinks.ts` — UTF-8 byte counted, default 10 MB cap, max 3 archives → ~30 MB worst-case.
   - Tauri-fs sink + live wire-up to provider event stream is **Phase 3.x** (deferred). The unit gate is the calculator + scrub + rotate cadence.

5. **§15 Cost meter (NEW, T-3.5).** Documents:
   - Per-provider rate table at `src/llm/sttPricing.ts` (constants pinned to ARCH §3.2 lines 113 + 119): MLX = $0, Deepgram = $0.0043/min, ElevenLabs = $0.40/h.
   - `src/cost/sttCostMeter.ts` exposes `onUpdate` event sink + cumulative session $ + per-provider attribution.
   - Wired to existing `transcript:chunk` Tauri stream via `src/cost/attachSttCostMeter.ts` — Phase 1 T-1.6 seam preserved.
   - Cost-guard threshold (T-2.7) reused — no new threshold logic.

Each addendum cross-references the implementation file by relative path so a reader can jump straight from spec to code.

## Spec — `docs/provider-comparison.md`

A new top-level doc (sibling to ARCH, PRD, IMPLEMENTATION-PLAN). Targets:

- **Audience:** contributor evaluating "which provider should I default to?" and security reviewer auditing "what data leaves the machine?".
- **Length:** ~150–200 lines. Not a tutorial; a comparison table + per-provider notes.

### Required sections

1. **Header + scope.** "What this doc is" / "What this doc is not" — one paragraph each.
2. **STT provider comparison table.** Columns: `Provider | Latency (partial / final) | Cost | Privacy posture | Languages | Streaming | API maturity | Auth | Default`. Rows: MLX, Deepgram, ElevenLabs Scribe.
3. **TTS provider comparison table.** Columns: `Provider | Latency (first audio) | Cost | Privacy posture | Voice library | Audio format | Default`. Rows: ElevenLabs (only TTS impl shipped).
4. **Per-provider notes.** Six subsections — one per (3 STT + 1 TTS + 1 "future" + 1 "selecting a provider" decision-tree). Each STT subsection contains: endpoint, framing, auth, env var, implementation file path, test coverage count, known limitations.
5. **Privacy posture matrix.** 3 modes × 3 STT providers × 1 TTS — links to `src/privacy/privacyMode.ts` for the runtime source of truth. Echoes ARCH §11 verbatim, then cross-references the Rust mirror at `crates/stt-mlx/src/providers/privacy.rs`.
6. **Cost reference.** Pulls the rate table verbatim from `src/llm/sttPricing.ts`. One worked example per provider (60-min meeting at default privacy).
7. **Setup steps.** For each cloud provider: env var name, where to obtain a key, how the UI's "Test connection" button works, what a successful test looks like.
8. **API maturity caveats.** Documented endpoint pin per provider + drift mitigation (where the constant lives, which test gates it).
9. **References.** Cross-links to ARCH, IMPLEMENTATION-PLAN, the per-task review docs, and the upstream provider docs.

### Source-of-truth rule

Every numeric in the doc (cost rate, latency target, max bytes, retry attempts) cites the implementation file/line where the constant lives, **not** a fresh value the doc invents. If the docs and the code drift, the code wins; the doc breaks first (tested by `bun run typecheck` + future eyeball review).
