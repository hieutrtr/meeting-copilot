## Goal

Add a **Privacy Mode picker** with three modes (Local-first / Cloud / Mixed) that constrains which STT (and TTS) providers may be selected. The constraint is enforced **twice** — by the UI (disabled options + tooltips + auto-revert when current selection becomes disallowed) and by the **Rust factory backend** (a new `factory_with_privacy(mode, kind, cfg)` seam that returns a typed error on violations). UI gating alone is not sufficient — a user who hand-edits `localStorage` or bypasses the picker via a future Tauri-command call must still be blocked by the backend.

Default mode for new users is **Local-first** (MLX only, $0, audio never leaves the machine), per ARCH §11 + plan note "Privacy mode default: Local-only (MLX) cho user mới — opt-in cloud explicit".

When mode is `Cloud`, App.tsx renders a red consent banner at the top of the transcript view ("Cloud mode — full audio is being sent to your STT provider; obtain participant consent.") per ARCH §11 line 405.

## Design

### 1. Constraint matrix (single source of truth)

```ts
// src/privacy/privacyMode.ts
export type PrivacyMode = "local-first" | "cloud" | "mixed";
export const PRIVACY_MODES: readonly PrivacyMode[] = Object.freeze([
  "local-first",
  "cloud",
  "mixed",
]);

// MLX + fake are always allowed (local stubs / local model). Deepgram + ElevenLabs
// are cloud STT providers — disallowed in Local-first and Mixed (Mixed = local STT
// + cloud TTS only, per ARCH §11 line 403).
const STT_MATRIX: Record<PrivacyMode, ReadonlySet<SttProviderId>> = {
  "local-first": new Set(["mlx", "fake"]),
  "cloud":       new Set(["mlx", "fake", "deepgram", "elevenlabs"]),
  "mixed":       new Set(["mlx", "fake"]),
};

// Cloud TTS allowed in Cloud + Mixed (per ARCH §11 line 403); blocked in Local-first.
const TTS_ALLOWED: Record<PrivacyMode, boolean> = {
  "local-first": false,
  "cloud":       true,
  "mixed":       true,
};
```

The pure helpers `isSttProviderAllowed(mode, provider)`, `isTtsAllowed(mode)`, and `availableSttProviders(mode)` consume the matrices; the matrices are not exported (callers must go through the helpers so behavior changes flow through one seam).

The picker tooltip is composed from a stable `(mode, blockedProvider) → string` table:

```ts
"Deepgram is a cloud STT — switch to Cloud mode or pick MLX (local)."
```

### 2. Auto-revert guard

When `setPrivacyMode(next)` is called and the current `sttProvider` is not in `STT_MATRIX[next]`, the store **also** sets `sttProvider = "mlx"` in the same `set()` call (single re-render, single persistence write). This avoids the inconsistent state where the UI shows e.g. `sttProvider="deepgram"` + `privacyMode="local-first"` after a mode switch.

The auto-revert is tested by SS-S38: switch `local-first → cloud`, set provider to `deepgram`, switch back to `local-first` → `sttProvider` snaps to `"mlx"`.

### 4. Backend enforcement (`factory_with_privacy`)

```rust
// crates/stt-mlx/src/providers/privacy.rs
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub enum PrivacyMode { LocalFirst, Cloud, Mixed }

pub fn is_provider_allowed(mode: PrivacyMode, kind: ProviderKind) -> bool {
    match (mode, kind) {
        (_, ProviderKind::Mlx) | (_, ProviderKind::Fake) => true,
        (PrivacyMode::Cloud, ProviderKind::Deepgram) => true,
        (PrivacyMode::Cloud, ProviderKind::ElevenLabs) => true,
        _ => false,
    }
}

pub fn factory_with_privacy(
    mode: PrivacyMode, kind: ProviderKind, cfg: ProviderConfig,
) -> Result<Box<dyn SttProvider>, FactoryError> {
    if !is_provider_allowed(mode, kind) {
        return Err(FactoryError::PrivacyModeViolation { mode, kind });
    }
    factory(kind, cfg)
}
```

Short-circuiting before `factory(…)` means a forbidden cell (e.g. Local-first + Deepgram) never opens a WS handshake or reads `DEEPGRAM_API_KEY` — privacy-by-construction at the seam.

### 5. ProviderKind ↔ SttProviderId parity

The TS matrix keys (`"mlx" | "fake" | "deepgram" | "elevenlabs"`) and the Rust `ProviderKind::as_str()` outputs already match (gate test `factory_kind_as_str_stable` in `providers/mod.rs`). T-3.8 adds two parity gates:

- TS: `availableSttProviders("cloud")` returns exactly `STT_PROVIDER_IDS` (every provider).
- Rust: a constraint test asserts `is_provider_allowed(PrivacyMode::Cloud, kind)` is `true` for every `ProviderKind` variant.

- `.settings-sheet__privacy-row` — same shape as the existing rows.
- `.settings-sheet__select option:disabled` — browser default greys it out; tooltip via `title` attr.

## Risk + mitigation

| # | Risk | Mitigation |
|---|---|---|
| R-3.8-1 | UI gating bypassed via direct `localStorage` edit or future Tauri-command call | Backend `factory_with_privacy` is the second gate. Six cargo tests prove it short-circuits before any construction side-effect. |
| R-3.8-2 | Auto-revert silently changes provider, surprises the user | `setPrivacyMode` writes both fields; SS-S38 is the test gate. The picker re-renders on the same tick so the user sees the new selection. UX note: a follow-up could surface a toast — tracked for T-3.x polish. |
| R-3.8-3 | Cloud banner wording drifts from ARCH §11 | CB-U1 asserts the verbatim wording; ARCH §11 line 405 is the source of truth. |
| R-3.8-4 | Constraint matrix drifts between TS and Rust | Two parity-gate tests: TS `availableSttProviders("cloud")` ≡ `STT_PROVIDER_IDS`; Rust `is_provider_allowed(Cloud, *)` ≡ all variants. ProviderKind::as_str() ↔ SttProviderId parity (already covered by T-3.5 ST-S9). |
| R-3.8-5 | `is_provider_allowed` panics on unknown variant | The match is exhaustive; adding a new `ProviderKind` variant breaks compilation in `privacy.rs` — caught by the Rust compiler, not at runtime. |
