## Goal

Extract a clean **provider factory** seam in `crates/stt-mlx/` so subsequent Phase 3 adapters
(Deepgram T-3.2, ElevenLabs T-3.4) plug in without rippling import paths through
`helper-daemon` or `src-tauri`. Concretely:

1. **Relocate** the existing MLX impl from `crates/stt-mlx/src/mlx.rs` → `crates/stt-mlx/src/providers/mlx.rs`.
2. **Add** `crates/stt-mlx/src/providers/mod.rs` with:
   - `ProviderKind` (flat enum — variants for `Mlx`, `Fake`; T-3.2/T-3.4 add `Deepgram` / `ElevenLabs`).
   - `ProviderConfig` (per-variant payload, `mlx-runtime`-feature-gated for the MLX cell).
   - `FactoryError` (`ProviderDisabled` / `ConfigMismatch` / `Stt`).
   - `pub fn factory(kind, cfg) -> Result<Box<dyn SttProvider>, FactoryError>` — single seam.
3. **Keep the public surface byte-identical**: `stt_mlx::{SttProvider, SttSegment, SttError, FakeStt, MlxConfig, MlxWhisperSubprocess}` continue to resolve via `lib.rs` re-exports, so the existing
   `helper-daemon::bridge` import (`use stt_mlx::{SttError, SttProvider}; … use stt_mlx::FakeStt;`)
   needs no changes.

The `SttProvider` trait itself was already authored in Phase 1 T-1.5 (`crates/stt-mlx/src/provider.rs`)
with the explicit Phase 3 hot-swap shape (`Box<dyn SttProvider>` + `Send`). T-3.1 does **not**
change the trait — it only adds the construction seam around it.

### Layout decision (locks INDEX line 8 ambiguity)

The plan literal says `daemon/src/providers/{mlx,deepgram,elevenlabs}.rs`; the actual Phase 1/2
layout is `crates/stt-mlx/`. Two options were on the table per INDEX line 8:

- **(A)** Add `providers/` as a sub-module **inside** the existing `stt-mlx` crate.
- **(B)** Spin up a sibling crate `crates/stt-providers/` and move the MLX impl into it.

T-3.1 picks **(A)**. Rationale:

- Zero churn for downstream import paths — `stt_mlx::SttProvider` keeps working byte-identically.
- The `stt-mlx` crate is already feature-gated (`mlx-runtime` default-on); the same gate cleanly
  scopes MLX-specific code in `providers::mlx`. Helper-daemon already builds with
  `default-features = false`, so the Mlx variant of `ProviderConfig` is dead-stripped out of that
  build — exactly the shape the factory expects.
- A future rename to `crates/stt-providers/` (or a sibling crate) is a mechanical `git mv` once
  Deepgram + ElevenLabs are also living under `providers/`. Phase 3.x decision; not blocking now.

The crate **name** `stt-mlx` is a known minor mis-naming after T-3.2/T-3.4 — documented as a
follow-up in the Phase 3 sign-off. Renaming the crate now would force a `Cargo.toml` edit in
`helper-daemon` + `src-tauri` workspace pin + re-baseline of every Phase 1/2 cargo test, which
violates the T-3.1 "relocation only, no signature changes" risk-budget.

## TDD Plan

### Test cases (Rust, `crates/stt-mlx/src/providers/mod.rs#tests`)

The factory tests are pure — they exercise `Box<dyn SttProvider>` end-to-end through `FakeStt`
(no Python / no MLX subprocess). The MLX-specific test (`factory_mlx_constructs_subprocess_struct`)
construction-only smoke runs without spawning Python.

1. **`factory_kind_as_str_stable`** — Settings persist `ProviderKind` as `"mlx"` / `"fake"` strings (T-3.6 store v2 schema). Locking the literals here means any future rename surfaces as a test diff.
2. **`factory_fake_returns_boxed_trait_object`** — Asserts `factory()` hands back a value typed as `Box<dyn SttProvider>` (compile-time + runtime call through the boxed pointer).
3. **`factory_fake_honours_fixed_text_override`** — `FakeConfig::fixed_text = Some(...)` threads through to the produced segment text + timestamps match `FakeStt`'s contract.
4. **`factory_kind_config_mismatch_is_typed_error`** — `(ProviderKind::Mlx, ProviderConfig::Fake(_))` returns either `ConfigMismatch` (when `mlx-runtime` on) or `ProviderDisabled(Mlx)` (when off). Both branches asserted via `#[cfg]` arms.
5. **`factory_fake_byte_identical_to_direct_construction`** — Equality (`assert_eq!`) of `Vec<SttSegment>` produced by direct `FakeStt::new()` vs `factory(Fake, FakeConfig{fixed_text: Some(_)})`. **This is the core regression test for T-3.1**: any factory-side transformation would diverge here.
6. **`factory_preserves_text_for_phase2_question_detector`** — Drives a `?`-terminated English question through the factory's boxed provider; asserts segment text round-trips verbatim. The Phase 2 question detector (`src/detector/heuristic.ts` T-2.1) reads exactly this string out of the helper-daemon's `transcript:chunk` event; T-3.1 must not perturb it.
7. **`factory_output_is_send_and_swappable_under_mutex`** — Stuff a `Box<dyn SttProvider>` from `factory(Fake, …)` into `Mutex<Box<dyn SttProvider>>`, swap it for a fresh factory result, and assert the new provider's output. This is the hot-swap primitive the helper-daemon's runtime-switch and the T-3.6 settings UI build on.
8. **`factory_mlx_constructs_subprocess_struct`** — Construction-only smoke. Verifies `factory(Mlx, MlxConfig{work_dir: …})` writes `transcribe.py` and reports `name() == "mlx-whisper"`. Does **not** spawn Python.

### RED → GREEN trace

This is a refactor — there's no RED. The Phase 1 tests (`crate::provider::tests`,
