## Why feature-flag default OFF

ARCH §4 line 126: *"V1 không bật TTS mặc định (answer là text trên UI). V2 cho phép user bật 'spoken answer' cho hands-free mode."* — Phase 3 ships the seam (trait + adapter + UI button) but defaults the entire surface OFF so:

1. Default vitest builds dead-strip nothing **TS-side** (the button just doesn't render); default cargo builds dead-strip the entire `tts` module **Rust-side** (no `tungstenite`/`reqwest` cost on the helper-daemon binary).
2. No regression risk to Phase 1/2: a default install has zero new code paths exercised — the `Speak answer` button is never rendered, the `tts` cargo module is never compiled.
3. Phase 3.x can flip the flag once the audio routing path (BlackHole virtual output, latency < 2 s wall-clock under live ElevenLabs RTT) is verified on hardware.

## Scope (T-3.7 ships)

### Rust side (`crates/stt-mlx/`, behind `tts` cargo feature, default OFF)

- New module `crates/stt-mlx/src/tts/` — the entire module is gated by `#[cfg(feature = "tts")]`. Default builds (`default = ["mlx-runtime", "deepgram", "elevenlabs"]`) compile zero TTS code.
- `tts::provider::TtsProvider` trait (Rust analogue of ARCH §4 TS interface):

  ```rust
  pub trait TtsProvider: Send {
      fn name(&self) -> &'static str;
      /// Synthesize `text` into PCM audio chunks. Sync/blocking — caller pumps on a
      /// `tokio::task::spawn_blocking` boundary, same convention as `SttProvider`.
      fn speak(&mut self, text: &str, opts: &TtsSpeakOptions) -> Result<Vec<TtsAudioChunk>, TtsError>;
  }
  ```

- `tts::provider::{TtsAudioChunk, TtsSpeakOptions, TtsError}` — the data types. `TtsAudioChunk { samples: Vec<i16>, sample_rate: u32, ts_ms: u64 }` (16 kHz mono PCM, matches the helper-daemon's input convention).
- `tts::elevenlabs::ElevenLabsTtsAdapter` + `ElevenLabsTtsConfig` — POST to `/v1/text-to-speech/{voice_id}/stream` with `xi-api-key` auth header (analogue of T-3.4's STT adapter), parses streaming PCM bytes into `TtsAudioChunk`s.
- **Transport seam (test-friendly)**: the adapter takes a `transport: Box<dyn TtsTransport + Send>` where `TtsTransport::execute(req: TtsRequest) -> Result<Vec<u8>, TtsError>`. Production wires a `reqwest::blocking::Client` (deferred to Phase 3.x — same pattern as T-3.4's TLS deferral); tests inject a deterministic `FakeTransport` that returns a fixed PCM payload. This avoids pulling `reqwest` into the default cargo dep graph.
- `tts::elevenlabs::tests` — structural tests asserting:
  - request frame shape (URL, headers including `xi-api-key`, JSON body fields including `model_id`, `output_format = "pcm_16000"`)
  - response → `TtsAudioChunk` mapping (i16 LE bytes → samples, sample_rate stamped from request, ts_ms stamped from a session base)
  - missing-API-key path returns `TtsError::Config("ELEVENLABS_API_KEY missing or empty")` at construction (matches T-3.4 STT adapter convention)
  - default config points at production `https://api.elevenlabs.io` URL, default `voice_id` documented in the const
- **No factory wiring** — the STT factory (`providers::factory()`) is unchanged. TTS is a separate seam (Tauri command surface lands later); shipping it here would break Phase 1/2 cargo carry-forward via signature drift.

### TS side (`src/tts/`, default ENABLE_TTS=false, no Phase 1/2 surface change)

- `src/tts/featureFlag.ts` — `readTtsFlag(env?)` + `ENABLE_TTS` constant. Reads `import.meta.env.VITE_ENABLE_TTS`. Truthy values: any string except `""`, `"0"`, `"false"`, `"off"`, `"no"` (case-insensitive). Default is `false` when the env var is absent or unparseable.
- `src/tts/ttsProvider.ts` — TS interface verbatim from ARCH §4:

  ```ts
  export interface TtsProvider {
    name: "mlx" | "elevenlabs";
    speak(text: string, opts: TtsSpeakOptions): AsyncIterable<TtsAudioChunk>;
  }
  ```

- `src/tts/elevenLabsTts.ts` — `ElevenLabsTts` class implementing `TtsProvider`. Uses prop-injected `fetch` for testability. Streams `response.body!.getReader()` into `TtsAudioChunk`s. Same auth header (`xi-api-key`) and request body shape as the Rust adapter.
- `src/components/AnswerPanel.tsx` — adds optional `onSpeak?: (text: string) => Promise<void>` prop. **When the prop is undefined, the button does NOT render** — no DOM presence, no event listeners. App.tsx wiring conditionally passes `onSpeak` only when `ENABLE_TTS === true`.
- Speak button states: `idle → speaking → done` (or `error`). `aria-live="polite"` status pill. Latency budget under test: from click → "speaking" pill flip < 2 000 ms wall-clock measured via `performance.now()`.

### Tests

- **Vitest** (TS):
  - `src/tts/featureFlag.test.ts` — TF-S1..S6: default off (no env), explicit truthy (`true`/`1`/`on`), explicit falsy (`""`/`"0"`/`"false"`), unknown string truthy (e.g. `"yes"`).
  - `src/tts/elevenLabsTts.test.ts` — EL-S1..S6: missing API key → throws at construction; request shape (URL/method/headers/body); streaming chunks → `TtsAudioChunk` mapping (i16 LE bytes round-trip); default voice_id + model_id constants pinned; `name === "elevenlabs"`.
  - `src/components/AnswerPanel.test.tsx` (extension) — AP-S13..S16: default render (no Speak button), button present iff `onSpeak` prop is supplied, click → "speaking" pill < 2 s, button disabled while speaking (debounce parity with SettingsSheet test-connection).

- **Cargo** (Rust, `--features tts`):
  - `tts::provider::tests::*` — trait object-safe; `TtsAudioChunk` shape; `TtsError` variants.
  - `tts::elevenlabs::tests::*` — request shape (URL/headers/body), missing-key → `TtsError::Config`, byte → sample conversion, default config constants pinned.
  - **Default cargo build (no `tts` feature)** — running `cargo check --workspace` (existing carry-forward) MUST pass without compiling the `tts` module. The module being entirely behind `#[cfg(feature = "tts")]` is the gate; if the module compiles in default mode, the dead-strip claim is broken.

## Out of scope (deferred)

- **Live audio playback** (Web Audio API context, MediaSource, buffered chunk queue). The button's `onSpeak` prop is the seam; the actual `<audio>` element wiring is deferred to Phase 3.x once the BlackHole virtual-output routing is verified on hardware.
- **MLX TTS** (`kokoro-mlx`, `parler-tts-mini`). ARCH §4 marks MLX TTS as experimental; T-3.7 ships ElevenLabs only. The trait is provider-agnostic so a future MLX TTS impl is additive.
- **Tauri command wiring** (Rust `ElevenLabsTtsAdapter` ↔ TS `ElevenLabsTts`). Currently the TS impl is the live path (uses `fetch`); the Rust adapter is structural only (transport-injected; no live HTTP). Bridging the two sides waits on T-3.10's settings-keychain integration.
- **Voice-picker UI** (currently the voice_id is a constant in code). Settings UI extension is Phase 3.x — out of scope for the "Speak answer" MVP.
