# T-3.9 — Telemetry log (opt-in, rotating, PII-scrubbed)

> Phase 3 task #9. Reference: `docs/IMPLEMENTATION-PLAN.md` Phase 3 — Pluggable Providers.
> Architecture refs:
> - ARCH §11 "Privacy Modes" (lines 395–408) — telemetry is opt-in; default OFF.
> - ARCH §13 "Cost Model" (lines 430–447) — provider switches/errors/latencies are part of the observability surface, but content (transcript / audio bytes) is **never** logged.
> Carry-forward: `src/store/settingsStore.ts` (T-2.9 + T-3.6 + T-3.8 — schema v2, where the new `telemetryEnabled` flag persists); `src/llm/sttPricing.ts` (T-3.5 `SttProviderId`); `src/privacy/privacyMode.ts` (T-3.8 `PrivacyMode`).

---

## Goal

Add a **local-only**, **opt-in** telemetry log that records *operational* signals from the STT provider stack — provider switches, error codes, per-request latency — without ever capturing the content of a transcript chunk, an audio frame, or an API key. The log appender rotates at 10 MB and keeps at most a few archived files so a long-running session cannot run the disk full.

The log is local-only by design. Phase 3 does NOT ship a remote uploader; the appender writes through a **sink abstraction** that the eventual Tauri-fs adapter (Phase 3.x) plugs into. For T-3.9 we ship the in-memory rotating sink + the scrubber + the public `createTelemetryLog()` API; tests exercise the rotation and PII-scrub behavior on the in-memory sink, which is the same surface the Tauri-fs sink will satisfy.

Default state for new users: **opt-out**. The picker UI lands a checkbox in the Settings sheet. When the flag is OFF, `appendEvent` is a documented NO-OP (no sink writes, no in-memory accumulation) so a privacy-conscious user can be sure that turning the toggle off is sufficient.

## Design

### 1. Forbidden-key scrubber (`src/telemetry/scrub.ts`)

The scrubber is the **single source of truth** for which fields must never reach the log. The grep gate in TM-S2 + TM-S15 reads `FORBIDDEN_KEYS` so the contract is one-line-edit-able if a future provider surfaces a new content field.

```ts
export const FORBIDDEN_KEYS: readonly string[] = Object.freeze([
  "text",
  "transcript",
  "pcm",
  "pcmFrame",
  "audio",
  "audioBytes",
  "apiKey",
  "secret",
  "password",
  "key",
]);

export function scrubEvent(raw: unknown): TelemetryEvent | null;
export function containsForbiddenKey(s: string): boolean;
```

`scrubEvent` walks the input shallow + one nested level (the event shape is flat with one optional `meta` object); any forbidden key triggers `null` (whole event dropped) — we prefer drop-on-suspect rather than partial-write so a buggy upstream caller cannot leak a transcript field by piggybacking it on a switch event.

`containsForbiddenKey(s)` is the **string-level grep** used by TM-S15 to assert that the serialized log line contains none of the forbidden keys. Case-insensitive substring match — defensive against camelCase / snake_case drift.

### 2. Event schema (`src/telemetry/telemetryLog.ts`)

```ts
export type TelemetryEventType =
  | "provider_switch"
  | "stt_error"
  | "stt_latency"
  | "privacy_mode_change"
  | "test_connection";

export interface TelemetryEvent {
  /** ISO-8601 string at append time. The appender stamps this if missing. */
  ts: string;
  eventType: TelemetryEventType;
  /** Optional structured fields. ALL forbidden by `FORBIDDEN_KEYS` are dropped at scrub time. */
  provider?: SttProviderId;
  fromProvider?: SttProviderId;
  toProvider?: SttProviderId;
  privacyMode?: PrivacyMode;
  latencyMs?: number;
  errorCode?: string;
  result?: "ok" | "fail";
  /** Bounded-shape metadata. Forbidden keys cause the whole event to drop. */
  meta?: Readonly<Record<string, string | number | boolean | null>>;
}
```

Notes:
- IDs (`provider`, `fromProvider`, `toProvider`) are typed against `SttProviderId` so they must come from the `STT_PROVIDER_IDS` whitelist; the scrubber double-checks at runtime to defend against `as any` casts upstream.
- `latencyMs` is a number — never a duration object that might carry a transcript reference.
- `errorCode` is a stable enum-ish string; never a free-form `errorMessage` (which could echo a stack trace containing a transcript). Documented in `T-3.9-review.md` as a specific privacy gate.

### 3. Rotating in-memory sink (`src/telemetry/sinks.ts`)

```ts
export interface TelemetrySink {
  append(line: string): void;
  rotate(): void;
  size(): number;
  /** Test-only inspection — production sinks may return `null`. */
  inspect?(): { current: string; archives: readonly string[] };
}

export interface MemorySinkOptions {
  /** Rotate when current segment grows past this many bytes. Default 10 MB. */
  maxBytes?: number;
  /** Keep at most this many archived segments (oldest dropped on overflow). Default 3. */
  maxFiles?: number;
}

export function createMemorySink(opts?: MemorySinkOptions): TelemetrySink;
export function createNoopSink(): TelemetrySink;
```

The memory sink keeps a UTF-8 byte counter + an array of archived segments. `append(line)` adds `line + "\n"` to the current segment and updates the counter; if `currentBytes + line.length > maxBytes` (counted before append), `rotate()` is called first. `rotate()` pushes the current segment to the archive head, shifts off `archives.length > maxFiles` worth of overflow, resets the counter.

Default `maxBytes = 10_000_000` (10 MB, per AC) and default `maxFiles = 3` so the on-disk equivalent is bounded at ~30 MB worst-case — well-bounded for a desktop log file.

### 4. Append loop (`src/telemetry/telemetryLog.ts`)

```ts
export interface CreateTelemetryLogOptions {
  sink: TelemetrySink;
  isEnabled: () => boolean;
  scrub?: typeof scrubEvent;
  now?: () => string;
}

export interface TelemetryAppendResult {
  written: boolean;
  rotated: boolean;
  reason?: "disabled" | "scrub-rejected";
}

export interface TelemetryLog {
  appendEvent(event: TelemetryEvent): TelemetryAppendResult;
  /** Diagnostic — synchronous read on the sink. */
  size(): number;
}

export function createTelemetryLog(opts: CreateTelemetryLogOptions): TelemetryLog;
```

Flow per `appendEvent`:

1. **Gate.** `if (!isEnabled()) return { written: false, rotated: false, reason: "disabled" }`. The function never touches the sink in this branch — the safety belt for the opt-in promise.
2. **Scrub.** `const safe = scrub(event)`. `null` → `{ written: false, rotated: false, reason: "scrub-rejected" }`.
3. **Stamp ts** if missing (`safe.ts ??= now()`).
4. **Serialize** to a single JSON line.
5. **Pre-check rotate.** `if (sink.size() + line.length + 1 > maxBytes)` is the sink's responsibility — `append()` itself triggers `rotate()`. The append loop only reads `rotated = sink.size() < beforeSize` post-call.
6. **Append.** `sink.append(line)`.

The `rotated` flag is a *signal*; tests (TM-S13) read it to assert that 10 MB synthetic events trigger exactly the documented rotation cadence.

### 5. Settings store extension

`telemetryEnabled` defaults to `false`. The setter is symmetric with the existing `setHaikuEnabled` / `setCostGuardPaused` setters. Persisted to the existing `:v2` slot — `coerceLoaded` already tolerates missing fields (zero-fill from defaults), so no schema bump is required.

### 6. UI toggle

A single `<input type="checkbox">` under a labelled row in the Settings sheet:

```tsx
<div className="settings-sheet__row">
  <label className="settings-sheet__label">Telemetry</label>
  <input
    type="checkbox"
    data-testid="settings-telemetry-toggle"
    checked={telemetryEnabled}
    onChange={(e) => setTelemetryEnabled(e.target.checked)}
  />
  <span className="settings-sheet__hint">
    Local-only operational log (provider switches, errors, latency). No transcript or audio. Off by default.
  </span>
</div>
```
