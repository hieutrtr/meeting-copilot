## 3. Findings (memo bullets — for `docs/PHASE-0-COMPLETE.md`)

1. **Tauri 2 hand-scaffold is faster than `bun create tauri-app` for this project.** The interactive scaffolder writes into a fresh subdir, but our project root already has `docs/`, `experiments/`, `.claude/`, `README.md` — writing the ~14 quickstart files by hand is deterministic, audit-friendly, and matches ARCH App A directly. Phase 1 won't regret this.
2. **Frontend toolchain works without Rust.** `bun install` + `bun run dev` + `bun run build` all exit 0 on a host with no cargo. This means **dashboard-style work** (PWA mode? read-only viewer?) could ship a UI even before Rust lands. Useful fallback if Rust install is delayed for the user.
3. **Vite cold-start is fast on M1 Max — 1.1 s.** Production build 0.3 s / 143.5 kB JS (46.2 kB gzip). Phase 1 budget for "UI render < 500 ms" (ARCH §12) has plenty of headroom.
4. **Tauri 2 capabilities ACL is required even for the trivial `greet` command.** Without `src-tauri/capabilities/default.json` granting `core:default`, `invoke()` is rejected. Phase 1 must narrow this per ARCH §11 when adding plugins (keychain, fs, dialog) — `core:default` is too broad for v1.0 release. Carry into PHASE-0-COMPLETE.
5. **CI Rust job is currently disabled** (`if: false`) on purpose — it'd fail until T-1.1 lights up cargo on the runner. Frontend-only CI is sufficient for Phase 0 sign-off and gives the user a green badge from day 1.
