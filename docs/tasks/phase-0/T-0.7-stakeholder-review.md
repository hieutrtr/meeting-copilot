## 4. Conditions (must address before Phase 1 sprint plan locks)

These are not blockers for **T-0.8 / Tauri scaffold** — that task is environment-independent. They are blockers for **Phase 1 task-list refinement** (the planning work that immediately follows Phase 0 sign-off in PHASE-0-COMPLETE.md).

### Condition C-1 — Reconcile the "T-1.5 wires Silero VAD" claim with PLAN T-1.5 scope

**Memo location:** `docs/spike-memo.md` §"Unknown #2 — MLX whisper RTF" (the line "Promote `large-v3-turbo` to default once T-1.5 wires Silero VAD + 30s sliding window") AND §"Stack decision" (the line "STT default: MLX local with `medium` (Phase 1) → `large-v3-turbo` post-VAD (Phase 2 / T-1.5)").

**Issue.** Two problems on this point:
1. **Phase confusion.** T-1.5 is in **Phase 1** (PLAN line 56), not Phase 2. The "(Phase 2 / T-1.5)" parenthetical contradicts itself.
2. **Scope drift.** PLAN T-1.5 reads: *"MLX whisper integration: spawn `mlx-whisper` subprocess, feed PCM stream, parse JSON transcript output."* No VAD. No 30s sliding window. The memo is silently rescoping T-1.5 to add VAD without flagging it.

**Action required (during Phase 1 kickoff).** Either (a) explicitly extend T-1.5's AC to include "Silero VAD wired before runaway-decode-prone models are enabled," (b) split a new T-1.5b for VAD with `large-v3-turbo` upgrade gated behind it, or (c) keep `medium` as Phase 1 default and defer the VAD work + `large-v3-turbo` upgrade to a Phase 2 task (e.g., as part of T-2.2 sliding-window assembler — but T-2.2 is utterance assembly, not VAD, so this still needs a new task).

**My recommendation:** option (b) — insert `T-1.5b — Silero VAD integration + `large-v3-turbo` upgrade gate` as a Phase 1 stretch task. Default Phase 1 ships with `medium` (sufficient per spike), `large-v3-turbo` becomes a setting toggle that's only available when VAD is on.

### Condition C-2 — Make the 1.7× M1 Max → M1 Pro scaling factor's basis explicit

**Memo location:** `docs/spike-memo.md` §"Unknown #2 — MLX whisper RTF" §"Caveats" (the line "conservative 1.7× scale to M1 Pro / 16 GB target gives worst-case RTF ≈ 0.435").

**Issue.** The 1.7× factor is sourced from `experiments/T-0.4/results.md` line 53 ("Estimate ~1.3–1.7× slower on target") which itself does not cite a source — it's a rule-of-thumb from the GPU-core ratio (M1 Pro 16-core GPU vs M1 Max 32-core GPU = 2× raw, but unified-memory + Apple Neural Engine usage in MLX usually closes the gap to ~1.3–1.7×). The memo picks the **upper** bound (1.7×) which is conservative — that's good — but does not say so.

**Action required.** Add a one-sentence footnote in the memo's Caveats section: *"1.7× is the upper bound of the 1.3–1.7× rule-of-thumb derived from GPU-core count and MLX Metal usage; T-1.12 mandates an empirical M1 Pro re-measurement before Phase 1 ships."* This protects against a downstream reader treating 1.7× as if it were measured.

**Optional but recommended.** Phase 1 PHASE-0-COMPLETE.md should call out the **M1 Pro re-measurement** as an explicit Phase 1 gate, not just an item in the Caveats — because if the re-measurement comes back > 1.0 RTF on `medium` we trigger Pivot row 4 (drop tier) or Pivot row 5 (Deepgram default), and that's a 3-day plan delta that needs to be owned.

### Condition C-3 — Restate the cost AC revision more transparently

**Memo location:** `docs/spike-memo.md` §"Unknown #3 — Claude streaming + prompt cache" §"Pricing math holds against ARCH §13" (the line "Original AC-5 advisory bar of $0.005/call was too tight — output tokens at $15/MTok dominate warm-call cost. Revised to $0.015/call advisory.").

**Issue.** The memo states the revision but doesn't show the math. A reader who later challenges the cost ceiling can't reconstruct the new bound. The math is implicit: 600 output tokens × $15/MTok ≈ $0.009 + ~21 500 cached input tokens × $0.30/MTok ≈ $0.0065 = ~$0.0155 ≈ **$0.015**.

**Action required.** Add a one-line breakdown in the memo (or in `T-0.5-review.md` §"Cost AC revision" if more detail is wanted): *"$0.015/call = 600 output × $15/MTok ($0.009) + ~21.5k cached input × $0.30/MTok ($0.0065)."* This makes the bound auditable.

This is a low-effort fix — nice-to-have, not a Phase-1-kickoff blocker. If not done, T-0.5 review §"Issues" already states the bar was revised, so the audit trail exists; the memo just doesn't republish the math.
