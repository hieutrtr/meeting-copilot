## Objective

Prove (or disprove) that `mlx-whisper` can transcribe meeting-shaped audio in real time on Apple Silicon — i.e. **Real-Time Factor (RTF) = wall_clock_seconds / audio_seconds < 1.0** on the recommended production model. Numerically rank `tiny`, `small`, `medium`, and `large-v3-turbo` so the spike memo (T-0.6) can pick a default and a fallback ladder.

This is a **batch-transcribe** RTF bench (not streaming). The streaming wrapper is raw plan T-0.4 (loop-deferred to Phase 1 T-1.5 per INDEX renumbering note); the batch RTF here is sufficient evidence for UNKNOWN #2 because:
- Streaming wrappers can only ever be *slower* than batch (chunk overhead + window seam handling).
- If batch RTF ≥ 1.0, streaming is mathematically infeasible — early NO-GO is a correct call.
- If batch RTF ≪ 1.0, there is headroom for streaming overhead (T-1.5 risk shrinks).

## Approach (per loop rule 2 — spike + benchmark harness, NOT TDD)

T-0.4 is a hardware/measurement task. No unit tests; instead a deterministic measurement script + raw output capture + post-hoc verification of every reported number.

### Harness design

`experiments/T-0.4/`:
- `bench.py` — single-shot benchmark for one (model, sample) pair. Loads model → transcribes → emits one JSON line on stdout. Run as a fresh subprocess per pair so peak RSS is per-invocation (no process-level accumulation across models).
- `gen_samples.sh` — uses macOS `say` to generate one ~5-min source AIFF, then ffmpeg-splits into 5 × 60s WAVs (16 kHz mono PCM_S16LE). Idempotent: skips if `out/samples/*.wav` already present.
- `run.sh` — orchestrator: uv venv (Python 3.12) → `uv pip install mlx-whisper` → call `gen_samples.sh` → for model in {tiny,small,medium,large-v3-turbo} × sample in {1..5}: invoke `bench.py` as subprocess → tee one JSON line per pair → aggregate into `results.json` + render markdown table into `results.md`. Configurable: `MODELS=...`, `N_SAMPLES=...` env vars. Fail-fast on any subprocess crash; preserves any partial JSONL.
- `README.md` — reproduce + interpretation + post-fix expected output.

### Verdict logic (computed in `run.sh` aggregator)

For each model, count samples where `rtf < 1.0`:

| pass count | per-model verdict |
|---|---|
| 5/5 | **GO** |
| 3–4/5 | **CAVEAT-GO** (variance — note worst sample) |
| 0–2/5 | **NO-GO** for production default; eligible only as cloud-burst fallback |

Overall UNKNOWN #2 verdict: **GO** iff at least one model with quality ≥ `small` (per ARCH §2.4 acceptable-quality bar) is GO or CAVEAT-GO.

If overall NO-GO: pivot path is **Deepgram Nova-2 cloud as Phase 1 default** (per `IMPLEMENTATION-PLAN.md` Phase 0 exit criteria line 38: *"Nếu MLX không đủ nhanh → fallback Deepgram làm default Phase 1, MLX trở thành Phase 3"*).

### Measurement contract

Per `bench.py` invocation, emit (one line, JSON):

```json
{
  "model": "mlx-community/whisper-tiny-mlx",
  "model_short": "tiny",
  "sample_path": "out/samples/01.wav",
  "sample_idx": 1,
  "audio_seconds": 60.024,
  "load_ms": 412.7,
  "transcribe_ms": 4127.3,
  "wall_total_ms": 4540.0,
  "rtf": 0.0688,
  "rtf_no_load": 0.0688,
  "peak_rss_bytes": 612581376,
  "peak_rss_mb": 584.2,
  "text_chars": 781,
  "language": "en",
  "ok": true
}
```

`rtf = transcribe_ms / 1000 / audio_seconds`. We exclude `load_ms` from the headline RTF (it's amortized in production; reported separately as `load_ms`). Also report `rtf_with_load = wall_total_ms / 1000 / audio_seconds` for completeness — but the AC headline is `rtf` (transcribe-only).

Peak RSS measured via `resource.getrusage(resource.RUSAGE_SELF).ru_maxrss` (bytes on macOS). Subprocess isolation guarantees this is per-(model,sample) cold-start, not cumulative.

## Notes / open questions

1. **Host vs target.** Bench host is M1 Max / 64 GB; target spec is M1 Pro / 16 GB. M1 Max has ~2× GPU cores + 4× RAM. RTF numbers will be optimistic. Memo (T-0.6) must caveat with a rough scale-down (Apple has not published Whisper-on-MLX cross-chip data; we estimate 1.3–1.7× slower on M1 Pro based on general MLX benchmarks). NO-GO on M1 Max ⇒ definitely NO-GO on M1 Pro; CAVEAT-GO on M1 Max ⇒ requires re-measurement on target before Phase 1 commit.
2. **Batch vs streaming gap.** Batch RTF underestimates streaming RTF because streaming has window-seam re-decode + chunk overhead. Phase 1 T-1.5 will re-measure with the streaming wrapper. This task answers the *necessary* condition (batch < 1.0), not the *sufficient* one.
3. **Sample diversity.** Using `say` produces clean TTS audio — easier than real meeting recordings (no overlap, no background noise, single speaker). Real-meeting RTF will likely be similar (whisper is mostly compute-bound by audio length, not content), but accuracy will degrade. We measure RTF here, not WER.
4. **Model auto-download.** First run downloads `mlx-community/whisper-*-mlx` from HuggingFace (~75 MB tiny → ~1.5 GB medium → ~1.5 GB large-v3-turbo, total ~3.5 GB). Cached under `~/.cache/huggingface/hub/`. Subsequent runs reuse cache. Network failure → bench.py exits non-zero with `error: model_download_failed`.
5. **Python version.** Host has 3.13.7, but MLX historically lags on cutting-edge minor versions. We pin uv venv to **Python 3.12** for safety. If `mlx-whisper` install fails on 3.12, fall back to 3.11.
6. **`mlx-whisper` API stability.** Use `import mlx_whisper; mlx_whisper.transcribe(audio_path, path_or_hf_repo=repo)` — public API since v0.4. Pin version in install.
7. **`say` voice selection.** Use system default (Alex on US locales) — neutral voice for clean WER baseline. Sample text is a synthetic meeting transcript covering different prosody (declaratives, questions, code-like content with abbreviations).
8. **Determinism.** mlx-whisper is roughly deterministic for greedy decoding; we don't enforce determinism since we measure timing not text. Re-runs may differ in `transcribe_ms` by ~5–15 % due to thermal / GPU contention. Run each (model,sample) once; report raw numbers (no averaging within a single benchmark run).
9. **Cleanup.** Sample WAVs (~5 MB each) and HF model cache are *not* checked in. `experiments/T-0.4/.gitignore` blocks `out/samples/`, `out/runs/`, `out/raw_text/`, `out/run.log`. Only `results.{md,json}` + scripts are durable.
10. **TCC / permissions.** No microphone or screen-recording prompt — bench operates on prerecorded WAV files only. No hardware permission gate.

## User unblock (if anything BLOCKED)

If `bench.py` exits non-zero with `error: hf_download_failed` or similar, this likely means HuggingFace rate-limit / network. User action:
1. Run `huggingface-cli login` (optional, raises rate limit).
2. Re-run `./run.sh` — cache is incremental, only missing models redownload.

If `error: not_apple_silicon` → mlx requires arm64. Bench halts.

If `error: mlx_install_failed` → manual `uv pip install --python 3.11 mlx-whisper` and re-run. Document the working Python version in `results.md` "host" section.
