## Acceptance criteria (mic-only slice)

Adapted from plan AC, scoped to mic:

1. **Reproducible script** — single `swift mic_capture.swift <duration> <out.wav> <metrics.json>` invocation, no Xcode project, no extra deps.
2. **WAV opens** — `afinfo out.wav` reports valid duration ≈ requested seconds, sample rate matches log, channel count matches log.
3. **No glitch measured** — instrumented gap-detection between consecutive `installTap` callbacks. Glitch count must be `0` for a clean run; if non-zero, raw sample-gap counts logged.
4. **Latency measured** — first callback latency from `engine.start()` recorded in ms.
5. **Failure mode documented** — if microphone permission is denied (TCC), the script exits with a non-zero status and a structured JSON note (`{"ok": false, "error": ...}`); `results.md` records this as a hardware-blocked outcome with the exact user steps to unblock (System Settings → Privacy & Security → Microphone → enable for the executing terminal).

## Approach: spike + measurement script

This is hardware-bound and TCC-permission-bound, so per loop rule 2 we do not TDD. We:

1. Write a minimal Swift CLI (`mic_capture.swift`) using `AVFoundation.AVAudioEngine`, install a tap on the input node at the device's native format, write each buffer into an `AVAudioFile`, time the recording, and produce a structured `metrics.json`.
2. Wrap with `run.sh` that creates `experiments/T-0.1/out/`, executes the recorder, captures stdout/stderr to `out/run.log`, and copies the metrics into `results.md` / `results.json`.
3. Attempt to run inside this iteration. If TCC permission isn't yet granted to the executing process, the script will return zero samples or fail at `engine.start()` — that is recorded as `BLOCKED` with reproduce steps for the user.

## Open questions / known limits

- **TCC permission scope** — Microphone permission is per-binary; running under `swift` means `/usr/bin/swift` (or its child swift-driver) is the requesting process, and macOS will pop a permission dialog the first time. Headless agent run cannot satisfy this dialog. The script is still reproducible; user runs it once interactively to grant.
- **Native sample rate** — built-in mic on Apple Silicon is typically 48 kHz float32. The architecture target is 16 kHz mono. We do NOT resample in this spike — that's deferred. The tap operates at hardware native; metrics record the actual rate.
- **Glitch detection caveat** — relies on `AVAudioTime.sampleTime` continuity between callbacks. Some platforms reset `sampleTime` after `engine.stop()` / `start()`; we only run a single start, so this is safe. A truly silent run from the system (no audio device) would give `inputFormat.sampleRate == 0` — handled as a separate failure path.
- **Buffer size histogram** — Core Audio coalesces buffer sizes; we log distribution to spot device misconfiguration without judging it as glitch.
