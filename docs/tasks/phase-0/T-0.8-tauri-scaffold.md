## 4. Approach — code-heavy + structural verification

Per INDEX §"Spike vs TDD Per Task" — T-0.8 is one of two code-heavy tasks (T-0.5 the other). Approach:

### 4.1 Scaffold by hand (not via `bun create tauri-app`)

`bun create tauri-app` is interactive (prompts for app name, identifier, frontend framework, package manager) and writes into a *new* subdirectory. Our project root already has `docs/`, `experiments/`, `README.md`, `.claude/` — so we hand-write the minimum Tauri 2.x quickstart files at project root, matching ARCH App A exactly. This is faster, deterministic, and produces files we fully understand.

### 4.2 Files written

**Frontend (project root + `src/`)**:

- `package.json` — bun scripts (`dev`, `build`, `tauri`); deps `@tauri-apps/api@^2` + `react`; devDeps `@tauri-apps/cli@^2` + `vite` + `@vitejs/plugin-react` + `typescript`.
- `index.html` — Vite entry, mounts `<div id="root">`, loads `/src/main.tsx`.
- `vite.config.ts` — Vite + React plugin, port 1420 (Tauri default), HMR on 1421, ignores `src-tauri/`.
- `tsconfig.json` + `tsconfig.node.json` — strict TS, ES2020 target, `jsx: react-jsx`.
- `src/main.tsx` — React root.
- `src/App.tsx` — IPC smoke UI: `<input>` for name, button calling `invoke<string>("greet", { name })`, renders the reply.
- `src/styles.css` + `src/App.css` — minimal styling.

**Rust backend (`src-tauri/`)**:

- `Cargo.toml` — Tauri 2.x deps + `lib` crate-types (`["staticlib","cdylib","rlib"]`).
- `build.rs` — `tauri_build::build()`.
- `tauri.conf.json` — productName, identifier `dev.hieutran.meeting-copilot`, single 800×600 window labelled `main`, `beforeDevCommand: "bun run dev"`, `devUrl: "http://localhost:1420"`, bundle config.
- `src/main.rs` — calls `meeting_copilot_lib::run()`.
- `src/lib.rs` — `#[tauri::command] fn greet(name: &str) -> String`, registered via `invoke_handler(generate_handler![greet])`. Contains a `#[cfg(test)] mod tests` Rust unit test for the pure function.
- `capabilities/default.json` — minimal Tauri 2 capability granting `core:default` to window `main` (required for `invoke()` to work).
- `icons/icon.png` — placeholder 1×1 transparent PNG. Phase 1 will replace via `cargo tauri icon` (out of T-0.8 scope; documented in review).
- `.gitignore` — `/target`.

**Project root `.gitignore`** — `node_modules`, `dist`, `*.log`, `.DS_Store`, `src-tauri/target`.

### 4.3 Verification harness (`experiments/T-0.8/`)

Per loop rule 4, the verification machinery is throwaway and lives under `experiments/`. Files:

- `run.sh` — single-command repro. Branches:
  1. **Structural verification (always runs)** — assert files exist, JSON parses, key tokens present in `lib.rs`/`App.tsx`/`Cargo.toml`. Exit 0 / 1.
  2. **`bun install` + `bun run dev` smoke** (always runs if bun available) — verifies frontend boots; SIGINT after 3s; exit 0 if Vite logs "Local:".
  3. **`cargo tauri dev` smoke** (only if cargo present) — runs in background, waits for "App listening" / window-open log marker, kills after 5s. Exit 0 / 14 (cargo missing).
- `verify.ts` — bun-runnable structural assertions, used by `run.sh` for the JSON-parse + grep checks (cleaner than bash `jq` chains).
- `results.md` — Markdown verdict table per AC, fills in numbers from the run.
- `bench.log` — captured stdout/stderr from `run.sh`.
- `README.md` — repro instructions + caveats.

### 4.4 IPC smoke test (Rust↔frontend round-trip)

The `greet` command is the canonical Tauri 2 hello-world. We test it three ways:

1. **Structural** (always works): grep `#[tauri::command]\s*\nfn greet` in `lib.rs` + `invoke<string>("greet"` in `App.tsx`. — proves both sides reference the same command name.
2. **Rust unit test** (post-cargo): `cargo test -p meeting-copilot` runs `tests::greet_smoke` which asserts `greet("World") == "Hello World, from Tauri!"`. — proves the function is pure-callable.
3. **Live round-trip** (post-cargo + window open): user clicks the button in the dev window and observes the rendered reply. — proves IPC plumbing.

Layers 1 + 2 give automated coverage; layer 3 is the manual smoke that gates Phase 1 kickoff.

## 7. Failure modes (for review checklist)

| Mode | Detection | Remediation |
|---|---|---|
| Cargo missing on host | `command -v cargo` empty → run.sh exits 14 | User installs Rust per walkthrough; re-run |
| Bun missing | `command -v bun` empty → run.sh exits 13 | Already verified present (1.3.11); shouldn't fire |
| Vite port 1420 collides | Vite log shows "Port 1420 is already in use" | Kill the colliding process or change port in `vite.config.ts` |
| Tauri config schema mismatch (Tauri 2 schema rejects our hand-written conf) | `cargo tauri dev` exits non-zero with schema error | Inspect log; align field names with current schema |
| IPC handler not registered | Frontend `invoke('greet')` rejects with "command greet not found" | Verify `generate_handler![greet]` in `lib.rs` |
| Frontend dev server up but window blank | Bun running, but Tauri WebView shows blank | Check CSP in `tauri.conf.json` (`security.csp: null` for dev), check `devUrl` matches Vite port |
