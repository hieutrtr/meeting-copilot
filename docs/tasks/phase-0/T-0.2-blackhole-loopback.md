## Acceptance criteria (system-audio slice)

Adapted from plan AC, scoped to system-audio loopback:

1. **Reproducible script** — single `./run.sh [duration]` invocation from `experiments/T-0.2/`, no Xcode project, no extra deps beyond the Swift toolchain. Compiles `blackhole_capture.swift` once, caches binary, re-runs in <2s.
2. **Device enumeration** — script lists every Core Audio input device by uid + name + channel count and structurally identifies BlackHole-2ch (matching name regex `BlackHole 2ch` or uid prefix `BlackHole2ch_UID`). Output recorded to `metrics.json.devices[]`.
3. **BlackHole presence check** — if BlackHole-2ch is **not present**, the script exits with a structured `BLOCKED-PENDING-INSTALL` reason (`{"ok": false, "error": "blackhole_not_installed"}`). `results.md` records the user-facing install steps verbatim from this task file (brew formula + Audio MIDI Setup walk-through + expected `system_profiler` output line).
4. **Loopback capture (when present)** — captures 60s of audio from the BlackHole-2ch input device into a 2-channel WAV at native rate. WAV opens with `afinfo`. Reports: callback count, sample count, audio_seconds_recorded, first-callback latency (ms), glitch count (gap-detection between consecutive `installTap` callbacks), dropout count (zero-amplitude buffers exceeding 50 ms), and peak amplitude.
5. **Numeric pass thresholds** —
   - `glitch_count == 0` for full 60s.
   - `dropout_count == 0` (i.e. no buffer with `peak < 1e-4` for ≥50 ms while audio is supposed to be playing).
   - `audio_seconds_recorded` within 1% of requested 60s (gives ±0.6s).
   - `first_callback_latency_ms < 500` (Core Audio HAL plug-ins typically <100 ms).
6. **Failure mode documented** — three distinct structured failure exits, each with a `hint` field that names the user action to recover:
   - `exit 6` — TCC microphone permission not authorized (BlackHole shows up under Privacy & Security → Microphone).
   - `exit 7` — BlackHole-2ch not installed (most common on first run).
   - `exit 8` — BlackHole installed but no audio playing into it (capture works but `signal_present == false`); script still passes `glitch`/`dropout` checks but flags `signal_present: false` so user can re-run with audio playing.

## Approach: spike + measurement script

This is hardware-bound (BlackHole HAL plug-in) AND TCC-permission-bound, so per loop rule 2 we do **not** TDD. We:

1. Write a minimal Swift CLI (`blackhole_capture.swift`) using:
   - `CoreAudio` `AudioObjectGetPropertyData(kAudioHardwarePropertyDevices)` to enumerate input devices and find BlackHole-2ch by name.
   - `AVAudioEngine` with the input node's underlying `AudioUnit` set via `AudioUnitSetProperty(kAudioOutputUnitProperty_CurrentDevice)` so the engine reads from BlackHole-2ch instead of the system default mic. (Bypasses needing a separate Aggregate Device just for this task — the user-facing app will use Aggregate, but for the *single-source* spike we point AVAudioEngine directly at BlackHole.)
   - Same TCC `AVCaptureDevice.authorizationStatus(for: .audio)` pre-flight as T-0.1 — virtual audio devices share the microphone TCC bucket on macOS.
   - Tap on the input bus at native format, write to `AVAudioFile` (2-channel float32 LPCM), accumulate the same metrics shape as T-0.1 plus a `dropout_count` extension.
2. Driver `run.sh` mirrors T-0.1: cache `swiftc -O` build, run binary, mirror metrics into `results.json` + canonical summary `results.md`, dump `afinfo`. Hard watchdog `duration + 8s`.
3. Attempt to run inside this iteration. The host probe shows BlackHole is **not installed** (`brew list` does not contain `blackhole-2ch`, `/Library/Audio/Plug-Ins/HAL/` only contains `ParrotAudioPlugin.driver` and `ShureVirtualAudio.driver`), so the expected outcome is `exit 7 / blackhole_not_installed`. We record that as the BLOCKED case with reproduce steps for the user.

## User unblock steps (for `results.md` + spike memo Phase 1 wizard)

```sh
# 1. Install the HAL plug-in
brew install blackhole-2ch

# 2. (One-time) macOS may require approval after install:
#    System Settings → Privacy & Security → scroll bottom → "BlackHole-2ch system extension"
#    "Allow" → reboot prompt (often required first time, not always).

# 3. Verify installation
ls /Library/Audio/Plug-Ins/HAL/ | grep -i blackhole
#   Expected:  BlackHole2ch.driver

system_profiler SPAudioDataType | grep -A1 "BlackHole 2ch"
#   Expected:  BlackHole 2ch:
#                Manufacturer: Existential Audio Inc.

# 4. Open Audio MIDI Setup.app:
#    a. Create Multi-Output Device:
#       - Click "+" → "Create Multi-Output Device"
#       - Check: "MacBook Pro Speakers" (or whatever default), "BlackHole 2ch"
#       - Set Master Device = built-in speakers, "Drift Correction" ON for BlackHole
#       - Rename: "MeetingCopilot Output"
#    b. Create Aggregate Device (used by T-0.3, not this task):
#       - Click "+" → "Create Aggregate Device"
#       - Check: "MacBook Pro Microphone", "BlackHole 2ch"
#       - Rename: "MeetingCopilot Input"
#
# 5. Set system output → "MeetingCopilot Output" before running this spike.
#    Play any audio source (YouTube tab, Music.app, system test tone) so loopback has signal.

# 6. Re-run:
cd experiments/T-0.2 && ./run.sh 60
```

After install the spike script's BlackHole-presence check flips from `exit 7` to a real recording, populating every numeric AC field with measured values.

## Open questions / known limits

- **TCC bucket for virtual devices** — empirically virtual audio inputs on macOS Sonoma+ share the Microphone TCC bucket (granting Microphone to a binary lets it read from BlackHole). This task's TCC pre-flight uses `AVCaptureDevice.authorizationStatus(for: .audio)` which covers the virtual-input case. If the user's macOS version splits the buckets (unlikely on 14+), the script will still emit a structured TCC error.
- **Single-device vs Aggregate** — we point AVAudioEngine directly at BlackHole-2ch via `kAudioOutputUnitProperty_CurrentDevice` rather than requiring the Aggregate Input Device. This isolates the BlackHole capture path from the mic+sys mixing concern, which is T-0.3's job. The Aggregate Device approach (used in production / T-0.3) reads both streams on a single tap — but for the unknown-1-system-audio half, single-device is cleaner.
- **Loopback signal source** — even with BlackHole installed, if the system output is *not* routed through it (i.e. user forgot the Multi-Output Device step) the capture will succeed but record silence. We detect this as `signal_present == false` and surface it as `exit 8` rather than `exit 0`, so a user-pleasing pass requires actual audio routed correctly.
- **Native format from BlackHole** — BlackHole-2ch advertises 48 kHz / 2 ch / float32 by default. We do **not** resample in the spike; resampling to 16 kHz mono is T-0.4 / T-1.2 work.
- **Glitch detection assumption** — same as T-0.1: relies on `AVAudioTime.sampleTime` continuity. BlackHole's HAL plug-in is well-behaved here per upstream docs; we measure rather than assume.
