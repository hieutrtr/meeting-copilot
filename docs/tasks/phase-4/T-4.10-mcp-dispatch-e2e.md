## 1. Goal

Prove the **MCP surface contract** end-to-end by spawning the real `meeting-copilot-mcp` binary as a child process and driving it from a vitest test using the upstream `@modelcontextprotocol/sdk` `Client` + `StdioClientTransport`. The test stands in for "Telegram → claude-bridge → meeting-copilot" by replicating the same JSON-RPC framing claude-bridge uses when it dispatches to a registered agent.

The audio pipeline, real Tauri spawn, real Unix-domain socket, and real fs-backed snapshot loader are **all** intercepted by a fixture-backed harness gated on the `MEETING_COPILOT_E2E_FIXTURE_PATH` env var. The harness is a **dev/test-only** code path — production callers never set the env var, so the path is dead in shipping binaries.

This is the seam Phase 4's exit criteria require: the operator can dispatch from Telegram, the MCP layer answers correctly, error envelopes are typed, and the binary recovers between calls. Live-host extension (real `open(1)` deeplink, real audio capture, real STT) lives in `PHASE-BROWSER-TEST.md` (T-4.10's manual companion).

## 3. Architecture & Reference

### 3.1 Why an env-gated harness inside `bin.ts`

The 5 handler modules already accept dependency-injected fakes (T-4.4 `start.spawn`/`pollHandshake`, T-4.5/T-4.6 `dialSocket`, T-4.7 `loadSnapshot`/`exportRoot`/`fs`). Existing `src/mcp/server.test.ts` exercises that seam over `InMemoryTransport` — same process, same module space. T-4.10 needs the **subprocess** path: the real `bun run src/mcp/bin.ts` executable, real `StdioServerTransport`, real JSON-RPC framing. The two ways to get fakes into a subprocess are:

1. **Bake them into a separate test binary** (`src/mcp/bin.e2e.ts`). Splits production bin from test bin; doubles maintenance cost; risks divergence between the two boot sequences.
2. **Env-gate the harness inside the production bin**. One boot path; the env switch is the **only** difference; production is `process.env.MEETING_COPILOT_E2E_FIXTURE_PATH === undefined`, which is the default everywhere except the test harness.

Option 2 wins on parity. The shipped binary is byte-for-byte the same one the test exercises, modulo a single `if` branch that no production caller ever takes. The dead branch is a deliberate trade — the E2E test would otherwise be testing a different binary than ships.

### 3.2 Fixture file shape

```jsonc
{
  "tmpdir": "/tmp/.../t410-A",                  // resolved per-scenario by the helper
  "appBundlePath": "/tmp/.../no-such-bundle",   // install scenario points here
  "spawnLogPath": "/tmp/.../spawn.log",         // start writes one JSON line per spawn call
  "handshake": {                                // start's pollHandshake returns this
    "meetingId": "m_e2e",
    "pid": 12345,
    "rpcSocket": "/tmp/.../meeting-copilot.sock",
    "uiUrl": "http://127.0.0.1:7411/embed/transcript/m_e2e?token=t-e2e"
  },
  "statusReply": {                              // status's dialSocket returns this
    "meetings": [{ "id": "m_e2e", "pid": 12345, ... }]
  },
  "stopReply": { "durationSec": 60, "questionCount": 1 },  // stop's dialSocket returns this
  "snapshot": { ... ExporterMeetingSnapshot ... },        // export's loadSnapshot returns this
  "exportRoot": "/tmp/.../exports"              // export writes here (atomic write goes here)
}
```

All paths are absolute; no env interpolation, no tilde expansion. The helper fills `tmpdir` per scenario from `mkdtempSync(`${tmpdir()}${sep}t410-`)` and threads it into every absolute path before serializing. The static seed (`tests/e2e/__fixtures__/seed-meeting.json`) carries only the `ExporterMeetingSnapshot` payload — every other field is per-scenario.

### 3.3 Mapping each handler to its fixture seam

| Handler | DI seam (existing) | E2E fixture wiring |
|---|---|---|
| `bridge_meeting_install` (T-4.3) | `appBundlePath` deps override | Set to `<tmpdir>/no-such-bundle.app` for the missing-app path. |
| `bridge_meeting_start` (T-4.4) | `spawn` + `pollHandshake` deps | `spawn` writes one JSON line `{cmd, args}` to `spawnLogPath` (replaces real `child_process.spawn`); `pollHandshake` returns `fixture.handshake`. |
| `bridge_meeting_status` (T-4.5) | `dialSocket` deps + `resolveSocketPathOpts` | `dialSocket` returns `fixture.statusReply` regardless of request shape. `resolveSocketPathOpts.homedir` set to `tmpdir` so the resolver never reads real `$HOME`. |
| `bridge_meeting_stop` (T-4.6) | Same as status | `dialSocket` returns `fixture.stopReply` for non-error paths or a `DaemonMeetingNotFound` envelope when `stopReply` is null. |
| `bridge_meeting_export` (T-4.7) | `loadSnapshot` + `exportRoot` deps | `loadSnapshot(id)` returns `fixture.snapshot` iff `id === fixture.snapshot.meeting.id`; `exportRoot` set to `<tmpdir>/exports/`. |

The harness module imports each handler **and** its public deps interface; production handler code is untouched. Adding the harness changes zero production behavior — verified by parity tests in `e2eHarness.test.ts` that boot the harness and assert the resolved handler set returns identical envelopes for the production-default code path (i.e. when fixture fields are absent).

### 3.4 Discovery is skipped in E2E mode

`bin.ts`'s `tryRegisterDiscovery()` writes to `~/.claude-bridge/config.json` (or `$CLAUDE_BRIDGE_HOME/config.json`). On a developer machine running the E2E test, this would mutate real config. The `MEETING_COPILOT_E2E_FIXTURE_PATH` branch **bypasses** discovery entirely. T-4.8's discovery is itself non-fatal (try/catch around the call), so production users with no claude-bridge installed still get a working server; in test mode we just skip the call rather than letting it write to disk. The unit test for the harness asserts the early-return ordering.

### 3.5 Three Telegram-shaped scenarios + two error paths

The five `it` cases mirror what claude-bridge would dispatch from a Telegram inbound:

1. **install-check** — operator asks "is meeting copilot installed?". claude-bridge dispatches `bridge_meeting_install({path: …})`, MC checks the bundle, returns `installed: false` envelope. Asserts the error-free envelope shape, the `downloadUrl` field is a GitHub URL, and `expectedVersion` matches the running MCP server's `package.json#version`.
2. **start-and-export** — operator asks "start a meeting on my PRD". claude-bridge dispatches `bridge_meeting_start({contextPaths:["/abs/PRD.md"], ...})`. MC validates, gates privacy, builds the deeplink, "spawns" (logs to spawnLogPath), and returns the `meetingId + uiUrl` envelope. The test then dispatches `bridge_meeting_export({meetingId, format:"markdown"})`, asserts the on-disk markdown body contains the seeded transcript text. Asserts the spawn log shows exactly one entry whose `args[0]` matches `/^meeting-copilot:\/\/start\?/` (proves the deeplink builder ran end-to-end through the real subprocess).
3. **summarize-last-meeting** — operator asks "summarize my last meeting". claude-bridge dispatches `bridge_meeting_status({})` to find the active or most recent id, then `bridge_meeting_export({meetingId, format:"markdown"})`. The test asserts the markdown body contains the seeded **question** + **answer** text + the privacy-mode header line — the "summary" is the rendered Q/A block per T-4.7's exporter contract.
4. **error path: PrivacyModeViolation** — operator asks "start with deepgram in local-first mode". MC must reject **before** spawn. The test asserts `isError: true`, the envelope text starts with `PrivacyModeViolation:`, and the spawn log is empty (the harness's spawn never fires).
5. **error path: ContextNotFound** — operator passes a `contextPaths` value containing `..`. T-4.4's `validateContextPaths` rejects pre-spawn and the handler maps to `ContextNotFound`. The test asserts the envelope text starts with `ContextNotFound:` and again the spawn log is empty.

Each `it` spawns a **fresh** subprocess (so test failures from one don't leak state into another). Per-scenario tmpdirs guarantee no cross-scenario fs collision. The 5 `it` cases run **serially** under vitest's default — no `it.concurrent` — so socket / file contention is impossible.

### 3.6 SDK version pin (R-1 carry-forward)

The test imports `@modelcontextprotocol/sdk/client/index.js` + `@modelcontextprotocol/sdk/client/stdio.js`. Both ship in the `^1.0.0` package we already pinned in T-4.2. The same SDK version is used by claude-bridge (verified in T-4.1 §6 against daemon v1.0.4 `package.json`). If the daemon bumps SDK and our test exercises a now-incompatible framing, the test breaks loudly — exactly the early-warning signal R-1 wants.

### 5.2 `tests/e2e/mcp-dispatch.e2e.test.ts` — 5 scenarios

Each scenario:
1. `mkdtempSync` a per-scenario tmpdir under `os.tmpdir()`.
2. Build a fixture object referencing only that tmpdir.
3. Write the fixture JSON to `<tmpdir>/fixture.json`.
4. Spawn the bin via `StdioClientTransport` with `MEETING_COPILOT_E2E_FIXTURE_PATH` set.
5. `client.connect(transport)` (drives JSON-RPC `initialize`).
6. Call the relevant tools, assert the envelopes.
7. `await client.close()`; `rmSync(tmpdir, { recursive: true, force: true })`.

Scenarios:
1. **install-check** — fixture's `appBundlePath` points at a non-existent dir under `tmpdir`; assert `installed:false` + downloadUrl.
2. **start-and-export** — fixture sets `handshake` + `snapshot` + `exportRoot`; call `start`, assert envelope `meetingId === "m_e2e"`; call `export`, assert markdown body contains seeded transcript text + chunk timestamp; assert spawn log has exactly one line.
3. **summarize-last-meeting** — fixture sets `statusReply` (one meeting) + `snapshot`; call `status`, assert envelope contains the meeting; call `export`, assert markdown body contains seeded Q + A + privacy line.
4. **PrivacyModeViolation** — call `start` with `{privacyMode:"local-first", sttProvider:"deepgram"}`, assert isError + `PrivacyModeViolation:` prefix + empty spawn log.
5. **ContextNotFound** — call `start` with `{contextPaths:["../etc/passwd"], privacyMode:"local-first", sttProvider:"mlx", model:"claude-sonnet-4-6"}`, assert isError + `ContextNotFound:` prefix + empty spawn log.

## 6. Risk & Mitigation

| Risk | Probability | Impact | Mitigation |
|---|---|---|---|
| **Subprocess spawn races / port collisions in CI.** Two scenarios overlap and both bind the same socket fixture path. | Low | Medium | Per-scenario tmpdirs guarantee unique paths; vitest runs `it`s serially; `client.close()` always called in a `try/finally`. |
| **Bun resolver picks up a different `package.json` between test and prod.** | Low | Low | `bin.ts` reads `package.json` via `import.meta.url`-relative resolution; same code in test + prod; the install handler test asserts the parsed expectedVersion. |
| **Env var leak across scenarios.** A previous scenario sets `MEETING_COPILOT_E2E_FIXTURE_PATH` in the shared parent env, polluting later scenarios. | Low | Medium | Each scenario constructs the env explicitly via `getDefaultEnvironment()` + the per-scenario fixture path; `process.env` is not mutated. |
| **Vitest timeout on slow CI.** Subprocess spawn cold-start under bun is ~1–2 s; 5 scenarios = 5–10 s plus assertions. | Medium | Low | `vitest.config.ts` bumps `testTimeout` to 30 s; per-scenario `client.connect` uses the SDK's default 60 s timeout (we never wait that long). |
| **Discovery hook still fires in E2E mode** (R-X) — would mutate real `~/.claude-bridge/config.json` on the developer's machine. | Low | **High** | E2E branch in `bin.ts` returns before `tryRegisterDiscovery()`; unit test asserts ordering; `CLAUDE_BRIDGE_HOME` env override is a second line of defence (the helper sets it to the per-scenario tmpdir so even if discovery were called by mistake it would only mutate the tmpdir). |
