## 1. Goal & Scope

Lock down — **before any code lands** — the four contracts that surface between *claude-bridge daemon* and *meeting-copilot* so that T-4.2..T-4.10 implement against a frozen design:

1. **Discovery** — how meeting-copilot finds the daemon's `config.json` and publishes itself into `meeting_copilots: []`.
2. **MCP transport** — stdio JSON-RPC, SDK pin matching the daemon, 5-tool surface.
3. **Embed contract** — iframe URL, SSE event shape, CORS allow-list, single-use token auth.
4. **Privacy-mode enforcement** — where the gate fires in the pipeline (must be **before** any process spawn).

Out of scope (Phase 5 or later): GitHub-release auto-install for the meeting-copilot DMG, multi-daemon discovery, tunnel exposure of the embed endpoint, dashboard-side UI patches (those land in `claude-bridge-dashboard` repo separately).

## 2. Discovery Model — Two-Repo, One Config File

### 2.1 Single source of truth

Per dashboard ARCH §7.2 and §16, `$CLAUDE_BRIDGE_HOME/config.json` (default `~/.claude-bridge/config.json`) is the **only** discovery file. meeting-copilot follows the dashboard's pattern verbatim:

- **Daemon writes** `daemon.{version, db_path, socket, mcp_endpoint, events_log, compat_range_for_dashboard}` and `dashboards: []` (existing dashboard ARCH §16).
- **meeting-copilot writes (T-4.8) — additive only**, an extra top-level array `meeting_copilots: []` mirroring the `dashboards: []` shape:

```json
{
  "version": 1,
  "daemon": { … unchanged … },
  "dashboards": [ … unchanged … ],
  "meeting_copilots": [
    {
      "version": "1.0.0",
      "path": "/Applications/Meeting Copilot.app",
      "default": true,
      "mcp_bin": "/Users/hieu/.claude-bridge/meeting-copilots/v1.0.0/meeting-copilot-mcp",
      "rpc_socket": "/Users/hieu/.claude-bridge/meeting-copilot.sock",
      "embed_origin": "http://127.0.0.1:7411",
      "compat_range_for_daemon": ">=0.7.0 <2.0.0",
      "installed_at": "2026-05-07T00:00:00Z"
    }
  ]
}
```

All paths absolute (no tilde) — same rule as dashboard ARCH §16. Atomic write via `<config>.tmp` + `renameSync` (same pattern as `dashboard-installer.ts` in claude-bridge daemon).

### 2.2 Config-version handshake

- meeting-copilot reads `config.version`. If `> 1` → throw typed `ConfigSchemaUnsupported` with upgrade pointer. (Risk-1 mitigation; T-4.8 review checkbox.)
- meeting-copilot reads `daemon.version`. If `daemon.version` outside `meeting_copilots[default].compat_range_for_daemon` → refuse to register, log to stderr, exit 2 — mirrors dashboard ARCH §15 cell `1.0.x` row.

### 2.3 No reverse coupling

- Daemon does **not** depend on meeting-copilot's source — only on the `meeting_copilots[]` shape it reads from `config.json`. (Same isolation guarantee as dashboard ARCH §7.1: "Daemon **không depend on dashboard**.")
- Phase 5 of claude-bridge will add `bridge_meeting_install` *as a daemon-side wrapper* that shells out to meeting-copilot's `meeting-copilot-mcp install` binary — not in scope here.

## 3. MCP Transport Choice — stdio

### 3.1 Decision: stdio

Mirrors the daemon's `bridge_dashboard_*` tools (dashboard ARCH §13 implementation notes — `Bun.spawn` + stdio). Three reasons:

1. **SDK parity** — daemon pins `@modelcontextprotocol/sdk` to `^1.0.0` (verified at `claude-bridge/src/mcp/tools.ts` and `package.json`). meeting-copilot's MCP server pins the same, no version skew.
2. **Cold-spawn cost is acceptable** — install / status / export are infrequent operator commands; not on the hot transcript path.
3. **No persistent socket coupling** between daemon and meeting-copilot — keeps dashboard ARCH §18 open question #3 (stdio-vs-Unix-socket) compatible with both eventual decisions.

The persistent **helper-daemon** Unix socket (T-4.5) is a *separate* channel — used by the meeting-copilot MCP server's own handlers to talk to the running Tauri app. Not exposed to claude-bridge daemon.

### 3.2 Pinned versions

| Concern | Pin | Source |
|---|---|---|
| `@modelcontextprotocol/sdk` | `^1.0.0` | `claude-bridge/package.json` (frozen snapshot v1.0.4) |
| `zod` | `^3.23.0` | same |
| Daemon MCP tool surface (dashboard tools) | `bridge_dashboard_versions`, `bridge_dashboard_install`, `bridge_dashboard_uninstall` | `claude-bridge/src/mcp/tools.ts` lines 60–62 |
| Our 5 tool names (added at meeting-copilot side) | `bridge_meeting_install`, `bridge_meeting_start`, `bridge_meeting_status`, `bridge_meeting_stop`, `bridge_meeting_export` | This doc; mirrored to `src/mcp/tools.ts` (T-4.2) |

T-4.2 has a regex test against `package.json` that asserts the SDK pin literal — fails the test if anyone bumps it without re-verifying daemon compatibility.

## 4. 5-Tool Surface — Name → Handler-File Mapping

| Tool name | Handler file (T-4.<N>) | Input contract | Output contract | Side effects |
|---|---|---|---|---|
| `bridge_meeting_install` | `src/mcp/handlers/install.ts` (T-4.3) | `{ source?: "github"\|"local", ref?: string, path?: string, version: string }` | `{ installed: bool, version?: string, expectedVersion: string, downloadUrl?: string, message: string }` | **Read-only** in Phase 4 (parses `Info.plist` only; no fs writes). GitHub auto-download deferred. |
| `bridge_meeting_start` | `src/mcp/handlers/start.ts` (T-4.4) | `{ contextPaths: string[], sttProvider: "mlx"\|"deepgram"\|"elevenlabs", ttsProvider?: enum, model: enum, privacyMode: "local-first"\|"cloud"\|"mixed", meetingTitle?: string }` | `{ meetingId: string, pid: number, rpcSocket: string, uiUrl: string }` | (a) Privacy gate (`isSttProviderAllowed`); (b) URL build via `URLSearchParams`; (c) `child_process.spawn(["open", deeplink], { shell: false })`; (d) poll RPC socket up to 5s. |
| `bridge_meeting_status` | `src/mcp/handlers/status.ts` (T-4.5) | `{ meetingId?: string }` | `{ meetings: Array<{ id, pid, startedAt, sttProvider, transcriptChunks, questionCount, answerCount, uptimeSec }> }` | Unix-socket RPC `{"method":"status"}` to helper daemon. Read-only. |
| `bridge_meeting_stop` | `src/mcp/handlers/stop.ts` (T-4.6) | `{ meetingId: string }` | `{ exportedPath?: string, durationSec: number, questionCount: number }` | RPC `{"method":"stop"}`; idempotent (already-stopped → return recorded values). |
| `bridge_meeting_export` | `src/mcp/handlers/export.ts` (T-4.7) | `{ meetingId: string, format: "markdown"\|"json"\|"vtt"\|"srt" }` | `{ path: string, sizeBytes: number }` | Reads via `persistClient.ts` (TS-side, no daemon RPC); writes to `~/.claude-bridge/meeting-copilot/exports/<meetingId>.<ext>`. |

All handlers return the standard MCP envelope on error: `{ isError: true, content: [{ type: "text", text: "<typed error>: <message>" }] }`. Typed error codes (Zod-derived): `PrivacyModeViolation`, `DeeplinkNotRegistered`, `ContextNotFound`, `MeetingNotFound`, `InvalidMeetingId`, `ConfigSchemaUnsupported`, `BridgeConfigInvalid`. The list is **closed** — handler placeholders in T-4.2 reject any other shape.

## 5. Embed Iframe Contract

### 5.1 URL surface

| Endpoint | Method | Purpose | Auth |
|---|---|---|---|
| `GET /embed/transcript/:meetingId?token=<uuid>` | HTTP | Static HTML shell + bundled JS (transcript view + answer panel) | Single-use token, scoped to `meetingId` |
| `GET /embed/transcript/:meetingId/events?token=<uuid>` | SSE | Live transcript chunks + question + answer events | Same token |

Bind: `127.0.0.1:7411` (helper daemon, T-4.9). Loopback only.

### 5.2 SSE event shape

Each event is a single `data:` line with JSON body. Three event types, matching the SQLite tables (ARCH §10):

```jsonc
// transcript chunk
{ "type": "chunk", "id": "...", "meetingId": "...", "text": "...",
  "startTs": 1714998000.123, "endTs": 1714998001.456,
  "speaker": "user", "isFinal": true, "confidence": 0.97 }

// question detected
{ "type": "question", "id": "...", "meetingId": "...", "text": "...",
  "detectedTs": 1714998001.789, "method": "auto", "confidence": 0.83,
  "status": "answering" }

// answer ready
{ "type": "answer", "id": "...", "questionId": "...",
  "text": "...", "model": "claude-sonnet-4-6",
  "tokensIn": 412, "tokensOut": 180, "cachedPct": 87 }
```

Fan-out source: helper-daemon RPC `subscribe(meetingId)` (T-4.5 method) — broadcast channel, multiplex into HTTP response.

### 5.3 CORS allow-list (BLOCKING — privacy gate)

```
Access-Control-Allow-Origin: http://127.0.0.1:7878   # claude-bridge dashboard default port
Access-Control-Allow-Methods: GET
Access-Control-Allow-Headers: Authorization, Accept
Vary: Origin
Referrer-Policy: no-referrer                          # prevents token leak via Referer
```

**No wildcard, no localhost-prefix glob.** T-4.9 axum test enforces 4 cells: `Origin: http://127.0.0.1:7878` → 200 · `Origin: http://evil.example` → 403 · missing token → 401 · expired token → 401.

### 5.4 Auth — single-use UUID token

- Minted by helper daemon at `bridge_meeting_start` time (T-4.4 returns it inside `uiUrl`).
- TTL 5 minutes; scope = `meetingId`. Token-set is in-memory `HashMap<TokenId, (MeetingId, ExpiresAt)>`; cleared on `bridge_meeting_stop` and on TTL sweep.
- Single-use for the **HTML shell** request; the SSE request **may reuse the same token** (one stream per meeting); after SSE disconnects, re-issuance requires a new `bridge_meeting_start` call.
- No bearer header — token rides the query string. Justification: SSE has no auth-header spec in browsers when used via `EventSource`; URL-borne is the standard local-tunnel pattern. `Referrer-Policy: no-referrer` + 5-min TTL bound the leak surface.

## 6. Privacy-Mode Enforcement Layer

ARCH §11.1 (Phase 3 T-3.8) defines `isSttProviderAllowed(currentMode, requested) → boolean`. Phase 4 wires it into the MCP layer **before any process spawn**:

```
bridge_meeting_start({ privacyMode, sttProvider, … })
  ├── 1. Zod schema validate (typed enum on providers)
  ├── 2. isSttProviderAllowed(privacyMode, sttProvider) ─── FAILS → return PrivacyModeViolation
  ├── 3. Path-traversal guard on contextPaths[]
  ├── 4. Build deeplink via URLSearchParams (NOT string concat)
  ├── 5. child_process.spawn(["open", deeplink], { shell: false })   <── only reached if (2) passed
  └── 6. Poll RPC socket up to 5s for { meetingId, pid }
```

**The gate fires at the MCP layer**, NOT inside the Tauri app. Two reasons:

1. Defense in depth — even if the deeplink handler in `src-tauri/src/lib.rs` had a bug that ignored the `privacyMode` query param, no Cloud STT spawn would happen because the spawn never started.
2. Telemetry — the rejection is logged with `mcp_tool_error` event (T-3.9 sink) at the same layer that recorded the request, so audit trails stay coherent.

T-4.4 review checkbox is **BLOCKING** on this gate having an explicit unit test (`{ privacyMode: "local-first", sttProvider: "deepgram" }` → typed error, no spawn observed). Same shape as `crates/stt-mlx/src/providers/privacy.rs::PrivacyModeViolation`.

## 8. Risks (Phase 4-specific top 3)

| # | Risk | Probability | Impact | Mitigation |
|---|---|---|---|---|
| **R-1** | **MCP SDK / config schema drift between meeting-copilot and claude-bridge daemon.** Daemon bumps SDK major or `config.version` past 1; meeting-copilot's tool-list framing or registration silently fails. | Medium | High | (a) Pin daemon snapshot at v1.0.4 in T-4.2 `package.json` regex test; (b) `config.version > 1` → typed `ConfigSchemaUnsupported` (T-4.8); (c) `tools/list` snapshot test re-verified on every SDK bump (T-4.2); (d) Phase-4 sign-off captures the pinned daemon snapshot for future-proof debugging. |
| **R-2** | **Deeplink registration / injection.** `meeting-copilot://` not registered until first app launch on a fresh Mac (Apple Launch Services lazy-registers); OR caller passes shell metacharacters in `contextPaths` and they leak into the URL the OS hands back to the app. | Medium | **CRITICAL** | (a) Tauri scheme declared in `src-tauri/tauri.conf.json` + Info.plist (T-4.4); (b) operator-facing `T-4.4-manual-verify-deeplink.md` checklist for first-run; (c) URL build via `URLSearchParams` exclusively — review checkbox forbids string concat; (d) `child_process.spawn` always array-form, `shell: false`; (e) Zod path-traversal guard on `contextPaths` strings before URL build. |
| **R-3** | **CORS / token leak on iframe embed surface.** Wildcard `Access-Control-Allow-Origin: *` lands by accident, OR token leaks via Referer header to a third party loaded by the embed page → live transcript readable by attacker on the same machine. | Low | **CRITICAL** | (a) Hardcoded allow-list `http://127.0.0.1:7878` only (T-4.9 axum test); (b) `Referrer-Policy: no-referrer` header on every embed response; (c) 5-min TTL + scope-to-meetingId on the token; (d) review checkbox is BLOCKING; (e) PHASE-BROWSER-TEST.md step has explicit `Origin: http://evil.example` → 403 verification. |
