## Defense-in-depth notes

1. **Path traversal:** every `path`/`binPath`/`appPath` value is checked for tilde, non-absolute, and `..` segments BEFORE either reaching the fs or being persisted to disk. Three tests cover the rejection (`rejects relative binPath`, `rejects tilde-prefixed appPath`, `rejects binPath containing ..`). ARCH §16's "absolute paths only" rule is honored.
2. **Concurrency:** atomic rename via `<config>.tmp.<pid>` → `renameSync` (mirrors `claude-bridge/src/lib/dashboard-installer.ts:writeConfigJsonAtomic`). Worst case if both daemons race: the loser's atomic-write step overwrites the winner's, but since `meeting_copilots` and `dashboards` are disjoint keys with `passthrough()` preserving both, final state is consistent.
3. **Schema drift:** `SUPPORTED_CONFIG_VERSION = 1`. If claude-bridge daemon ever bumps `config.version` past 1, `readBridgeConfig` throws `ConfigSchemaUnsupportedError` BEFORE Zod parsing — operator gets a readable upgrade message, not a Zod issue stack.
4. **No daemon RPC dependency:** discovery is pure fs I/O. Registration succeeds even when claude-bridge daemon is down.
5. **Discovery skipped on `--version`/`--help`:** `tryRegisterDiscovery()` only runs in the stdio-server boot path, so introspection commands never touch `~/.claude-bridge/`.
