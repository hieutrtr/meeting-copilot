2. **`docs/RELEASE-NOTES-v1.0.0.md`** — single-page release notes covering Phase 1+2+3+4 highlights, breaking changes (none — first stable), known issues (Phase 0 carry-forward × 3 + Phase-3-new × 2 + Phase 4 deferreds), install matrix (DMG / Homebrew cask / source build), and verification commands.

## 2. Non-goals

- **Do NOT submit the Homebrew cask PR.** The cask template + instructions stay in this repo until the operator has a notarized DMG + a release URL + a SHA-256 to slot in. `T-4.12-review.md` `R-5` checkbox guards this.
- **Do NOT run `xcrun notarytool`.** Apple Developer credentials are operator-owned; agent has no access. DMG-INSTRUCTIONS.md ships placeholders.
- **Do NOT push the `v1.0.0` tag.** Loop driver instruction explicit: "no `git push`". The tag annotation MAY reference PHASE-4-COMPLETE.md by relative path even though the sign-off doc lands in loop step 14 — INDEX risk register §R-5 wording flagged this ordering hazard; mitigation = annotation cites the sign-off doc by **path** (forward-reference) without quoting its body, and step 14 lands the doc before the operator pushes the tag.
- **Do NOT auto-generate a SHA-256 in the cask template.** Real SHA-256 requires a stapled DMG; agent has neither. Template ships `sha256 "REPLACE_WITH_SHA256_OF_NOTARIZED_DMG"`.
- **Do NOT add new features, fix bugs, or refactor.** Release prep is mechanical. Bug fixes go to v1.0.1.
- **Do NOT bump `Cargo.toml` rust-version, edition, or any non-version field.** Version-only edits.
- **Do NOT modify the existing `bun.lock` or `Cargo.lock`.** `package.json` version is a metadata-only field; lockfiles do not pin it. (Cargo `Cargo.lock` does pin path-dep versions, but a virtual workspace bump should be rebuilt by `cargo build` on host — the loop sandbox has no cargo per Phase 0 carry-forward, so `Cargo.lock` may diverge after host rebuild; that's expected and operator runs `cargo build` post-clone before the DMG step.)

## 5. Spec — `docs/release/DMG-INSTRUCTIONS.md`

Operator-side, host-only checklist. Sections:

1. **Pre-flight (host setup)** — ensure cargo + tauri-cli installed (Phase 0 carry-forward); `cargo build --workspace` once after tag pull; `bun install` clean; `xcode-select --install`; `xcrun --find notarytool` resolves.
2. **Build** — `bun run tauri build --target aarch64-apple-darwin` (Apple-Silicon only, per `IMPLEMENTATION-PLAN.md` Phase 0 hardware lock); artifact lands at `src-tauri/target/release/bundle/dmg/Meeting Copilot_1.0.0_aarch64.dmg`.
3. **Codesign** — `codesign --deep --force --options runtime --sign "Developer ID Application: <ORG_NAME> (<TEAM_ID>)" "Meeting Copilot.app"` — placeholders for ORG_NAME + TEAM_ID. Verify: `codesign -vvv --deep --strict "Meeting Copilot.app"`.
4. **Notarize** — `xcrun notarytool submit "Meeting Copilot_1.0.0_aarch64.dmg" --apple-id <APPLE_ID_EMAIL> --team-id <TEAM_ID> --password <APP_SPECIFIC_PASSWORD> --wait`. Three placeholders. Expected output: `status: Accepted`. Bail criteria: any other status → fix + retry; do NOT publish a non-Accepted DMG.
5. **Staple** — `xcrun stapler staple "Meeting Copilot_1.0.0_aarch64.dmg"`. Verify: `xcrun stapler validate "<dmg>"` → `The validate action worked!`.
6. **Compute SHA-256** — `shasum -a 256 "Meeting Copilot_1.0.0_aarch64.dmg" | awk '{print $1}'` — output goes into the Homebrew cask template `sha256` line.
7. **Upload to GitHub release** — `gh release create v1.0.0 "Meeting Copilot_1.0.0_aarch64.dmg" --title "v1.0.0" --notes-file docs/RELEASE-NOTES-v1.0.0.md` (operator runs after tag is pushed).
8. **Hand-off to Homebrew cask** — pointer to `docs/release/HOMEBREW-CASK-TEMPLATE.rb` + the cask submission flow (NOT executed by agent).

Length target: ~120–180 lines.

## 6. Spec — `docs/release/HOMEBREW-CASK-TEMPLATE.rb`

A single Ruby file. Top of file: a 12-line `#`-prefixed comment block titled "DO NOT SUBMIT THIS FILE AS-IS" with a checklist of substitutions the operator must make before opening a `homebrew/homebrew-cask` PR:

1. Set `version` to the actual release version (template ships `1.0.0` — keep if matches the tag).
2. Set `sha256` to the SHA-256 from `DMG-INSTRUCTIONS.md` step 6.
3. Set `url` to the actual GitHub release asset URL (template ships `REPLACE_WITH_RELEASE_URL`).
4. Confirm `homepage` matches the actual repo URL.
5. Confirm `app "Meeting Copilot.app"` matches the bundle name.
6. Verify `livecheck` block uses `:strategy :github_latest` and points at the right repo.
7. `zap trash:` — verify the four paths align with where Tauri persists state (we use `~/Library/Application Support/com.bridge-bot-ts-1.meeting-copilot/`, `~/Library/Caches/com.bridge-bot-ts-1.meeting-copilot/`, `~/Library/Preferences/com.bridge-bot-ts-1.meeting-copilot.plist`, `~/.claude-bridge/meeting-copilot/`).
8. Run `brew style ./Casks/meeting-copilot.rb` locally before opening PR.
9. Run `brew audit --new --cask ./Casks/meeting-copilot.rb`.
10. Open PR against `homebrew/homebrew-cask` `master` with title `Add meeting-copilot v1.0.0`.

Cask body uses standard cask DSL (no obscure helpers); reviewer can copy-paste into `homebrew-cask/Casks/m/meeting-copilot.rb`.

Length target: ~70–110 lines.

## 7. TDD plan

Mostly mechanical — no new vitest / cargo tests land. Verification gates:

1. **`bun run typecheck`** — `tsc --noEmit` exits 0. Version bumps in `package.json` do not trigger TS errors (no version-coupling in source).
2. **`bun test`** — full suite re-runs against the bumped `package.json#version`. Two tests reference `package.json` content:
   - `src/mcp/server.test.ts` (T-4.2) — asserts `bun run mcp-server --version` prints `<package.json#version> (mcp <const>-skeleton)`. Bump → expected output is `1.0.0 (mcp 0.4.0-skeleton)`. Test reads `package.json` at runtime so no test edit needed; the test passes by definition.
   - `src/mcp/handlers/install.test.ts` (T-4.3) — `expectedVersion` field reads `package.json#version`. Bumped value flows through fixtures naturally; same fix-by-construction.
3. **Local tag** — `git tag -l v1.0.0` non-empty; `git tag -v v1.0.0 2>&1 | head -1` shows the annotation.
4. **Markdown link audit** — internal anchors in the three new docs resolve to existing files (`docs/RELEASE-NOTES-v1.0.0.md`, `docs/release/DMG-INSTRUCTIONS.md`, `docs/release/HOMEBREW-CASK-TEMPLATE.rb` cross-link via relative paths).
5. **No `git push`** — verified by `git status` showing the tag local-only after creation.

If `bun test` flags a discrepancy that the version bump introduced, the bump is reverted and the test source is fixed first. Empirically this should not fire — both T-4.2 + T-4.3 tests load `package.json` at test-run time, so the bumped value flows transparently.
