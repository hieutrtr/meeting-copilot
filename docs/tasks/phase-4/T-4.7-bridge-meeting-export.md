## 1. Goal

Replace the `NotImplemented` placeholder for `bridge_meeting_export` with a handler that, on a single `tools/call`:

1. **Validates the request** with `ExportInputSchema` (Zod, strict). `meetingId` is **required** (1+ chars); `format` is required and ∈ `{markdown, json, vtt, srt}`.
2. **Rejects path traversal in `meetingId`** — anything containing `..`, `/`, `\`, or null byte returns a typed `InvalidMeetingId` envelope (no fs touch). Defence-in-depth: even though Zod's `min(1)` allows arbitrary strings, the handler enforces a stricter character class before the path is constructed.
3. **Loads the meeting snapshot** via an injected `loadSnapshot(meetingId)` dependency. Returns either a `MeetingSnapshot` (mirrors `crates/helper-daemon::repo::MeetingSnapshot` 1:1) or `null` for missing. `null` → typed `MeetingNotFound` envelope.
4. **Dispatches to the format renderer** — one of 4 pure functions in `src/mcp/exporters/{markdown,json,vtt,srt}.ts`. Each takes the snapshot and returns `{ext, mime, body}`.
5. **Writes the body atomically** to `<exportRoot>/<meetingId>.<ext>` (default exportRoot = `~/.claude-bridge/meeting-copilot/exports`; overridable via `MCP_BRIDGE_HOME` env, mirroring T-4.5 socket path resolution). Atomic = `writeFile(tmp); rename(tmp, final)`. The directory is created with `recursive: true` if missing.
6. **Returns `{path, sizeBytes}`** validated through `ExportOutputSchema`.

In addition, the markdown renderer surfaces:

- **Privacy mode badge** in the header (`> Privacy mode: …`).
- **Cost meter** in the header (`> Cost: $…`) — derived from `answer.tokens_in` × prompt-cache-hit cost + `answer.tokens_out` × output cost; if no answer is present, `> Cost: $0.00 (no Q&A)`.
- **Q/A blocks** with question text + answer text (one block per question; if no matching answer, the block ends with `_(no answer recorded)_`).
- **Transcript chunks** rendered in start_ts order, each prefixed with `[HH:MM:SS]` relative to `meeting.startedAt`.

The JSON renderer emits the `MeetingSnapshot` round-trippable through `JSON.parse(JSON.stringify(snapshot))` — same wire shape as the helper-daemon's `serde(rename_all = "camelCase")` output.

The VTT renderer emits a valid WebVTT file: `WEBVTT\n\n` header, then one cue per chunk with `HH:MM:SS.mmm --> HH:MM:SS.mmm` timestamps (mm = milliseconds).

The SRT renderer emits a SubRip Subtitle file: 1-indexed cue numbers, then `HH:MM:SS,mmm --> HH:MM:SS,mmm` timestamps (comma not period — that is the SRT spec).

## 3. Architecture & Reference

- **DI seam for snapshot load** — the handler accepts a `loadSnapshot(meetingId): Promise<MeetingSnapshot | null>` dependency. The default in `server.ts` returns `null` (so production today reports `MeetingNotFound` until Phase 4.x wires a real loader); tests inject a fixture loader. This keeps T-4.7 honest: the handler logic is fully exercised by tests, and the production wiring is captured by an explicit follow-up rather than shipping a half-broken default that reaches into Tauri (where `invoke` is unavailable in the standalone bun MCP server).
- **Atomic write** — same writeFile-tmp + rename shape as `claude-bridge/src/lib/dashboard-installer.ts`. The temp filename includes the process pid + a timestamp suffix to avoid races between two MCP server instances writing the same meetingId concurrently. On rename failure, the tmp file is unlinked best-effort.
- **Path traversal guard** — applied at the handler layer (not pushed into Zod) so the error envelope can carry a meaningful `InvalidMeetingId` code rather than a generic ZodError. Vectors guarded: `..`, `/`, `\`, NUL (` `), the empty string after Zod's `min(1)`, and an absolute-path-style id (`/etc/foo`). The guard rejects via `errorResult("InvalidMeetingId", …)` — never throws.
- **Cost meter** — pure function on the snapshot's single `answer` row. Phase 1 schema only has `answer.tokens_in / tokens_out / cached_ratio`. We use `claude-sonnet-4-6` pricing (`$3 / 1M input` × `(1 - cachedRatio)` + `$0.30 / 1M cached input` × `cachedRatio` + `$15 / 1M output`) — pulled from a small pricing constant in markdown.ts (no cross-import on src/llm/pricing.ts to keep the exporter standalone). Drift between the two is acceptable for v1.0 (the markdown is operator-facing, not a billing surface).
- **Privacy mode badge** — read from `meeting.privacy_mode` field. If absent → `"unknown"`.
- **Format dispatch** — a `Record<ExportFormat, RendererFn>` rather than a switch, so adding a new format in Phase 5 is one entry; the closed format set in `tools.ts:EXPORT_FORMAT_ENUM` remains the source of truth.
- **VTT timestamp** — WebVTT spec requires `HH:MM:SS.mmm`. The shared formatter takes a `separator: "." | ","` arg.
- **SRT timestamp** — SubRip spec requires comma. Cue numbers start at 1; cues are blank-line separated.
- **No transcript over MCP boundary** — the export tool returns `{path, sizeBytes}`, not the rendered body. The caller reads the file from disk. This is deliberate: large transcripts would blow the JSON-RPC payload size limits, and the file is the source of truth (operator can `cat ~/.claude-bridge/meeting-copilot/exports/m_1.md`).
- **Privacy mode → cloud LLM gate** — N/A for export. The provider was already chosen + gated at T-4.4 start. Export only reads from local SQLite; no transcript text or audio crosses any network boundary.

## 6. Risks & Mitigations

| Risk | Mitigation |
|---|---|
| **Path traversal via `meetingId`** (R-2 family — escape into `/etc/passwd.md` if id is `../etc/passwd`) | Handler-layer guard rejects `..`, `/`, `\`, NUL, leading `/`. 6 explicit test vectors. The guard runs **before** any fs call (asserted via spy). |
| **Cost meter drift from `src/llm/pricing.ts`** | Acceptable for v1.0 — exporter has its own pricing constant (`SONNET_4_6_USD_PRICING`) with the same numbers. A regression test asserts the constants byte-match a local copy; if `pricing.ts` changes, the test stays green (intentionally decoupled) and a follow-up TODO captures the drift. Operator-facing surface, not billing. |
| **Atomic write race** (two MCP servers writing same meetingId) | Tmp filename = `<final>.<pid>.<random>.tmp`; rename is atomic on POSIX. If two renames target the same final path, last-writer-wins is acceptable (same content for same meetingId — exports are deterministic per snapshot). |
| **Large transcripts blow JSON-RPC envelope** | Handler returns `{path, sizeBytes}` only; body lives on disk. Caller reads from disk if needed. |
| **Loader not wired in production** (Phase 4 ships a `null` default) | Documented as out-of-scope for T-4.7 (entrypoint is Phase 4.x). The default returns `null` so production reports `MeetingNotFound` rather than crashing — soft-fail shape preserves the contract. T-4.10 E2E injects a fixture loader to exercise the full chain end-to-end. |
| **VTT/SRT timestamp overflow > 24h** | The timestamp formatter clamps `HH` to two digits up to 99; > 99 wraps via modulo (acceptable — meetings > 100 hours are out of scope and the formatter logs a `console.warn` once per call; tested). |
| **Markdown injection via question/answer text** (e.g. malicious `</details>` in a transcript) | Out of scope — the markdown is operator-facing (read by the user in their own editor), not rendered server-side. We do NOT escape; that is consistent with how the daemon's other markdown surfaces (existing claude-bridge dashboard) treat user content. Documented. |
| **JSON ` ` / ` ` confusing JS string literals** | `JSON.stringify` already escapes these by default; no extra handling needed. Tested via a ` `-containing chunk text. |

## 7. Out of Scope (Phase 4.x / later)

- **Production snapshot loader** — wires into either the standalone bun MCP server (direct `bun:sqlite` read on `~/Library/Application Support/Meeting Copilot/meetings.db`) or the Tauri-context `persistClient.ts` invoke. The lib-level handler is loader-agnostic.
- **Auto-export on stop** — T-4.6 `StopRecord.exported_path` is populated by the entrypoint that wires `handle_stop` into the live STT pipeline; that entrypoint optionally calls T-4.7's `handleExport` after `mark_meeting_ended` per the user's `autoExportFormat` setting. The `bridge_meeting_stop` response surfaces the path. Phase 4.x.
- **Multi-meeting batch export** — `bridge_meeting_export` is per-meeting. A "export all meetings" surface lands as a separate tool in Phase 5 if requested.
- **Custom output paths** — current default is `~/.claude-bridge/meeting-copilot/exports/<meetingId>.<ext>`. A user-supplied output path is not in the input schema for v1.0 (keeps the surface minimal; operator can move the file post-export).
- **Transcript redaction / PII scrub on export** — not in scope. The `src/telemetry/scrub.ts` redactor is for telemetry, not exports. Operator-facing surface.
