## 4. Review checklist (Phase 4 process)

- [x] **No regression Phase 1/2/3**. Full suite green at 740. The 1 prior placeholder regression (`server.test.ts > placeholder for bridge_meeting_stop`) was intentionally dropped in favour of two positive integration tests (happy + DaemonMeetingNotFound mapping).
- [x] **MCP tool error handling proper** (no panic on missing args; typed `isError` envelope). `handleStop` catches `SocketPathRejected` and maps to `BridgeConfigInvalid`; `DaemonMeetingNotFound` maps to typed `MeetingNotFound` envelope; unknown daemon error codes re-throw to surface in `server.ts`'s catch (per T-4.2 dispatch design); Zod parse failures on the success branch also throw and bubble to the same catch. **Zod strict tests** assert empty / missing / non-string / unknown-key meetingId all throw at the schema layer (4 cases), so the handler never reaches the dial path with malformed input.
- [x] **Deeplink URL parser safe** (no injection; URLSearchParams only). N/A — no URL building in T-4.6. Socket path is constructed via `path.resolve` (reused from T-4.5; the traversal guard there is exercised by the 3 env-override tests).
- [x] **Privacy mode enforce at MCP layer** (Local-only is NOT dispatchable to Cloud STT). N/A for stop — provider was already chosen + gated at T-4.4 start. Stop only flushes + persists + responds with `{exportedPath?, durationSec, questionCount}`; **no transcript text crosses the MCP boundary in the response**. This is a deliberate design choice (the T-4.7 export tool is the read-side surface for transcript text).
- [x] **Iframe embed CORS + auth check** — N/A for T-4.6 (T-4.9 owns this checkbox). The stop RPC's response shape is consumed by T-4.10 E2E only.

## 5. Threat-model walkthrough (R-4 in INDEX)

| Attack vector | Defence layer | Test |
|---|---|---|
| Stop on unknown id | (1) Daemon `DaemonMeetingNotFound` envelope; TS handler maps to `MeetingNotFound` | `mcp_rpc.rs > dispatch_stop_unknown_id_returns_meeting_not_found` + `stop.test.ts > maps DaemonMeetingNotFound to a typed MeetingNotFound envelope` |
| Stop without meetingId (omitted in JSON) | (2) Daemon `DaemonMalformedRequest` envelope; TS handler never reaches the dial path because `StopInputSchema.parse` rejects empty `meetingId` first | `mcp_rpc.rs > dispatch_stop_without_meeting_id_returns_malformed_request` + `stop.test.ts > rejects empty-string meetingId (min(1))` |
| Stop on already-stopped meeting (double-stop race) | (3) Daemon-side `RpcState.stopped` cache; idempotent replay returns the same `StopRecord` | `mcp_rpc.rs > dispatch_stop_is_idempotent_on_replay` (asserts wire-level equality + cache size = 1) |
| `MCP_BRIDGE_HOME=/tmp/../etc` | (4) `containsTraversal` rejects `..` substring (reused from T-4.5 socket.ts) | `stop.test.ts > rejects MCP_BRIDGE_HOME with `..` traversal as BridgeConfigInvalid` (asserts dial not called) |
| `MCP_BRIDGE_HOME=~/foo` | (4) Non-absolute reject (no leading `/`) | `stop.test.ts > rejects MCP_BRIDGE_HOME with non-absolute value as BridgeConfigInvalid` |
| Daemon hangs and never replies | (5) `responseTimeoutMs` (default 1000ms) on dial (reused from T-4.5) | Indirect — covered by `socket.test.ts > rejects when the response timeout fires after connect` |
| Daemon returns shape that doesn't match `StopOutputSchema` (e.g. negative durationSec) | (6) Zod `.parse` throws → server.ts catch | `stop.test.ts > throws on a daemon reply that doesn't parse through StopOutputSchema` |
| Daemon returns unknown error code (e.g. `DaemonExploded`) | (7) Re-throw with original message preserved | `stop.test.ts > throws on an unknown daemon error code (preserves original message)` |
| Concurrent stop + status read on same daemon | (8) `Arc<Mutex<RpcState>>` serialises mutation; status filter test asserts post-stop state coherent | `mcp_rpc.rs > dispatch_stop_after_status_filter_still_round_trips` + `> dispatch_stop_removes_meeting_from_active_list` |

All 8 vectors land on a typed envelope (no panic, no leak past the MCP boundary).
