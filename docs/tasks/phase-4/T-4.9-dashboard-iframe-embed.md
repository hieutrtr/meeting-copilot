## 1. Goal

Add the helper-daemon's HTTP layer (`crates/helper-daemon/src/embed_http.rs`) so the claude-bridge dashboard can iframe a **read-only**, **token-gated** transcript view of a live or completed meeting.

Two routes, both bound to `127.0.0.1:7411` (loopback only — never exposed to the network):

1. `GET /embed/transcript/:meetingId?token=<UUID>` — static HTML shell that hosts the React `<TranscriptEmbed/>` component. Vite builds the bundle to `dist/embed/transcript.{html,js}` via a separate rollup entry. Daemon serves the file inline (small enough to ship as a `&'static str` constant in the Rust binary; the daemon tests stub the HTML body).
2. `GET /embed/transcript/:meetingId/events?token=<UUID>` — Server-Sent Events stream of transcript / question / answer append events for the meeting. The daemon owns a `tokio::sync::broadcast::Sender<EmbedEvent>` per meeting and fans into one `SSE` body per subscriber.

Auth = single-use token (UUID v4, 5-min TTL, scoped to one `meetingId`) issued by the daemon when `bridge_meeting_start` returns. The MCP tool's `uiUrl` is `http://127.0.0.1:7411/embed/transcript/<meetingId>?token=<UUID>`. CORS allow-list is **hardcoded** to `http://127.0.0.1:7878` (claude-bridge dashboard default port) — wildcard is **never** emitted; missing/mismatched `Origin` → 403. `Referrer-Policy: no-referrer` is set on every embed response so a token in the URL never leaks into a downstream Referer header.

The TS-side `<TranscriptEmbed/>` React component (`src/embed/TranscriptEmbed.tsx`) is the iframe contents: connects an `EventSource` to the SSE route, renders chunks/questions/answers as they arrive, surfaces connection status. Tests use jsdom + a hand-rolled `EventSource` mock (no network I/O).

## 3. Architecture & Reference

### 3.1 Why `127.0.0.1:7411` (and not the existing UDS)

The dashboard is a browser context — it cannot dial a Unix-domain socket directly. The HTTP layer is the smallest bridge that lets a `<iframe src="http://127.0.0.1:7411/...">` load and an `EventSource(...)` subscribe. Bind is loopback-only (`127.0.0.1`, **never** `0.0.0.0`); the OS firewalls non-loopback inbound by default but we belt-and-brace by binding to the loopback interface explicitly.

Port 7411 is chosen out of a free range (avoids common collisions: 7878 is the dashboard, 7474 is Neo4j, 7400/7500 are common dev ports). Documented in PHASE-4-COMPLETE for operator-facing collision triage.

### 3.2 Auth model (R-3 mitigation)

- **Token lifecycle**: minted by `bridge_meeting_start` → carried in the `uiUrl` query string → consumed by the dashboard iframe → verified per request by the daemon.
- **Single use? — No, time-bounded use**: the iframe loads the static HTML once and then opens an SSE stream that lives until the meeting ends. A "single-use" UUID would force a re-mint per route. We model this as **scope-bounded + time-bounded**: one `(meetingId, token)` pair valid for 5 minutes from issuance; multiple GETs are allowed in that window. The 5-min TTL is short enough that a leaked token is a low-impact incident; long enough that the typical iframe load + SSE connect sequence completes inside the window.
- **Storage**: in-memory `HashMap<MeetingId, TokenRecord { token: Uuid, expires_at: Instant }>`. Only one active token per meeting at any time — re-minting overwrites. Cleared on `bridge_meeting_stop`. No persistence to disk (no token file to leak; daemon restart invalidates all outstanding tokens).
- **Side-channel hardening**:
  - `Referrer-Policy: no-referrer` on every response — prevents downstream pages from leaking the token via `Referer:`.
  - `Cache-Control: no-store` on every response — prevents browser cache from retaining the token in a disk-cached HTML body.
  - No `Set-Cookie` ever — token is never copied into a cookie jar.
  - Token is read from `?token=…` query (URL-bound). We do **not** accept it via `Authorization:` header to avoid splitting the auth surface; the iframe is a same-origin GET and a query token is the natural fit. Future enhancement: move to a one-shot exchange that swaps the URL token for a session cookie scoped to the iframe origin.

### 3.3 CORS allow-list (R-3 mitigation)

- **Allow-list**: `["http://127.0.0.1:7878"]` — claude-bridge dashboard default. **No wildcard**.
- **Effect**: `Access-Control-Allow-Origin` header is **only** emitted when the request `Origin:` matches the allow-list. Mismatched origin → 403 with no CORS header (browser refuses).
- **Embed HTML route does not strictly need CORS** (the iframe doc is same-origin from the iframe's perspective). The SSE route **does** — the dashboard's outer page may live on `127.0.0.1:7878` and the iframe content fetches the SSE from `127.0.0.1:7411`, which is a cross-origin request from the browser's perspective (different port = different origin).
- **Test coverage**: 4 cases — valid origin → 200/SSE; missing origin (e.g. `curl` direct hit, no `Origin:`) → 403; `Origin: http://evil.example` → 403; `Origin: http://127.0.0.1:1234` (wrong port) → 403.

### 3.4 SSE fan-out

- The daemon binary entrypoint (Phase 4.x) creates one `tokio::sync::broadcast::Sender<EmbedEvent>` per active meeting and inserts it into a `HashMap<MeetingId, Sender<EmbedEvent>>` inside `RpcState` (or a sister state struct). Whenever the in-process Chunker → STT pipeline emits a transcript chunk, the daemon clones the chunk, stuffs it into an `EmbedEvent::TranscriptChunk`, and `send`s on the broadcast channel.
- The SSE route handler subscribes (`broadcast::Receiver`), wraps it in an `axum::response::sse::Sse` adapter that maps each `EmbedEvent` to a `data: <json>\n\n` frame, and streams until the receiver closes (meeting ended) or the client disconnects.
- T-4.9 ships the **embed-side wiring** + tests; the broadcast `Sender` is constructed by the daemon binary entrypoint in Phase 4.x. The lib-level tests inject a synthetic `Sender` directly (no STT pipeline, no audio).

### 3.5 React `<TranscriptEmbed/>` shape

```
<TranscriptEmbed meetingId="m_1" token="…">
  <header>{title} <span class="status">{connectionState}</span></header>
  <ol class="chunks">
    <li>[HH:MM:SS.mmm] <strong>{speaker}</strong> {text}</li>
  </ol>
  <section class="qa">
    <article>
      <h3>{question.text}</h3>
      <p>{answer?.text ?? '(no answer yet)'}</p>
    </article>
  </section>
  <footer>{meetingEnded ? "Ended" : "Live"}</footer>
</TranscriptEmbed>
```

State is held by a `useReducer` over the wire-event union; tests render the component and dispatch synthetic events through the mocked `EventSource`. No external state store is required (the iframe is its own React root).

## 6. Risks & Mitigations

| Risk | Mitigation |
|---|---|
| **CORS misconfiguration** (R-3) — wildcard `*` lands → any local origin reads transcripts | Hardcoded allow-list `["http://127.0.0.1:7878"]`; explicit 403 test on `Origin: http://evil.example`; CI-style assertion that the `Access-Control-Allow-Origin` header is **not** wildcard in any test. |
| **Token leak via Referer** (R-3) — token in URL leaks to downstream pages | `Referrer-Policy: no-referrer` header on every response; tested. |
| **Token leak via cache** | `Cache-Control: no-store` header on every response; tested. |
| **TTL bypass** — implementation uses wall-clock and skews | Clock is injected (`Clock = fn() -> Instant`); tests advance the clock past TTL and assert rejection. Production uses `Instant::now`. |
| **Scope confusion** — token for `m_1` accepted on `/m_2/events` | `verify(meeting_id, token, now)` cross-checks the meeting id; explicit test. |
| **SSE backpressure** — slow client blocks broadcast | `tokio::sync::broadcast` drops oldest on lag (default behaviour) — acceptable for transcript embed (UI re-fetches on lag via the meeting's HTTP route on reconnect). Phase 4.x can swap for `mpsc` if telemetry shows lag. |
| **Vite build entry collision** | New rollup entry uses a distinct chunk name (`embed-transcript`); the existing `main` entry retains `index.html`. The vite config diff is additive. |
| **EventSource mock drift** — jsdom doesn't ship one | We define a global mock at test-file scope (`globalThis.EventSource = MockEventSource as any`) and clean up in `afterEach`. Identical pattern to the Anthropic SDK mock in `E2E.test.tsx`. |

## 7. Out of Scope (Phase 4.x / later)

- **Daemon binary entrypoint wires `embed_http::serve` into a tokio runtime + binds the broadcast `Sender` per meeting** — Phase 4.x. The lib here exposes the `Router::new()` factory + `EmbedState` struct so the entrypoint can construct one with its own broadcast registry.
- **Persistent tokens across daemon restart** — out of scope. Restart invalidates all tokens by design (no disk-side token file).
- **WebSocket variant** — not required for read-only transcript embed; SSE is the simpler half-duplex fit.
- **Tauri WebView2 / WKWebView CORS quirks** — embed is loaded by the dashboard's browser, not Tauri's WebView; standard browser CORS rules apply.
- **Sub-resource integrity (SRI) on the embed bundle** — deferred; the embed is loopback-only and the bundle is served from the same origin as the SSE route.
