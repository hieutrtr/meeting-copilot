## 1. Goal

Replace the `NotImplemented` placeholder for `bridge_meeting_install` with a **read-only probe** that:

1. Locates the macOS `.app` bundle (default `/Applications/Meeting Copilot.app`, overridable via the `path` input arg);
2. Reads `Contents/Info.plist`;
3. Extracts `CFBundleShortVersionString`;
4. Compares against the MCP server's own `package.json#version` (the canonical "expected" version);
5. Returns the standard `InstallOutput` envelope:
   - bundle present + version parsed → `{ installed: true, version, expectedVersion, message }`;
   - bundle absent → `{ installed: false, expectedVersion, downloadUrl, message }` ("Install from <url>");
   - bundle present but Info.plist malformed → `{ installed: true, expectedVersion, downloadUrl, message }` (no `version` field; user is told to reinstall).

The handler is **idempotent** and **never** mutates the filesystem — no `mkdir`, no `writeFile`, no `spawn`. GitHub-release auto-download is **deferred to Phase 4.x** per T-4.1 §4 ("Read-only in Phase 4").

## 3. Architecture & Reference

- **T-4.1 §4** — install input schema is `{ source?, ref?, path?, version? }` (all optional in Phase 4); output schema is `{ installed, version?, expectedVersion, downloadUrl?, message }`. Source of truth = `src/mcp/tools.ts` `InstallInput/OutputSchema` (already landed in T-4.2). T-4.3 satisfies the schema.
- **macOS Info.plist format** — XML property list. Layout:
  ```xml
  <key>CFBundleShortVersionString</key>
  <string>0.3.0</string>
  ```
  Whitespace between key/string tags is permitted. The version value is the user-visible release number (vs. `CFBundleVersion` which is the build number).
- **Risk register R-1** (INDEX) — Info.plist format drift between macOS versions. Mitigation: pure regex against a single key name (no full XML parser dependency); fall back to `installed: true, version: undefined` when the key is missing — caller is told to reinstall.

## 4. Design Decisions

### 4.1 Pure parser, no XML library

The Info.plist file format is stable enough that a single regex against the `CFBundleShortVersionString` key works across all macOS releases since 10.0 (2001). Adding a full XML parser dependency would be overkill — every Apple-supplied plist follows the documented DTD, and Tauri's bundle generator (the only writer of our plist) emits the same shape.

```typescript
const re = /<key>CFBundleShortVersionString<\/key>\s*<string>([^<]+)<\/string>/;
```

Non-greedy + restricted-character-class on the captured value avoids over-capture if the plist contains additional `<string>` elements after the key.

### 4.2 Deps injection over fs mocking

The handler accepts an optional `InstallHandlerDeps` second argument exposing `readFile`, `packageVersion`, `appBundlePath`, and `downloadUrl` overrides. Tests pass synthetic implementations directly — no `vi.mock("node:fs")` global module-level mock that contaminates other tests. This mirrors the per-handler deps seam laid down in T-4.2 (each handler module exports its own `*HandlerDeps` interface).

### 4.3 Three-state envelope

| Bundle exists? | Plist parses? | Output |
|---|---|---|
| No | n/a | `{ installed: false, expectedVersion, downloadUrl, message: "...not found...Install from..." }` |
| Yes | Yes | `{ installed: true, version, expectedVersion, message: "...installed at <path>..." }` (version may match or not — message states which) |
| Yes | No | `{ installed: true, expectedVersion, downloadUrl, message: "...malformed Info.plist...Reinstall from..." }` |

The third case is **not** `installed: false` because the bundle directory does exist — distinguishing "missing" from "corrupt" matters for the operator (the install tool message tells them which).

### 4.4 Path arg precedence

Resolution order for the bundle directory:
1. `args.path` (caller override — explicit)
2. `deps.appBundlePath` (test injection / per-process override)
3. Hardcoded default `/Applications/Meeting Copilot.app`

No tilde expansion, no env-var substitution — keeps the precedence trivially auditable.

### 4.5 Package version source

`expectedVersion` is read from the MCP server's own `package.json#version` at handler-call time (lazily, with try/catch fallback to "0.0.0"). Tests inject `deps.packageVersion` directly. T-4.12 bumps `package.json` to `1.0.0` and the install tool's `expectedVersion` automatically follows.

## 7. Risks

| # | Risk | Mitigation |
|---|---|---|
| R-1 | Info.plist key-order or whitespace variation breaks the regex. | Regex tolerates `\s*` between key/string tags; fixtures cover compact + multi-line layouts. Future Apple plist drift surfaces as `installed: true, version: undefined` (graceful — bundle is found, version unknown). |
| R-2 | Reading `package.json` at call time fails (e.g. running from a packaged binary that didn't include it). | `try/catch` + fallback to `"0.0.0"`. The handler still returns a valid envelope; the message just shows `expectedVersion: "0.0.0"`. T-4.12 release packaging keeps `package.json` adjacent to `dist/`. |
| R-3 | Caller passes a malicious `args.path` (e.g. `/etc/shadow`). | Read-only — handler only invokes `readFile` and parses output; no shell, no spawn. Worst-case the parser returns `null`, and we report `installed: true, version: undefined, message: "malformed"`. No content from the file is reflected in the envelope. |
| R-4 | The integration test in `server.test.ts` could accidentally read the *real* `/Applications/Meeting Copilot.app` on the developer's machine if the path arg defaults aren't honored. | Test passes an explicit `path: "/var/empty/<random>.app"` so the real bundle is never touched. CI machines have no `/Applications/Meeting Copilot.app` regardless. |

## 8. Telemetry

Not wired in T-4.3 — the handler is read-only and the events of interest (`mcp_tool_invoked` / `mcp_tool_error`) attach more naturally at the dispatcher level (`server.ts`). Wiring is deferred to a single later task that emits the events for all 5 handlers from one place. T-4.2 review notes this as the planned approach; T-4.3 keeps the handler signature seam-friendly (`deps` second arg) so the future task adds `emit?: TelemetryEmit` without renegotiating the contract.

## 9. Out of Scope (deferred)

- GitHub-release auto-download (Phase 4.x).
- `mdls` shell-out fallback for plist parsing (R-1 INDEX risk register — would require a real spawn; Phase 4 keeps the install tool zero-side-effect).
- Compatibility-range parsing (e.g. semver match `>=1.0.0 <2.0.0`) — T-4.3 does a literal string compare in the message; the Phase 5 daemon-side wrapper handles range logic.
- `version` arg input — currently optional and accepted by Zod; Phase 4 ignores it. Documented in T-4.1 §4.
