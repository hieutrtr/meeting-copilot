## Implementation Notes

### Vitest 4 + zod 3.25 import quirk

`import { z } from "zod"` returns `undefined` for `z` inside a Vitest 4 transformed module — the named export is not surfaced through Vite's optimizeDeps cache. Confirmed reproducible with a one-line smoke test (`expect(typeof z).toBe("object")` → "undefined"). The namespace import `import * as z from "zod"` works in all three contexts (bun, tsc, vitest 4) and is what we use in `src/mcp/tools.ts`. Documented inline at the top of the file. Once vitest 4 fixes the resolver bug we can revert to the canonical `{ z }` form.

### MCP SDK return-type union

The SDK's `CallToolRequestSchema` return type is a discriminated union including stateful "task" results. Our `ToolResult` shape (`content` + optional `isError` + optional `structuredContent`) is structurally a `CallToolResult`, but TypeScript can't narrow the union without a discriminator. We cast through `unknown` at the `setRequestHandler` call site only — the cast is documented inline and never crosses out of `server.ts`. T-4.10 E2E will exercise the real wire format.

### Telemetry seam

Each handler module exports a `XxxHandlerDeps` interface (currently empty per skeleton) that future tasks fill in (privacy gate, RPC client, persist client, telemetry emitter). The skeleton lays down the seam shape so subsequent reviews can verify "telemetry emitted" without renegotiating the handler signature.
