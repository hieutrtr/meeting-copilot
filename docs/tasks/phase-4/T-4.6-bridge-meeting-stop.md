## 1. Goal

Replace the `NotImplemented` placeholder for `bridge_meeting_stop` with a handler that, on a single `tools/call`:

1. **Validates the request** with `StopInputSchema` (Zod, strict). `meetingId` is **required** (1+ chars).
2. **Resolves the helper-daemon socket path** using the same `resolveSocketPath` helper from T-4.5 (env override `MCP_BRIDGE_HOME` with traversal/non-absolute rejection).
3. **Dials the Unix-domain socket** (reuses `dialSocket` from T-4.5) with `{"method":"stop","meetingId":"…"}`. Reads a single line response and closes.
4. **Discriminates the response** — daemon returns either:
   - `{"exportedPath"?:"…","durationSec":…,"questionCount":…}` (success) — re-parsed through `StopOutputSchema` and surfaced as the `ToolResult.structuredContent`.
   - `{"error":{"code":"DaemonMeetingNotFound", …}}` — mapped to typed `MeetingNotFound` envelope.
   - Any other error envelope — re-thrown so `server.ts`'s catch maps to a generic `NotImplemented`-bucket envelope (preserves daemon's original message verbatim, same as T-4.5).
5. **Idempotent on already-stopped** — if `meetingId` was previously stopped, the daemon returns the same `StopRecord` (cached in `RpcState.stopped`). The TS handler is purely transport — idempotency is owned daemon-side.

The handler returns `{ exportedPath?, durationSec, questionCount }` on success, or one of `MeetingNotFound` / `BridgeConfigInvalid` on the typed failure paths.

In addition, this task ships:

- **Rust counterpart** — fills in the `stop` arm of `mcp_rpc::dispatch`. Mutates `RpcState` to remove the meeting from `meetings` and insert a `StopRecord` into a new `stopped: HashMap<String, StopRecord>` map. Returns the recorded `StopResponse` on every subsequent call (idempotency invariant). Unknown-id → `DaemonMeetingNotFound` typed error envelope.
- **Repo helper** — `Repo::mark_meeting_ended(meeting_id, ended_at, status)` lands in `repo.rs` so the helper-daemon binary entrypoint (Phase 4.x) can persist `endedAt IS NOT NULL`. Exercises the existing schema (`meetings.ended_at` + `meetings.status`) — no DDL change. Wired into `RpcState` via a callback seam so the in-memory tests stay pure (no sqlite tmpfile required at this layer; the Repo is exercised in its own unit test).

## 3. Architecture & Reference

- **Wire format reuse** — same line-delimited JSON over UDS as T-4.5. `dialSocket` is single-shot (write one line, read one line, close). T-4.6 is the second method to land on this transport; `subscribe` (T-4.9) is the third and will own a long-lived connection variant.
- **Idempotency contract** — owned by the daemon. `RpcState.stopped` is the source of truth: the first stop transitions a meeting from `RpcState.meetings` → `RpcState.stopped`; subsequent stops read from `stopped` and return the cached record. The TS handler stays pure transport — it does not implement client-side caching, because two MCP-server processes targeting the same daemon socket would otherwise see divergent state.
- **`MeetingNotFound` mapping** — daemon emits `{"error":{"code":"DaemonMeetingNotFound", "message":"…"}}`. Handler maps the daemon code (`DaemonMeetingNotFound`) to the MCP code (`MeetingNotFound`). The closed code set in `tools.ts:ERROR_CODES` already includes `MeetingNotFound` (added in T-4.5). The daemon prefix `Daemon` keeps the wire-level codes namespaced from MCP-level codes (no collision).
- **Privacy gate** — N/A for stop. The provider was already chosen + gated at T-4.4 start. Stop only flushes + persists; no transcript text crosses the MCP boundary in the response. Telemetry-side: `mcp_tool_invoked` event remains scrubbed (no transcript chunk text).
- **Repo wiring** — `mark_meeting_ended` is the schema-aware helper: `UPDATE meetings SET ended_at = ?, status = ? WHERE id = ?`. The helper-daemon binary entrypoint (Phase 4.x) wires this into `handle_stop` via a callback so the in-memory test for `mcp_rpc.rs` stays pure (no sqlite tmpfile per dispatch). The unit tests for `mark_meeting_ended` live in `repo.rs::tests`.
- **Mid-stream chunk safety** — full STT-buffer flush is owned by the entrypoint that wires `mcp_rpc::handle_stop` into the live audio pipeline (Phase 4.x). At the lib level we expose the dispatch shape only; the unit tests assert that `RpcState.meetings` no longer contains the stopped meeting after the first call (proxy for "the meeting transitioned to stopped"). The "in-flight chunk persisted" claim in INDEX §"Acceptance Criteria Summary" is exercised at the entrypoint test in Phase 4.x — flagged in §7 below.

## 6. Risks & Mitigations

| Risk | Mitigation |
|---|---|
| **Idempotent stop returns stale data after settings change** (e.g. user enables auto-export between two stops) | The stop record is cached on the **first** stop; the `exportedPath` field reflects the state at first-stop time. Second-stop returns the cached value — this is the documented contract. Operator owns settings ordering. |
| **Mid-stream chunk lost on stop** (R-4 mitigation) | Owned by Phase 4.x entrypoint that wires `handle_stop` into the live STT pipeline (flush before mutate). At the lib level, `dispatch` is single-threaded under `Arc<Mutex<RpcState>>` — no race within the daemon. |
| **`DaemonMeetingNotFound` typo on either side** | Daemon code symbol is `"DaemonMeetingNotFound"`; TS handler matches by exact string. Test `stop.test.ts > maps DaemonMeetingNotFound to MeetingNotFound envelope` asserts the wire string. Zod parse failure on the success branch is the schema-drift safety net. |
| **Stopping a never-started meeting** | Falls through to `MeetingNotFound` (not in `meetings` and not in `stopped`). Tested. |
| **Stop targeting a wrong meeting (right id format, wrong session)** | Out of scope — daemon trusts the id; the auth gate is at the MCP transport layer (only the local user can dispatch via stdio). |
| **Repo `UPDATE` with unknown id silently no-ops** | `rusqlite::Connection::execute` returns rows-affected; the helper test asserts the count = 0 for unknown id and = 1 for known. The helper itself returns `RepoError::Sqlite` only on transport-level failure, not on logical no-op (matches the rest of the Repo's CRUD shape — caller checks `get_meeting` if it cares). |

## 7. Out of Scope (Phase 4.x / later)

- **STT buffer flush before stop** — owned by the Phase 4.x daemon binary entrypoint that wires `handle_stop` into the live STT pipeline. The lib-level `handle_stop` only mutates `RpcState`; the entrypoint is responsible for calling the STT decoder's flush before the mutation.
- **`exportedPath` auto-set from settings** — owned by the entrypoint. The lib-level `StopRecord.exported_path` is `Option<String>`; entrypoint passes the resolved path (via `MeetingCopilotSettings.autoExportFormat`) when constructing the record.
- **`bridge_meeting_status` post-stop reflects the new state** — already true by construction (the lib mutates `meetings`); covered by a regression test in this task.
- **Helper-daemon binary entrypoint** that calls `serve(socket_path, state)` from a tokio runtime — Phase 4.x. The lib.rs surface is ready.
- **macOS sandbox/permissions for socket files** — handled at Tauri build time when the binary lands; not relevant in Phase 4 sandbox.
