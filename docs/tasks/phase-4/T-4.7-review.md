## 4. Review checklist (Phase 4 process)

- [x] **No regression Phase 1/2/3**. Full suite green at 824. The 1 prior placeholder regression (`server.test.ts > placeholder for bridge_meeting_export`) was intentionally dropped in favour of the positive integration test.
- [x] **MCP tool error handling proper** (no panic on missing args; typed `isError` envelope). `handleExport` produces typed envelopes for **3** distinct error paths: `InvalidMeetingId` (path traversal — pre-fs), `MeetingNotFound` (loader returned null), `BridgeConfigInvalid` (env override malformed — pre-fs). Zod parse failures on input throw and are caught by `server.ts`'s catch (mapped to `NotImplemented` bucket). Output schema parse failures throw at the post-render stage; impossible in practice (we construct the payload from validated parts), but kept as defence-in-depth. **Zod strict tests** assert missing meetingId / missing format / unknown format / unknown key all throw at the schema layer (4 cases), so the handler never reaches the render path with malformed input.
- [x] **Deeplink URL parser safe** — N/A for T-4.7 (no URL building; export reads via injected loader and writes to disk). The reused `containsTraversal` helper from `socket.ts` mirrors the same guard shape.
- [x] **Privacy mode enforce at MCP layer** — N/A as a gate (export does not dispatch to a network surface), but the markdown renderer **surfaces** the privacy mode badge in the header so an operator reviewing the export sees the constraint that was active during recording. No transcript text crosses any network boundary; the file lives on local disk only.
- [x] **Iframe embed CORS + auth check** — N/A for T-4.7 (T-4.9 owns this checkbox). The export tool returns a local file path; serving the export over HTTP is out of scope.

## 5. Threat-model walkthrough (R-2 family — path traversal)

| Attack vector | Defence layer | Test |
|---|---|---|
| `meetingId = "../etc/passwd"` (escape into root) | (1) `checkMeetingId` rejects `..` substring + `/` + leading `.` (any 1 of 3 fires); typed `InvalidMeetingId` envelope; loader + fs spies asserted uninvoked | `export.test.ts > rejects %s (%s) without touching fs or loader (7 vectors)` |
| `meetingId = "..\\..\\Windows\\System32\\config\\SAM"` | (2) `\` substring catch (Windows-style traversal also fails on `..`) | Same 7-vector matrix above |
| `meetingId = "foo\0null"` (NUL byte truncation in some libc paths) | (3) `\0` substring rejected | `export.test.ts > rejects m\0null (NUL byte)` |
| `meetingId = ".hidden"` (escapes into dotfile space) | (4) leading `.` rejected | `export.test.ts > rejects .hidden (leading dot)` |
| `meetingId = ""` (after Zod min(1) somehow bypasses) | (5) `checkMeetingId` rejects empty defence-in-depth; Zod also rejects upstream | `checkMeetingId — path traversal guard > rejects empty string` |
| `MCP_BRIDGE_HOME = "/tmp/../etc"` | (6) `containsTraversal` reuses `socket.ts` guard logic; rejects with `ExportRootRejected("traversal")`; loader + fs spies asserted uninvoked on the rejection path | `export.test.ts > rejects MCP_BRIDGE_HOME traversal as BridgeConfigInvalid` |
| `MCP_BRIDGE_HOME = "~/bridge"` (tilde not expanded — operator footgun) | (7) Non-absolute reject (no leading `/`) | `export.test.ts > rejects MCP_BRIDGE_HOME non-absolute as BridgeConfigInvalid` |
| `MCP_BRIDGE_HOME = "/var/run/bridge"` (legitimate operator) | (8) Pass-through; the path is rooted under the operator-controlled prefix | `resolveExportRoot — path resolution > uses MCP_BRIDGE_HOME when set to an absolute path` |
| Two MCP servers writing the same meetingId concurrently | (9) Tmp filename = `<final>.<pid>.<random>.tmp`; rename atomic on POSIX; last-writer-wins is acceptable (deterministic content per snapshot) | `export.test.ts > uses a tmp filename with pid + random suffix` |
| Mid-write crash (writeFile completes, rename fails) | (10) Tmp file unlinked best-effort; final file absent | `export.test.ts > rename failure unlinks the tmp file and re-throws` |
| Malicious markdown content in transcript (e.g. `</details>` injection) | (11) Out of scope — operator-facing surface; exporters do **not** escape user content. Documented in spec §6. | (no test) |

All path-traversal vectors land on a typed envelope (no panic, no fs touch on rejection paths).

## 6. Open follow-ups (out of scope for T-4.7)

- **Production snapshot loader** — wires into either the standalone bun MCP server (`bun:sqlite` direct read on `~/Library/Application Support/Meeting Copilot/meetings.db`) or the Tauri-context `persistClient.ts` invoke. The lib-level handler is loader-agnostic; the default in `server.ts` returns `null` so production reports `MeetingNotFound` rather than crashing. Phase 4.x.
- **Auto-export on stop** — T-4.6 `StopRecord.exported_path` is populated by the Phase 4.x daemon binary entrypoint; that entrypoint optionally calls `handleExport` after `mark_meeting_ended` per the user's `autoExportFormat` setting. The `bridge_meeting_stop` response surfaces the path.
- **Cost meter drift** — exporter has its own Sonnet 4.6 pricing constant (`SONNET_4_6_USD_PRICING`). If `src/llm/pricing.ts` diverges, the markdown header silently drifts — operator-facing surface, not billing. Documented; intentional decoupling.
- **VTT/SRT > 99h hour wrap** — formatter currently wraps via modulo with a `console.warn`. Meetings exceeding 100 hours should produce a multi-file export (Phase 5) but the v1.0 surface clamps + warns rather than overflowing the timestamp width.
- **Markdown injection / escaping** — operator-facing content; we do not escape Q/A or transcript text. If the export is later served over HTTP (Phase 5 dashboard direct-render), an HTML escape pass is needed at the consumer side.
