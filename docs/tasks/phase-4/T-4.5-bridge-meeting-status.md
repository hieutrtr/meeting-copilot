## 1. Goal

Replace the `NotImplemented` placeholder for `bridge_meeting_status` with a handler that, on a single `tools/call`:

1. **Validates the request** with `StatusInputSchema` (Zod, strict). `meetingId` optional.
2. **Resolves the helper-daemon socket path** — `MCP_BRIDGE_HOME` env override or default `~/.claude-bridge/meeting-copilot.sock`. Path-traversal in env override (`..` segments) is rejected with a typed envelope **before** any socket dial.
3. **Dials the Unix-domain socket**, sends a single line of JSON `{"method":"status"[,"meetingId":"…"]}`, reads a single line response `{"meetings":[…]}`, and closes the connection.
4. **Parses the response through `StatusOutputSchema`**. Drift between daemon and MCP envelope schemas surfaces as a typed envelope, not a panic.
5. **Filters by `meetingId`** when supplied. Empty filter result → typed `MeetingNotFound` envelope. No filter → return the full list.

The handler returns a `StatusOutput` envelope `{ meetings: MeetingStatus[] }` on success, or one of `MeetingNotFound` / `BridgeConfigInvalid` / `NotImplemented` (catch-all for socket I/O errors — see §4) on the typed failure paths.

In addition, this task ships the **Rust counterpart**: a tiny tokio-based RPC server (`crates/helper-daemon/src/mcp_rpc.rs`) that listens on the same socket and serves the `status` method (and lays the foundation for `stop` in T-4.6 + `subscribe` in T-4.9). State is held in an `RpcState` struct passed in by the daemon's binary entrypoint. T-4.5 ships the trait + handler shape; the binary entrypoint that owns long-lived state lives in Phase 4.x (out of scope — no audio capture in the loop sandbox).

## 3. Architecture & Reference

- **Wire format** — line-delimited JSON over a Unix-domain socket. One JSON object per line; `\n` terminator. Single-shot for `status` / `stop` (request → response → close). The future `subscribe` channel keeps the connection open and streams events; T-4.5 lays the dispatch shape but does not implement subscribe (T-4.9).
- **Socket path resolution** — checks `MCP_BRIDGE_HOME` env first; if set, must be an absolute path with no `..` segments (post-`path.resolve` re-checked for `..` between segments after canonicalization is impractical at this layer — we test the input string instead). When unset, uses `os.homedir() + "/.claude-bridge"`. Tilde-expansion is **NOT** performed — per claude-bridge dashboard ARCH §16, absolute paths only; a literal `~/foo` env value is rejected as non-absolute. The socket file basename is hardcoded to `meeting-copilot.sock`.
- **Schema drift** — the Rust `MeetingStatusEntry` and the TS `StatusOutputSchema.meetings[*]` shapes are mirror images. We re-parse the incoming line through Zod so any future drift fails the parse loudly instead of letting a malformed payload escape on the wire. Same defense-in-depth pattern as T-4.3 (`InstallOutputSchema.parse(payload)` before return).
- **R-4 mitigation** (INDEX line 201) — stale-socket recovery is a Rust-side concern: the daemon, on bind, attempts a quick dial against the existing socket file; if no listener responds within 200 ms, `unlink` the file and re-bind. Documented in `mcp_rpc.rs` doc-comment; not unit-tested at the binding-level (would require an actual listener race) but the dial-or-unlink helper is a deterministic function we can exercise directly. The TS side is **not** affected by this — the TS handler simply dials and expects either a response or a connect error.
- **Privacy gate** — N/A for status. The status handler is read-only and returns counts + ids; it does **not** return transcript text. No transcript bytes leave the process boundary. Telemetry-side: `mcp_tool_invoked` event remains scrubbed (no transcript chunk text).
- **Idempotency** — status is read-only, side-effect-free; multiple calls with the same args MUST return the same shape. Tested by calling the handler twice in `status.test.ts > idempotent re-query returns identical envelope`.

## 6. Risks & Mitigations

| Risk | Mitigation |
|---|---|
| **R-4 helper-daemon out-of-process race** (INDEX) | Stale-socket recovery: dial-or-unlink-then-bind. Deterministic helper test exercises both branches (no listener → unlink branch; live listener → no-unlink branch). PHASE-BROWSER-TEST.md will exercise crash-recovery on host. |
| **Path-traversal in env override** | `resolveSocketPath` rejects any input string containing `..` segments OR not starting with `/`. Test asserts both. |
| **MCP layer hang on socket I/O** | `dialSocket` carries a `connectTimeoutMs` (default 200 ms) + `responseTimeoutMs` (default 1000 ms). Both tested with mocked transports. Per-attempt sleep on poll deferred to T-4.4's `pollHandshake` consumer (which builds on this socket). |
| **Schema drift between Rust daemon and TS handler** | Both sides assert the camelCase shape via `serde(rename_all = "camelCase")` (Rust) + `StatusOutputSchema.parse` (TS). A drift fails the Zod parse loudly. Future migrations bump both sides in lockstep; the Rust struct's name (`MeetingStatusEntry`) is the parity anchor. |
| **`MCP_BRIDGE_HOME` typo lands a socket file outside the user's home** | Documented in the handler doc-comment. The non-absolute reject (above) catches obvious typos. Operator owns the env var. |
