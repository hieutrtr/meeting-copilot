## 1. Goal

Replace the `NotImplemented` placeholder for `bridge_meeting_start` with a handler that, on a single `tools/call`:

1. **Validates the request** with `StartInputSchema` (Zod, strict).
2. **Rejects path traversal** in `contextPaths` via `validateContextPaths` (see `src/mcp/deeplink.ts`).
3. **Enforces privacy mode** via `isSttProviderAllowed(privacyMode, sttProvider)` from T-3.8 — **before any spawn**.
4. **Builds the deeplink** `meeting-copilot://start?...` via `URLSearchParams` (no string concat, no shell metacharacter escape ever needed).
5. **Spawns** `open <deeplink>` in array form (`shell: false`, `detached: true`, `stdio: "ignore"`).
6. **Polls** the helper-daemon RPC socket (T-4.5) for the meetingId+pid handshake; default poll throws `T-4.5 not yet wired` until T-4.5 lands, surfaced as a typed `DeeplinkNotRegistered` envelope.

The handler returns the `StartOutput` envelope `{ meetingId, pid, rpcSocket, uiUrl }` on success, or one of `PrivacyModeViolation` / `ContextNotFound` / `DeeplinkNotRegistered` on the typed failure paths.

## 3. Architecture & Reference

- **T-4.1 §4** — start input schema is `{ contextPaths, sttProvider, ttsProvider?, model, privacyMode, meetingTitle? }`; output schema is `{ meetingId, pid, rpcSocket, uiUrl }`. Source of truth = `src/mcp/tools.ts` Zod (already landed in T-4.2). T-4.4 satisfies the schema without renegotiating the contract.
- **macOS deeplink registration** — declared in `tauri.conf.json` via the `tauri-plugin-deep-link` plugin (`plugins.deep-link.desktop.schemes`). The plugin's bundler hook injects `CFBundleURLTypes` into the bundled `Info.plist`. Cargo + plugin install + first-launch registration are host-side steps documented in `T-4.4-manual-verify-deeplink.md`.
- **`open(1)`** — macOS's launch helper. Invoked with array argv: `["open", "<deeplink>"]`. Returns 0 on dispatch (note: success of dispatch ≠ success of registration; an unregistered scheme exits 0 in some macOS builds with a stderr warning). Therefore, **handshake is the success gate, not exit code** — the helper daemon (T-4.5) must respond on the RPC socket within `handshakeTimeoutMs` (default 5_000 ms) for the call to count as success.
- **R-2 mitigation** (INDEX line 199) — three layers:
  1. Zod's `.strict()` rejects unknown keys; `.enum()` rejects out-of-set provider/model strings; `.array(z.string().min(1).max(4096)).max(64)` bounds the `contextPaths` shape.
  2. `validateContextPaths` (deeplink.ts) rejects `..` segments (raw or single-decode percent-encoded), embedded NULs, empty strings, and oversize arrays. Throws `ContextPathRejected` → handler maps to `ContextNotFound` envelope.
  3. `URLSearchParams` percent-encodes every value end-to-end. Even if a malicious string slipped through (1) and (2), the deeplink would carry it as an opaque encoded query value — never as a shell-interpretable token, because `child_process.spawn` is invoked with array form (`shell: false`).
- **Privacy gate ordering** — the gate runs **after** Zod parse + traversal check, **before** spawn. Re-ordering the gate after spawn would leak a process creation on a privacy-violation request — that is the explicit Phase 3 T-3.8 guarantee being preserved at the MCP boundary. The unit test `start.test.ts > rejects local-first + deepgram with PrivacyModeViolation, BEFORE spawn` asserts this with a spawn spy whose call count must be 0 on the violation path.

## 6. Risks & Mitigations

| Risk | Mitigation |
|---|---|
| **R-2 deeplink injection** (INDEX) | Three-layer defence (Zod + validateContextPaths + URLSearchParams). Spawn array form. Tests assert raw query string contains no shell metacharacters from input. |
| **R-2 privacy bypass** (INDEX) | Privacy gate runs before spawn; spawn spy count = 0 on violation path is the load-bearing test. |
| **macOS `open` exit code is unreliable** | Don't trust exit code; use helper-daemon handshake (T-4.5) as the success gate with a 5s default timeout. Unregistered scheme → poll times out → typed `DeeplinkNotRegistered` envelope. |
| **Default `pollHandshake` would crash if T-4.5 is unfinished** | Default returns a typed-error string and the handler maps to `DeeplinkNotRegistered`. Production wiring stays uniform; tests inject a successful poll. |
| **Sandbox cannot validate deeplink registration** | `T-4.4-manual-verify-deeplink.md` ships the host checklist (Xcode CLT + cargo); the conf diff is committed so a host with the toolchain can complete the loop. |
| **`open` outputs a stderr warning** when scheme is unregistered | `stdio: "ignore"` swallows the warning; we don't pipe stderr back to the MCP caller. |

## 7. Out of Scope (Phase 4.x or later)

- Cross-platform launch (`xdg-open` on Linux, `start` on Windows) — Phase 4 is macOS-only per ARCH §1.
- `child.on('error', …)` async failure capture — would require holding the child reference past `unref()`. The handshake timeout is the second-line catch.
- Deeplink "resume" semantics — re-using an already-running app instance vs spawning a new one is delegated to `tauri-plugin-deep-link` + LaunchServices.
- `commands::start_from_deeplink` Tauri command implementation — documented in `T-4.4-manual-verify-deeplink.md`; cargo build verification is host-only.
